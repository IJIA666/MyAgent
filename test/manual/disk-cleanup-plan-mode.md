# 手动测试用例：Plan 模式 + AskUserQuestion 端到端验证

> 测试目标：验证 agent 在 Plan 模式下能安全地扫描文件、主动向用户提问、产出方案但不执行写操作。
> 可复用：每次 `ask_user_question` 工具或 Plan 模式有改动后，重新跑一遍即可。

---

## 前置条件

1. 项目已编译或可运行：`npm run dev`
2. agent 启动后，确认环境变量和配置加载正常（Banner 输出无报错）
3. 确认工作区路径可写（用于可能的只读扫描测试）

---

## 测试场景一：Plan 模式基础拦截

**目的**：确认 Plan 模式下 write 工具被物理裁剪，agent 无法执行任何写操作。

**设计要点**：目标路径必须在工作区（`D:\projects\MyAgent`）内，否则会被 workspace 沙箱拦截——混淆两个不同的安全层会导致无法判断被哪个机制拦截。

| 步骤 | 操作 | 预期结果 |
|:---|:---|:---|
| 1 | 输入 `/workmode Plan` | 终端显示 "配置已生效！安全模式已切换为：Plan" |
| 2 | 输入 `在工作区目录下创建一个名为 _test_plan_mode.txt 的空文件` | agent 可能回复：(a) 无法执行写入操作（工具不可用），或 (b) 尝试调用 writeFile 但被拦截。**关键：agent 不得实际创建该文件** |
| 3 | 切回 Auto 模式，输入 `/workmode Auto` | 模式切换成功 |
| 4 | 输入 `在工作区目录下创建一个名为 _test_plan_mode.txt 的空文件` | agent 尝试执行 writeFile，弹出审批弹框（`⚠️ [安全提示]`） |
| 5 | 选择拒绝（输入 3 或 2） | 工具执行被拒绝 |
| 6 | 输入 `清理 _test_plan_mode.txt` 或在文件系统中确认 | **确认步骤 2 中没有文件被创建** |

**通过标准**：
- 步骤 2：Plan 模式下没有任何文件被实际写入
- 步骤 4：Auto 模式下 writeFile 工具可用，审批弹框正常弹出
- 步骤 2 和 4 的对比清晰区分了 Plan 模式的工具裁剪 vs Auto 模式的审批放行

---

## 测试场景二：AskUserQuestion 工具调用 — 选项模式

**目的**：验证 agent 在需要进行二选一决策时，主动调用 `ask_user_question` 工具。

| 步骤 | 操作 | 预期结果 |
|:---|:---|:---|
| 1 | 输入 `/workmode Plan` | 进入只读模式 |
| 2 | 输入 `帮我规划清理 C 盘的空间` | agent 开始扫描/分析 |
| 3 | 等待 agent 调用工具 | 终端应出现 `[⚡ 正在调用工具 "ask_user_question"]`，然后出现 `💬 [agent 提问]` 的交互界面 |
| 4 | 选择一个选项（如输入 `1`） | agent 收到回答后继续推理 |
| 5 | 观察 agent 后续输出 | agent 应基于你的选择调整方案 |

**通过标准**：
- 步骤 3 中 `ask_user_question` 工具被实际调用
- 终端展示的提问界面使用 `💬 [agent 提问]` 前缀（非 `⚠️ [安全提示]`）
- 步骤 4 的选项文本被 agent 正确消费

---

## 测试场景三：AskUserQuestion 工具调用 — 自由输入模式

**目的**：验证开放性问题（无预设选项）能正常渲染文本输入框。

| 步骤 | 操作 | 预期结果 |
|:---|:---|:---|
| 1 | 在 Plan 模式下输入 `我有一个项目目录，帮我分析哪些文件可以清理。项目路径是 D:\projects\MyAgent` | agent 开始扫描 |
| 2 | 等待 agent 提问 | 若 agent 问了开放性问题（如"你有什么特别要保留的吗？"），应为纯文本输入模式 |
| 3 | 输入自定义文本并回车 | agent 收到回答 |

**通过标准**：
- 开放性问题没有序号选项列表，显示 `请输入:` 提示
- 用户输入的自定义文本被正常返回

**备注**：此场景依赖模型自主决定是否调用 `allowFreeInput: true`，不保证每次都触发。若 agent 没有提问开放性问题，不影响整体评估——重点验证"如果有，渲染是否正确"。

---

## 测试场景四：超时行为

**目的**：验证用户不响应时工具能正常超时返回空字符串，不阻塞 agent。

| 步骤 | 操作 | 预期结果 |
|:---|:---|:---|
| 1 | 触发 agent 调用 `ask_user_question`（如场景二） | 提问界面出现 |
| 2 | 不做任何操作，等待 5 分钟 | 终端应显示 `⏰ 提问等待超时，自动跳过。`，agent 继续推理 |
| 3 | agent 不应崩溃或挂死 | 继续正常运行 |

**通过标准**：超时提示出现后 agent 继续运行，无异常退出。

**备注**：此场景耗时较长，日常回归测试可跳过。建议在重大版本发布前跑一次。

---

## 测试场景五：Plan → Auto 切换执行（两阶段协议验证）

**目的**：验证 Plan 模式的零代码两阶段协议——规划完成后用户切模式执行。

| 步骤 | 操作 | 预期结果 |
|:---|:---|:---|
| 1 | 在 Plan 模式下，agent 完成了一次清理规划并输出了方案 | 方案以文本形式展示在终端 |
| 2 | 输入 `/workmode Auto` | 模式切换成功 |
| 3 | 输入 `按照刚才的方案执行` | agent 开始执行写操作 |
| 4 | 对于每个写操作（如删除文件），审批弹框出现 | 用户可以选择放行或拒绝 |

**通过标准**：
- Plan 阶段 agent 没有执行任何写操作
- Auto 阶段 agent 的写操作触发审批弹框（使用 `⚠️ [安全提示]` 前缀）
- 整个流程没有崩溃或状态混乱

---

## 测试场景六：异常路径 — Ctrl+C 中断提问

**目的**：验证用户在提问过程中中断推理时，CLI 状态能正确恢复。

| 步骤 | 操作 | 预期结果 |
|:---|:---|:---|
| 1 | 触发 agent 调用 `ask_user_question` | 提问界面出现 |
| 2 | 按两次 ESC（或 Ctrl+C） | agent 推理被中断 |
| 3 | 输入新的指令 | agent 正常响应 |

**通过标准**：中断后 InputListener 恢复，可以继续输入新指令，无 stdin 死锁。
