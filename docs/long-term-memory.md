# 项目长期记忆（Markdown-first Auto Memory）

## 概述

项目长期记忆（Auto Memory）是 MyAgent 的一种按项目隔离、机器本地的长期记忆能力。它以 Markdown 文件作为唯一事实源，不引入数据库、向量库、Embedding 或专用记忆模型。当前版本是 **Auto Memory v1**，专注于为跨会话稳定信息提供简单、可审计的存储与召回方案。

## 目录结构

长期记忆目录位于项目私有数据根下的 `memory/` 分类：

```
~/.myagent/projects/<workspace-key>/
├── logs/
├── state/
├── artifacts/
├── tmp/
└── memory/
    ├── MEMORY.md       ← 有界索引，会话启动时加载为冻结快照
    └── topics/
        ├── user-preference.md
        ├── project-notes.md
        └── ...          ← 主题正文，按需由标准文件工具读取
```

- `memoryDir` 解析为 `<projectDataDir>/memory/`，不位于工作区 `.myagent/` 下。
- 每次模型请求都会通过独立的 `<memory-context>` 提供当前项目 `memoryDir` 的实际绝对路径；即使索引为空，也会提供该路径以支持创建第一份记忆。
- `MEMORY.md` 包含记忆索引的 Markdown 链接列表。
- `topics/` 为单层目录，每个主题文件以唯一 slug 命名。

## MEMORY.md 索引格式

`MEMORY.md` 每行对应一个主题条目，格式为：

```markdown
- [主题标题](topics/<slug>.md) — 主题描述
```

示例：

```markdown
- [用户偏好](topics/user-preference.md) — 记录用户的编码风格和常用工具链
- [项目约定](topics/project-conventions.md) — 项目使用的分支策略和测试框架约定
```

## 主题文件与 frontmatter

每个主题文件位于 `topics/` 目录，使用 ASCII kebab-case 命名（匹配 `[a-z0-9]+(?:-[a-z0-9]+)*\.md`）。

主题文件必须包含 YAML-like frontmatter：

```markdown
---
name: 用户偏好
description: 记录用户的编码风格和常用工具链
type: user
---

## 编码风格

- 使用 2 空格缩进
- 优先使用 TypeScript

## 常用工具

- uv 用于 Python 包管理
- Vitest 用于单元测试
```

### frontmatter 字段

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | 是 | 主题显示名称 |
| `description` | 是 | 主题用途说明 |
| `type` | 是 | 固定四种类型之一 |

### 四种记忆类型

| 类型 | 中文描述 | 保存条件 |
|------|----------|----------|
| `user` | 用户偏好与个人信息 | 仅保存用户明确表达或反复出现的稳定偏好 |
| `feedback` | 用户反馈与纠正 | 用户对行为或输出的纠正、批评与方向性反馈 |
| `project` | 项目背景与约定 | 无法从源码、Git 历史或配置文件直接推导的信息 |
| `reference` | 外部参考与指引 | 外部文档链接、技术选型依据、学习笔记 |

## 哪些内容不适合保存

- **秘密**：API Key、访问令牌、密码、密钥
- **可从源码/Git 历史推导的事实**：如文件结构、配置值、代码贡献记录
- **临时任务状态**：当前进行中的任务进度（属于会话上下文）
- **已有规则/技能覆盖的内容**：如已配置的项目规则
- **未经确认的推测**：假设或猜测
- **大段原始工具输出**：如冗长的编译日志或调试输出

## 创建与更新规则

### 创建新主题

1. **先查索引**：读取 `MEMORY.md` 并列举 `topics/` 目录，检查是否有语义相同的已有主题。
2. **优先复用**：与已有主题语义相近时，合并到已有主题而非创建新文件。
3. **新建顺序**：先写入 `topics/<slug>.md`（事实源），再更新 `MEMORY.md` 索引。

### 写入限制

- 索引读取上限：**200 行**或 **20KB**，以先达到者为准。
- 超限时索引在投影中被截断并标记，磁盘文件不受影响。
- 主题正文没有内置上限，但模型应注意保持内容简洁相关。

## 忘记操作

### 忘记单项内容

1. 编辑主题正文，删除该内容。
2. 按需更新 `MEMORY.md` 中对应条目的描述摘要。
3. 保留仍包含有效内容的主题文件。

### 忘记整个主题

1. 删除 `topics/<slug>.md`。
2. 删除 `MEMORY.md` 中对应的索引条目。

> **注意**："忘记"操作从当前回合起停止依赖被要求忘记的内容，但系统**不得声称能擦除已出现在既有会话历史中的文本**。

## 快照刷新边界

- **会话启动**：在 `SessionManager.open()` 阶段加载一次磁盘快照，并向模型提供实际记忆目录。
- **普通写入**：创建、编辑、删除记忆文件**不会**自动刷新当前会话快照。刚写入的信息在当前对话中通过文件工具结果可见。
- **上下文压缩**：成功完成上下文压缩后，系统重新加载磁盘快照。刷新失败保留旧快照，不撤销已成功的压缩。
- **即时核对**：如需核对最新磁盘状态，使用标准读取工具。该读取不会替换会话快照。

## 标准文件工具权限

长期记忆文件通过所有标准文件工具（列举、读取、写入、编辑、删除）维护，无需注册专用 `memory` 工具。文件操作经过以下检查层：

1. **路径授权**：目标路径必须位于授权工作区或 memoryDir 物理根子树内。
2. **权限模式**：沿用当前的 `PermissionMode`（`default`、`acceptEdits`、`plan`、`auto`、`dontAsk`、`bypassPermissions`）。
3. **审计日志**：所有文件变更经由审计系统记录。

## 与旧版记忆的区别

| 特性 | 旧版（已移除） | 新版 Auto Memory v1 |
|------|---------------|---------------------|
| 存储引擎 | RAG + Embedding + VectorDB | 纯 Markdown 文件 |
| 检索方式 | 语义检索 | 有界索引 + 模型自行选择 |
| 专用工具 | MemoryService 插件 | 标准文件工具 |
| 自动抽取 | 会话结束自动提炼 | 由模型主动写入 |
| 快照 | 实时更新 | 会话启动 + 压缩后刷新 |
| 数据库依赖 | LanceDB | 无 |

## 第一版限制

- 不引入数据库、向量库、Embedding、文本分块或专用记忆模型。
- 不提供语义搜索、多进程写入合并或用户全局记忆。
- 不自动从会话提炼记忆（由模型根据规则自行决定写入）。
- 不提供 `/memory` 命令或专用编辑器 UI。
- 200 行/20KB 固定上限（暂不可配置）。
- 不支持跨项目或跨工作区的记忆共享。
