## 新增需求

### 需求: 本地技能文件变更重载稳定性
在项目 `<workspace>/.myagent/skills` 目录下的技能主体文件遭受多次元数据触碰或高频修改时，系统应当（SHALL）在最后一次事件发生后的 100ms 进行单次热重载，必须（MUST）合并该时间窗内的全部重复事件，以保障系统稳定并杜绝日志洪泛。

#### 场景: 高频事件合并热重载
- **WHEN** 项目技能文件在数毫秒内连续抛出 10 次变动通知事件
- **THEN** 拦截器和重载器仅在最后一次事件发生的 100ms 后执行一次 `RuleManager` 技能重载，并仅输出一次刷新缓存的日志。

#### 场景: watcher 返回相对文件路径且不包含目录前缀
- **WHEN** 项目技能目录下的文件变更事件以 `example/SKILL.md` 相对路径形式抵达
- **THEN** 系统基于 watcher 根目录拼接完整路径，仅校验 basename 是否为 `SKILL.md`，不得要求路径中包含目录名前缀

#### 场景: watcher 未提供文件名
- **WHEN** 底层平台未随变更事件提供文件名
- **THEN** 系统在当前防抖窗口内执行一次项目 skills 全量摘要重扫，仅在内容实际变化时刷新缓存

### 需求: MCP 外部工具扩展自愈保活
系统应当（SHALL）对当前连接的外部 `MCP` 工具进程建立生命周期监测，若捕获到进程崩溃、退出或因超时挂死，系统必须（MUST）自动启动热拉起自愈模块，采用带有最大次数上限（如 3 次）的指数退避（Exponential Backoff）重连策略重新建立工具管道，保障扩展功能的运行可用性。

#### 场景: MCP 进程单次超时崩溃后热拉起重启
- **WHEN** 大模型调用 `tavily_research` 时触发网络超时崩溃，进程挂死断连
- **THEN** 客户端拦截该底层错误，触发重连哨兵守护，以 1s -> 2s -> 4s 退避序列自动拉起新 `MCP Server` 进程重建连接，在后续轮次中让工具正常回归可用。

### 需求: 超时等系统报错防幻觉重试
系统必须（MUST）在 `System Prompt` 中显式提供异常归因与重试响应的决策指令。明确区分“网络超时/基础设施繁忙等执行层异常”、“工具契约参数 Schema 不匹配校验报错”与“其他未知重大报错”三类故障：
1. 面对网络超时/基础设施繁忙等执行层异常，大模型必须（MUST）原参重新发起请求或直接报错返回用户，绝对禁止变动工具既定入参名称或擅自注入幻觉参数重试；
2. 仅在接收到确切的参数校验不通过异常时，才允许模型在对齐 Schema 后进行字段修正重试；
3. 面对既不符合网络超时特征、也不符合 Schema 错配特征的其他未知重大系统/业务工具报错（如文件锁、权限不足、未定义业务错误等），大模型必须（MUST）立即停止重试或随意修改入参的行为。必须（MUST）在回复中如实向用户陈述看见的错误原文、坦承自己无法判断根因，并请求用户协同确认为止。

#### 场景: 大模型遭遇系统级网络超时原参重试或报告用户
- **WHEN** 大模型执行搜索调用并接收到 `Request timed out` 的底层基础设施报错
- **THEN** 模型通过错误区分指令判定其为网络瞬时异常，在下一轮中自动以原输入参数重新调用或直接告知用户网络不通，绝对不会尝试篡改参数名或自行想象出类似 `apiKey` 字段强行调用。

#### 场景: 大模型遭遇未知的业务/系统错误时硬拦截重试并请求用户干预
- **WHEN** 大模型调用修改性工具时，接收到未识别的异常（如文件被锁定、或权限不足报错）
- **THEN** 模型通过错误区分指令判定其非超时和 Schema 错误，在下一轮中立即终止重试行为，向用户输出错误原文并请求用户介入排查。
