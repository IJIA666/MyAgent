## 新增需求

### 需求: 免特权高性能系统资源指标采集
系统必须提供一个高效、稳定的接口，用于获取 Windows 系统的整体性能指标。该操作必须在无需 Windows 管理员特权的环境下正常运行，且单次执行的平均耗时必须控制在 50 毫秒以内。

#### 场景: 查询系统整体指标
- **WHEN** 客户端向服务发起系统资源指标获取请求时
- **THEN** 服务返回包含系统 CPU 使用率、物理内存使用率、磁盘占用率以及全局网络收发 IO 字节数的字典结构，且无延迟卡顿。

---

### 需求: 进程级指标排序与优雅退化
系统必须支持获取并检索进程级 Top N 性能排行。在遇到受保护的系统进程或权限不足的进程时，数据采集必须实现优雅退化（即跳过特定字段或跳过该进程），而绝不允许抛出未捕获异常导致服务进程发生全局崩溃；除去必要的 CPU 采样等待周期外，整个列表的轮询检索耗时必须控制在 500 毫秒以内。

#### 场景: 查询进程级 Top N 指标
- **WHEN** 客户端请求获取当前系统前 15 个 CPU 占用最高的进程详情时
- **THEN** 服务返回包含 PID、进程名、CPU 占比、内存物理工作集大小、虚拟内存提交大小、进程读写 I/O 字节数、线程数和句柄数的有序列表，且已自动排除因权限不足无法读取的系统进程。

---

### 需求: 网络流量监听的 GIL 锁规避与高可用响应
网络流量（ETW）监听和聚合统计必须完全规避 GIL (全局解释器锁) 锁死。系统必须确保任何后台事件捕获循环的阻塞或等待均不得阻塞 FastMCP 协议解析的主 stdio 通信通道，客户端调用网络带宽统计接口必须能够在 10 秒超时阈值内稳定获取响应。

#### 场景: 调用网络带宽统计工具
- **WHEN** 客户端请求聚合过去 5 秒内的进程级网络流量带宽 Top 10 报告时
- **THEN** 服务应在 10 秒超时内，稳定返回已完成时间滑动窗口聚合的网络统计明细列表，包含各进程的 PID、进程名、发送速率、接收速率及流量总字节数。

#### 场景: 非管理员运行服务时子进程闪退退化
- **WHEN** 客户端以非管理员权限启动监控服务，且流量捕获子进程因权限不足产生迟发性闪退后
- **THEN** 网络流量工具 `get_network_traffic` 必须能够在 10 秒内优雅响应提权警告，而绝不允许因为子进程已死而返回空流量列表 `[]` 从而漏检。

---

### 需求: 多进程防残留与操作系统级清理绑定
在 Windows 操作系统中，被主服务进程创建的流量监听子进程必须强制实施操作系统级的生命周期清理绑定（Windows Job Object），以确保主进程不管以任何形式退出（包括被任务管理器强杀、发生未捕获致命崩溃等），子进程都必须随之被强制销毁。

#### 场景: 主进程被强杀后子进程的回收
- **WHEN** 主 MCP 进程由于外部信号（如 `taskkill /F`）被强制终止时
- **THEN** 操作系统自动销毁并清理与其关联的 `etw_collector.py` 流量监听子进程，后台没有任何残留的僵尸进程。

#### 场景: MCP Client 正常退出时子进程的回收
- **WHEN** 用户通过 `exit` 命令正常退出 IJIA Agent（触发 `session.close()` → `process.exit(0)`）时
- **THEN** MCP Client 必须在退出前显式关闭所有 MCP Server 连接并终止对应的子进程树，确保没有任何 Python 进程残留在后台。

---

### 需求: ETW 流量采集必须使用 Legacy Kernel Logger 会话

#### 场景: ETW 子进程能正确解析 TcpIp 事件属性
- **WHEN** ETW 流量收集子进程以管理员权限启动并监听网络事件时
- **THEN** 必须使用 `pyetwkit.KernelSession` + `KernelFlags.NETWORK_TCPIP` 启动 legacy NT Kernel Logger 会话（而非 `EtwSession` + manifest-based provider），以确保捕获到的 TcpIp 事件的 `properties` 字典包含有效的 `size` 字段，opcode 10（Send）和 11（Recv）能正确区分流量方向。
