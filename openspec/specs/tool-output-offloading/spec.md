# 业务能力: tool-output-offloading

本规范定义了超大工具输出的大文件自动拦截落盘、去中心化配额差异化折叠，以及智能分页读取调阅工具的安全和逻辑设计规范。

## 业务需求

### 需求: 工具去中心化配额差异化折叠 (Decentralized Tool Quota Pruning)

工具模块必须(MUST)在注册元数据中允许自定义 `maxLines` 和 `maxBytes`。当工具输出超出此配额时，系统必须(MUST)将完整输出同步写入本地外带目录 `.myagent/tool-outputs/`，并在消息历史中记录为包含折叠预览与文件路径引用的复合结构。送大模型前，仅投递双向行级对折与字节保底对齐截断后的预览文本。

#### 场景: 工具输出超出配额触发外带裁剪
- **WHEN** 智能体运行 `search` 工具返回了超过 100 行的庞大文本，且 `search` 工具元数据中声明了 `maxLines` 为 50。
- **THEN** 系统立即将 100 行原始文本写入 `.myagent/tool-outputs/` 目录，并在内存消息历史中将其记录为复合结构，投递给大模型时的文本仅保留前 25 行 and 后 25 行，中间插入 `... output truncated; full content saved to [originalPath] ...` 占位，且会话物理日志中保留对该原始大文件的路径索引。

### 需求: 智能分页调阅工具

系统必须向大模型提供一个支持行号范围分页读取的工具 `readFile`，支持大模型在看到占位引导后按需获取内容，避免将文件全量拉回上下文。

#### 场景: 分页读取特定行区间
- **WHEN** 大模型识别到占位信息并主动调用 `readFile` 且参数 `targetPath` 在沙箱区、`lineStart` 与 `lineEnd` 均合法时
- **THEN** 系统必须对文件路径进行沙箱验证，并只读取并返回该文件中对应行区间的纯文本，拒绝返回全量数据
