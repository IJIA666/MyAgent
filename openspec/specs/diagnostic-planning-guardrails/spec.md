# diagnostic-planning-guardrails

## Purpose

约束诊断、排障和磁盘清理建议类回合中工具失败后的下一步规划行为，防止模型在系统查询失败后升级命令复杂度或无限扩散目录枚举，确保降级路径收敛到内置只读工具、不确定性声明或请求用户缩小范围。

## Requirements

### Requirement: 诊断失败后的降级路径

系统必须（MUST）在诊断、排障或磁盘清理建议类回合中，对工具失败后的下一步行动施加收敛约束。若系统查询被拦截、失败或未提升证据等级，后续规划必须优先降级到内置只读工具、显式暴露不确定性，或要求用户缩小范围，而不得升级为更复杂的 shell 复合命令。

#### Scenario: 系统查询被拦截后回退到只读内置工具
- **WHEN** 模型为诊断磁盘占用而发起了一次系统查询，但该查询被安全策略拦截或执行失败
- **THEN** 下一步规划必须优先回退到可用的内置只读工具，或直接说明证据不足；不得立刻改写成更复杂的 shell 组合方案继续重试

#### Scenario: 失败后只能保留单一原子查询
- **WHEN** 内置只读工具无法覆盖某个明确的系统信息缺口，且模型需要再次请求系统查询
- **THEN** 后续请求必须仍然保持单一、原子、可静态证明安全；若再次失败或被拦截，系统必须停止继续升级查询复杂度

#### Scenario: 工具提示名称来自当前注册表
- **WHEN** 系统向模型生成诊断降级提醒或可用能力说明
- **THEN** 提醒中的工具名称必须来自当前 ToolRegistry 或稳定能力映射，不得硬编码未注册的 `list_dir`、`read_file` 等别名

### Requirement: 诊断扫描的停机条件

系统必须（MUST）按扫描成本、目标范围和新增证据治理目录枚举与递归测量。预算必须同时考虑请求上限与实际扫描条目、耗时和返回规模；截断后禁止自动扩大扫描，但允许在剩余预算内对已发现的更窄目标继续测量。

#### Scenario: 枚举未提升证据时停止扩散

- **WHEN** 模型连续枚举多个候选但没有产生新的对象级测量证据
- **THEN** 系统必须阻止继续扩大目标集合，并要求总结候选或请求用户缩小范围

#### Scenario: 截断后允许更窄目标收敛

- **WHEN** 一次目录测量被截断，但结果已经发现一个明确子目标且仍有剩余预算
- **THEN** 系统可以允许对该后代目标进行不扩大深度、条目、字节或时间上限的更窄测量，不得直接封死全部只读调用

#### Scenario: 截断后禁止扩大预算

- **WHEN** 模型尝试在截断后提高 maxDepth、maxEntries、maxBytes、maxDurationMs 或改扫无关范围
- **THEN** 系统必须阻断调用并要求基于现有证据总结或请求用户授权新的更窄任务

#### Scenario: 达到总成本预算后进入总结

- **WHEN** 本轮实际扫描成本达到预设总预算
- **THEN** 系统必须停止新的目录测量和枚举，把后续重点切换到对象级证据、不确定性和下一步建议

### Requirement: 诊断扫描的停机条件

系统必须（MUST）为诊断类目录枚举维护有限预算与停机条件。当继续扩展 `listFiles` 或同类只读扫描已无法新增高价值候选、无法提升证据等级或已经达到本轮预算时，系统必须停止扩散扫描并转入汇总或澄清。

#### Scenario: 枚举未提升证据等级时停止扩散
- **WHEN** 模型已经连续枚举多个候选目录，但得到的仍只是目录列表，尚未新增真实大小测量或更高证据
- **THEN** 系统必须阻止继续无限扩散枚举，并在后续上下文中明确要求转入总结当前发现或请求用户缩小目标范围

#### Scenario: 达到本轮诊断预算后进入总结
- **WHEN** 本轮诊断扫描已经达到预设的候选目录扩展预算
- **THEN** 系统必须停止继续追加新的 `listFiles` 类调用，并把后续重点切换到现有候选的解释、不确定性声明或下一步测量建议

### Requirement: 诊断工具调用必须按证据增益与实际成本收敛

系统必须（MUST）对所有诊断相关工具统一记录目标覆盖、指标新增、完整性变化、耗时、扫描条目、输出体积和失败类型，并据此计算证据增益。连续低增益、重复目标或成本超限时必须阻止继续扩散，要求缩窄目标、总结现有证据或显式报告未知项。固定调用次数只能作为辅助预算，不能代替证据增益判定。

#### Scenario: 重复枚举不新增证据

- **WHEN** 模型连续调用一个或多个工具，但只重复已有目标且没有新增指标或完整性提升
- **THEN** 系统必须阻止下一次同类扩散并要求基于现有账本总结

#### Scenario: 新目标但无筛选依据的横向扩散

- **WHEN** 模型不断增加互不相关的候选目标，却没有使用已有证据形成缩窄依据
- **THEN** 系统必须拒绝继续扩大范围，并要求说明选择下一目标的证据条件

#### Scenario: 部分结果引导更窄测量

- **WHEN** 部分结果识别出一个高价值后代目标且仍有预算
- **THEN** 系统可以允许在不扩大单次成本上限的前提下对该目标进行更窄测量

#### Scenario: Shell 只作为系统级信息补位

- **WHEN** 已注册结构化只读工具能够提供所需信息
- **THEN** 系统必须优先使用该工具；只有明确的信息缺口无法覆盖时，才允许原子且可静态证明安全的 Shell 查询

#### Scenario: 跨领域任务使用同一收敛规则

- **WHEN** 当前任务属于磁盘诊断、日志排查、进程分析或代码问题定位中的任意一种
- **THEN** 系统必须使用相同的证据增益和成本规则，不得依赖盘符、命令名或领域专用分支

### Requirement: 诊断降级工具必须具备目标指标能力

系统级诊断查询失败或被拒绝后，运行时必须（MUST）只允许能够为当前诊断指标产生有效证据的降级工具。仅能导航或枚举本地目录的浏览器工具不得作为目录容量、文件大小或可释放空间测量的替代能力。

#### Scenario: 磁盘容量查询失败后尝试浏览器导航

- **WHEN** 原子系统查询失败后，模型尝试使用 `browser_navigate` 访问 `file://` 目录以推断目录大小
- **THEN** 运行时必须拒绝该调用作为容量诊断降级路径，并要求使用具备测量解释器的更窄只读查询、总结未知项或请求用户缩小范围

#### Scenario: 合法读取本地 HTML

- **WHEN** 当前任务目标是检查一个已授权的本地 HTML 页面内容而非测量文件系统指标
- **THEN** 系统不得仅因 URL 使用 `file://` 而禁止浏览器导航

### Requirement: 所有诊断工具必须受统一的证据增益停机控制

系统必须（MUST）在诊断工具预留和结算链路中记录连续低增益、重复目标失败和无依据横向扩散。若后续调用不能新增指标、提升完整性或基于已有证据缩窄目标，系统必须阻止继续同类扩散。

#### Scenario: 连续浏览多个目录但只有枚举结果

- **WHEN** 模型连续访问多个候选目录，结果仅增加目录名称而没有容量测量或完整性提升
- **THEN** 系统必须在达到低增益阈值后停止新目录扩散，并要求总结当前候选或请求用户指定更窄目标

#### Scenario: 多次重复同类失败

- **WHEN** 多个连续诊断调用对相同指标返回拒绝、超时或执行错误，且没有形成新的有效证据
- **THEN** 系统必须阻止继续更换等价工具重试，不得由模型把失败解释成目标属性

#### Scenario: 部分结果支持更窄测量

- **WHEN** 已有证据识别出一个明确的高价值后代目标且仍有预算
- **THEN** 系统可以允许对该目标执行具备相应指标能力的更窄测量
