## 新增需求

### 需求: 向量数据库初始化与生命周期管理
系统必须具备向量数据库的初始化与连接生命周期管理能力。在系统初始化或需要加载向量存储时，如果数据库或特定的集合（表）不存在，应当自动创建并以强类型 Schema 锁死数据格式；在系统退出或关闭会话时，应当优雅物理断开连接以释放句柄与资源。

#### 场景: 数据库启动与自动初始化
- **WHEN** 向量服务启动或会话初次连接向量数据库
- **THEN** 系统自动建立物理连接（如连接到本地文件数据库路径），若发现目标表不存在，则以包含 id ( UUID )、text (记忆文本)、vector ( 1536 维特征向量)、metadata (额外元数据) 的 Schema 结构自动建表并锁死结构，随时支持数据追加。

#### 场景: 数据库连接的优雅注销与清理
- **WHEN** 系统接收到退出信号、执行 close 会话或进程即将注销时
- **THEN** 系统必须自动触发向量数据库适配器的 close() 优雅销毁方法，彻底物理关闭底层文件连接，并清空内存，防止文件锁残留与内存泄漏。

### 需求: 语义分块切片与批量索引构建
系统必须支持对大规模非结构化文档或长文本的切片（Chunking）与批量特征提取服务。物理文件同步时，系统应当使用规则或语义拆分长文本，并批量生成嵌入向量（Embedding）并插入向量数据库中。

#### 场景: 对 Markdown/PDF 物理文档进行增量切片同步
- **WHEN** 用户或自省系统对本地知识库文件（如 `.agent/MEMORY.md` ）发起向量重构或增量同步时
- **THEN** 系统读取文件，以设定的块大小（如以行或以 Markdown 标题/独立要点）拆分成多个不重合或包含微重叠的文本切片（Chunks），通过 Embedding 适配器批量换取 1536 维向量，并调用数据库适配器批量添加，避免逐条写入产生的网络开销。

### 需求: Top-K 语义距离相似度召回
系统在接收到 Query 查询时，必须能够生成查询向量，并支持在向量数据库中检索与其距离最近的 Top-K 条记录，同时必须将距离结果统一换算为直观相似度，且支持通过相似度过滤低质量结果。

#### 场景: 语义相似度查询与相似度分值换算过滤
- **WHEN** 发起向量语义匹配检索，且传入了 Query 查询文本与 Top-K 限制（如 Limit=5）
- **THEN** 系统计算 Query 的 Embedding 向量，调用向量库检索接口返回最相似的几条记录。由于底层向量数据库通过余弦距离（distance）进行检索匹配，适配器必须使用公式 `score = 1 - distance` 将其换算为标准的余弦相似度分值（处于 `[-1, 1]` 范围），并且必须硬编码拦截过滤掉 `score < 0.5` 的低相关度结果，仅返回高相关度结果列表。
