# 业务能力: context-compaction

本规范定义了会话上下文的静默自适应压缩、首尾双保中段有损压缩及大模型覆写下的窗口管理与防漏自适应机制。

## 业务需求

### 需求: 历史中段摘要协议
系统 MUST 将待压缩中段视为早于保留尾部的历史源材料，并生成只用于理解后续原文的结构化历史摘要。摘要 MUST NOT 定义当前任务、待办或下一步，MUST NOT 回答历史中的问题，且后续保留原文与摘要冲突时 MUST 以后续原文为准。

#### 场景: 生成历史型中段摘要
- **WHEN** 系统将可压缩中段发送给摘要模型
- **THEN** system 指令必须说明摘要之后仍保留时间上更新的原文，摘要只具有历史参考语义
- **THEN** 摘要必须按语义覆盖历史目标与背景、历史约束与偏好、已完成事项与结果、关键决定与依据、片段结束状态、问题/错误与有效结论、相关资源与关键事实
- **THEN** 摘要不得生成"当前任务""待处理事项"或"下一步"章节

#### 场景: 摘要输入保留必要工具事实
- **WHEN** 中段包含带 `tool_calls` 的 assistant 消息及对应 tool result
- **THEN** 摘要输入必须包含 assistant 可见文本、每个工具调用的名称与原始 arguments、tool result 的 `tool_call_id` 与内容
- **THEN** 摘要输入不得包含 system prompt、内部 `reasoning_content` 或运行时私有元数据

#### 场景: 语言、标识符与敏感信息处理
- **WHEN** 摘要模型处理任意语言的历史中段
- **THEN** 摘要正文必须沿用该历史的主要语言
- **THEN** 继续理解所需的路径、命令、错误、URL 和标识符必须保持精确，不得翻译或重写
- **THEN** API Key、Token、密码、凭据和连接字符串不得保留原值，必须替换为 `[REDACTED]`

### 需求: 中段压缩失败原子性
系统 MUST 先完成安全边界计算、摘要生成和候选结果验证，再一次性替换会话历史。任何失败都不得用缺少真实历史事实的静态文本强行截断历史，且未通过完整请求预算验证的候选历史不得提交。

#### 场景: 摘要调用失败或返回空文本
- **WHEN** 中段或全量摘要模型抛出异常、超时或返回空白结果
- **THEN** 压缩必须返回结构化失败结果
- **THEN** 内存消息历史和已持久化消息历史必须保持压缩前状态

#### 场景: 不存在安全可压缩中段
- **WHEN** 头部保护区与尾部保护区重叠，无法形成中段，或预算内无法保留至少一个完整近期轮次
- **THEN** 规划器必须把中段策略判定为不可行并在摘要前直接选择全量策略
- **THEN** 系统不得调用中段摘要模型进行试错

#### 场景: 候选历史膨胀或仍超过目标水位
- **WHEN** 摘要生成的候选历史预计用量不小于剪枝后的请求，或加入固定请求开销和输出预留后仍超过安全阈值
- **THEN** 系统必须拒绝提交候选历史并返回失败原因
- **THEN** 内存和持久化历史必须保持压缩前状态

#### 场景: 持久化失败时恢复内存历史
- **WHEN** 候选历史已经写入内存，但会话持久化失败
- **THEN** 系统必须恢复压缩前的内存历史
- **THEN** 压缩结果必须标记为失败且不得发出成功 restart

### 需求: 对抗 Lost-in-the-Middle 的首尾双保中段压缩 (Head & Tail Preserved Compaction)
当统一预算规划器选择中段压缩时，系统 MUST 保护消息历史开头连续的 system prompt 前缀，并仅对该前缀和近期尾部之间的对话历史进行 LLM 语义总结。工具列表 MUST 继续作为独立请求字段保留，不参与消息历史压缩。近期尾部 MUST 由完整 user 轮次组成，并同时服从最大轮数与 token 硬预算；若无法在预算内保留至少一个完整近期轮次，系统 MUST 将中段策略判定为不可行。

#### 场景: 规划器选择中段有损压缩
- **WHEN** 剪枝后的完整请求仍超过安全阈值，且中段候选预计能够恢复安全水位
- **THEN** 系统必须只保护消息历史开头连续的 system prompt 前缀
- **THEN** 首个 user 轮次及其 assistant/tool 结算消息应与其他较早历史一起进入中段
- **THEN** 独立模型工具列表必须保持不变
- **THEN** 系统必须只把中段交给历史型摘要模型，并将有效摘要以 `[Summary of Earlier Conversation]` 原位插入
- **THEN** 预算内的受保护尾部必须按原顺序完整拼接在摘要之后

#### 场景: 按轮数和 token 硬预算选择近期尾部
- **WHEN** 系统从最后一个 user 轮次向前选择受保护尾部
- **THEN** 尾部最多保留 `compactionRetainCount` 个完整 user 轮次，默认最多 4 轮
- **THEN** 在加入更早轮次会超过 `compactionRetainTokens` 时，系统必须停止扩展尾部，默认预算为 8000 tokens
- **THEN** 最新完整 user 轮次自身超过预算时不得突破预算被无条件保留，中段策略必须判定为不可行并交由规划器选择全量策略

#### 场景: 保持工具调用协议完整
- **WHEN** 某个受保护轮次包含 assistant `tool_calls` 与后续 tool result
- **THEN** 系统不得把压缩边界放在该工具调用与结果之间
- **THEN** 中段压缩不得改写预算内近期 tool result
- **THEN** 受保护尾部之外的旧 tool result 仅可按"可恢复的工具结果剪枝"需求生成摘要输入视图

#### 场景: 手动压缩复用统一规划策略
- **WHEN** 用户执行不带参数的 `/compact`
- **THEN** 系统必须使用与自动水位触发相同的完整预算、剪枝、策略预测和原子失败规则
- **THEN** 系统必须向用户报告实际选择的 middle、full、skipped 或 failed 结果
- **WHEN** 用户执行 `/compact full`
- **THEN** 系统必须按"全量会话检查点压缩"需求执行，不得先调用中段摘要

#### 场景: 自动压缩在最终请求边界原子提交
- **WHEN** 最终请求预算规划在模型发送前触发压缩
- **THEN** 压缩服务必须先在候选历史上完成摘要与预算验证，不得提前修改宿主会话
- **THEN** 只有候选历史通过验证并成功持久化后，AgentLoop 才能收到一次 `restart` 控制信号
- **THEN** 摘要失败、候选验证失败或持久化失败时不得提交历史或返回成功 restart

### 需求: 完整请求预算与单次策略规划
系统 MUST 在最终模型请求已经完成消息注入和工具裁剪后，对 messages、tools 及模型输出预留构成的完整请求进行预算估算。系统 MUST 在第一次摘要调用前一次性选择不压缩、中段压缩或全量压缩，同一次模型请求不得先后执行两种摘要策略。

#### 场景: 在最终请求边界估算完整预算
- **WHEN** `BeforeModel` 插件、system-reminder 注入和模式相关工具裁剪均已完成
- **THEN** 系统必须估算最终 messages 和最终 tools 的输入 Token
- **THEN** 系统必须加入当前模型最大输出预留，并将完整预计用量与 `contextWindow * compactionWatermarkFactor` 比较
- **THEN** 后续步骤不得再修改将要发送的 messages 或 tools

#### 场景: 剪枝后恢复安全水位
- **WHEN** 初始完整请求超过安全阈值，但可恢复工具结果剪枝后的请求不再超过阈值
- **THEN** 系统必须使用剪枝后的请求投影继续模型调用
- **THEN** 系统不得调用摘要模型或修改持久化历史

#### 场景: 预测中段压缩可以满足目标
- **WHEN** 剪枝后仍超过安全阈值，且存在安全可压缩中段
- **WHEN** 固定请求开销、system 头部、预算内近期尾部和最大中段摘要之和预计不超过安全阈值
- **THEN** 规划器必须选择中段压缩
- **THEN** 规划器不得在同一次模型请求中再选择全量压缩

#### 场景: 中段压缩预计收益不足
- **WHEN** 受保护尾部本身已经过大、没有安全中段、摘要源材料无法放入摘要请求，或中段候选预计仍超过安全阈值
- **THEN** 规划器必须在调用任何摘要模型之前直接选择全量压缩
- **THEN** 系统不得先执行一次中段摘要进行试错

### 需求: 可恢复的工具结果剪枝
系统 MUST 仅对能够从结构化引用或更晚完整副本恢复的旧 tool 消息执行自动剪枝。剪枝 MUST 保留消息 role、`tool_call_id`、错误状态和恢复依据，不得假设任意工具都可以安全重跑。

#### 场景: 缩减已落盘的旧工具结果
- **WHEN** 受保护近期尾部之外的 tool 消息带有 `isTruncated=true` 和有效 `originalPath`
- **THEN** 系统必须把长预览替换为包含工具调用 ID、原始输出路径和已截断事实的短引用
- **THEN** 系统必须保留原消息的 role 与 `tool_call_id`

#### 场景: 缩减完全重复的旧工具结果
- **WHEN** 受保护近期尾部之外存在内容完全相同的多个 tool 消息
- **THEN** 系统必须保留时间上最新的完整副本
- **THEN** 更早副本可以替换为指向最新 `tool_call_id` 的重复结果标记

#### 场景: 不可恢复的工具结果保持原样
- **WHEN** 旧 tool 消息没有落盘引用、没有相同的更晚完整副本，或包含工具错误
- **THEN** 系统不得自动删除、清空或改写其内容

#### 场景: 请求投影剪枝不修改持久历史
- **WHEN** 剪枝后无需生成语义摘要
- **THEN** 剪枝必须只作用于本次模型请求投影
- **THEN** `SessionContext` 与持久化会话中的原始消息必须保持不变

### 需求: 全量会话检查点压缩
系统 MUST 提供独立于中段历史摘要的全量检查点策略。该策略 MUST 摘要全部非 system 持久历史，并生成供正常 Agent 继续当前对话的状态检查点，不得改变 Agent 身份或生成 handoff 层级。

#### 场景: 自动规划直接选择全量检查点
- **WHEN** 中段压缩预计无法使请求回到安全阈值
- **THEN** 系统必须将可恢复剪枝后的全部非 system 持久历史交给全量检查点摘要协议
- **THEN** 新历史必须由原连续 system 前缀和一条 `[Conversation Checkpoint]` 消息组成
- **THEN** 独立工具列表必须继续由请求组装器提供，不得写入持久历史

#### 场景: 检查点保留继续任务所需状态
- **WHEN** 系统生成全量检查点摘要
- **THEN** 摘要必须覆盖当前目标与最新用户请求、用户约束与偏好、已完成工作和验证结果、关键决定、当前状态、阻塞、下一步及相关精确资源
- **THEN** 路径、命令、错误和标识符必须只在继续任务需要时保持精确
- **THEN** 凭据和秘密值必须替换为 `[REDACTED]`
- **THEN** 摘要不得声称 Agent 已转变为领导者、子单元或只负责战略交接

#### 场景: 手动请求全量压缩
- **WHEN** 用户执行 `/compact full`
- **THEN** 系统必须直接选择全量检查点策略
- **THEN** 系统仍必须执行摘要输入容量检查、结果验证和失败原子性规则

#### 场景: 全量摘要输入仍无法容纳
- **WHEN** 全量检查点摘要的源材料和输出预留超过当前模型物理上下文窗口
- **THEN** 系统必须保留原始持久历史并返回明确失败
- **THEN** 系统不得静默删除普通 user/assistant 消息，不得把不完整静态文本提交为成功检查点

### 需求: 有限压缩恢复与上下文溢出分类
系统 MUST 限制自动压缩 restart 和 provider 上下文溢出的恢复次数，并 MUST 将上下文溢出与认证、网络、限流及其他请求错误区分处理。

#### 场景: 连续预算 restart 被限制
- **WHEN** 一次真实模型调用尚未发生，预算规划已经产生一次压缩 restart
- **WHEN** 重组后的请求仍要求再次压缩
- **THEN** AgentLoop 必须停止再次摘要并返回明确错误
- **THEN** restart 不得无限回退 iteration

#### 场景: provider 首次报告结构化上下文溢出
- **WHEN** LLM adapter 将 provider 错误规范化为 `LlmContextWindowExceededError`
- **WHEN** 当前请求尚未执行全量压缩且尚未使用溢出恢复
- **THEN** AgentLoop 必须允许规划器强制执行一次全量压缩并重组请求

#### 场景: 全量恢复后仍然溢出
- **WHEN** 当前请求已经执行过全量压缩、已经使用过一次溢出恢复，或恢复后的请求再次返回上下文溢出
- **THEN** 系统必须停止恢复并返回明确错误
- **THEN** 系统不得再次摘要已有检查点

#### 场景: 非上下文错误不触发压缩
- **WHEN** provider 返回认证、限流、网络、超时或无法确认类型的其他错误
- **THEN** 系统必须沿用普通模型错误处理
- **THEN** 系统不得因为该错误自动触发上下文压缩

### 需求: 成功压缩后必须重新加载长期记忆快照

系统必须（MUST）仅在压缩摘要通过校验、新历史已提交且持久化成功后，从当前项目 `memoryDir` 重新加载记忆快照。重新加载成功后，后续模型请求必须（MUST）使用新快照；重新加载失败时，系统必须（MUST）记录诊断并保留旧快照，不得（MUST NOT）回滚已经成功的压缩。压缩失败、被跳过或未提交时不得（MUST NOT）刷新记忆快照。

#### 场景: 压缩和记忆刷新均成功

- **WHEN** 新的压缩历史已校验、提交并持久化成功
- **AND** 记忆目录重新加载成功
- **THEN** 后续请求使用重新加载后的记忆快照

#### 场景: 压缩成功但记忆刷新失败

- **WHEN** 新的压缩历史已提交并持久化成功
- **AND** 记忆目录重新加载失败
- **THEN** 压缩结果保持成功
- **AND** 系统记录刷新失败诊断
- **AND** 后续请求继续使用旧记忆快照

#### 场景: 压缩失败或被跳过

- **WHEN** 压缩未通过校验、持久化失败或因条件不足被跳过
- **THEN** 系统不重新加载记忆快照

### 需求: 非持久化记忆投影不得进入压缩摘要源

系统必须（MUST）仅压缩 `SessionContext` 中的持久化会话消息，不得（MUST NOT）将请求组装阶段生成的记忆投影写入摘要源。压缩后的记忆投影必须（MUST）根据刷新边界从记忆快照重新构建。

#### 场景: 请求中同时存在会话历史和记忆投影

- **WHEN** 系统触发上下文压缩
- **THEN** 摘要源只包含持久化会话历史
- **AND** 不包含请求组装阶段注入的记忆投影

#### 场景: 压缩完成后的下一次请求

- **WHEN** 压缩成功并完成记忆快照刷新
- **THEN** 下一次请求根据刷新后的快照重新生成记忆投影
- **AND** 不复用压缩前请求中的临时投影消息

### 需求: 大模型与网络参数配置化管理
系统必须支持将每个内置大模型的上下文窗口（Context Window）以及调用选项（如采样温度、超时限制、最大重试次数、自定义请求头）在配置层进行声明，且必须提供通过通用环境变量覆写整个模型配置（包括 API 端点、实际调用模型名称、上下文窗口大小、温度、超时、重试及请求头）的能力，以实现 Claude Code 式的高度可扩展性。

#### 场景: 模型最大窗口与调用选项配置化
- **WHEN** 载入大模型连接配置时
- **THEN** 系统必须将各内置模型（如 `deepseek-v4-flash`）的上下文窗口属性（`contextWindow`）、温度（`temperature`）、重试次数（`maxRetries`）、超时时间（`timeout`）及自定义请求头（`headers`）写入其 `ModelProfile` 档案；在执行自适应 Token 压缩时，系统必须基于此配置中的 `contextWindow` 属性（而非硬编码名字判定）计算触发水位。

#### 场景: Claude Code 式模型与网络配置环境变量覆写
- **WHEN** 从 `BUILTIN_MODELS` 工厂解析模型连接配置（`getModelConfig`）时
- **THEN** 系统必须支持通过 `process.env` 进行动态覆写：
  1. 支持通过 `process.env.AGENT_LLM_MODEL`（或对应的其他模型覆写变量）动态改写最终发送给 API 的模型标识符名称，允许使用第三方兼容端点。同时，系统必须支持匹配并自动剥除模型名中的 `[1m]`、`[128k]` 等窗口后缀（以防第三方 API 接收到带后缀的模型名发生校验报错），并将解析出来的物理窗口大小在系统内自适应应用；
  2. 支持通过 `process.env.AGENT_LLM_CONTEXT_WINDOW` 动态覆写上下文物理窗口大小，系统必须支持对其指定的文本缩写（如 `1m` / `1M` 代表 1000000；`128k` / `128K` 代表 128000）进行解析还原。如果检测到模型名称被覆写但缺失窗口环境变量及后缀匹配时，系统必须自动将其退化至保守的上下文物理窗口限制（32k，即 32000 tokens）以防由于第三方小模型限制而导致溢出；
  3. 支持通过 `process.env.AGENT_LLM_TEMPERATURE` 动态覆写采样温度；
  4. 支持通过 `process.env.AGENT_LLM_TIMEOUT`（毫秒）动态覆写网络超时限制；
  5. 支持通过 `process.env.AGENT_LLM_MAX_RETRIES` 动态覆写网络请求的最大重试次数；
  6. 支持通过 `process.env.AGENT_LLM_HEADERS`（以换行符或分号分隔的名值对）动态覆写并解析为自定义 HTTP 请求头合并注入。
