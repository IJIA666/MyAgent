# 探索主题: CLI 交互展示层 UX 问题

## 1. 问题定义

终端展示层的一个视觉问题：Clack 菜单在 ESC 取消时错误地显示删除线。

## 2. 关键发现与调研结果

### 问题：Clack 菜单 ESC 取消时删除线渲染误导

**现象**：在 `/` 菜单或 WorkMode 子菜单中按 ESC 取消时，Clack 自动将光标所在选项渲染为删除线，再输出取消消息。用户未选择该选项，逻辑上不相关，造成视觉误导。

**复现路径**：
```
/ → 回车 → 主菜单出现 → 光标在 "切换安全执行模式" → 按 ESC
→ 输出:
  │  ~~~切换安全执行模式 (WorkMode)~~~    ← 删除线
  └  操作已取消。
```

**根因**：`@clack/prompts` 1.5.x 的 `p.select()` 在 cancel 时自动对当前高亮项应用 `strikethrough` 样式，后输出取消消息。公开参数中没有关闭该样式的选项。这是库的内建行为。

**涉及文件**：
- `src/adapters/input/interface/command.ts` — `showInteractiveMenu()`
- `src/adapters/input/interface/commands/workmode.ts` — `WorkModeCommand.execute()`

**修复方向探讨**：

| 方案 | 做法 | 风险 |
|:---|:---|:---:|
| A: ANSI 代码覆盖 | 在 `p.cancel()` 后输出 `\x1b[1A\x1b[2K` 上移一行并清除 | ❌ `p.cancel()` 的输出行数不确定，上移一行可能只清除取消消息而保留删除线行 |
| B: 自定义 select 组件 | 用 raw readline 替换 Clack select | 工作量大，非本 issue 范围 |
| C: 接受库行为 | 保留当前表现 | 无风险 |

**方案 A 的风险细节**：`p.select()` 在 cancel 时输出两行内容：
```
│  ~~~选项文字~~~    ← 第 1 行（删除线）
└  ✔ 操作已取消。   ← 第 2 行（取消消息）
```
`\x1b[1A\x1b[2K` 只能清除第 2 行回到第 1 行末尾，删除线仍然可见。需要两次上移或更高精度的终端操作。需要在 `@clack/prompts` 1.5.x 的终端输出上确认 cancel 后的确切行序列。

## 3. 方案对比与推荐方向

| 方案 | 可行性 | 工作量 |
|:---|:---:|:---:|
| A: 精确 ANSI 后处理 | 需要测试 | 低 |
| B: 替换自定义 select | 高 | 高 |
| C: 接受库行为（暂不修复） | ✅ 当前可行 | 0 |

**推荐路径**：方案 C。此问题为低优先级 UX 问题，当前保留已知限制，无需投入修复。

## 4. 否决方案

- **重写 Clack select 组件**：工作量大，收益仅限 cancel 渲染改进，不划算。
- **移除 Clack 依赖**：整个项目多处使用 Clack，移除成本高。
