# 探索主题: Agent 联网实现架构选型

## 1. 问题定义
在构建 `MyAgent` 时，如何为 Agent 提供高效、可靠的获取互联网信息的通道（Web Search & Extraction），同时兼顾学习价值、执行效率与环境普适性。

## 2. 关键发现与调研结果
- **现有逻辑**：目前 `MyAgent` 仅有基础的本地文件操作工具，无联网能力。
- **核心洞察**：业界关于 Agent 联网主要分为两大演进方向：
  - **基于后端请求**：使用聚合 API (如 Tavily) 或组合开源库 (如 DuckDuckGo + Axios)。
  - **基于浏览器接管**：通过浏览器协议 (CDP) 提取完整的动态 DOM，甚至进一步演化为依赖视觉大模型 (VLM) 的截屏点击流（Computer Use）。
- **效率重估**：狭义的视觉截屏点击流（Computer Use）虽然理念超前，但在当前工程落地中存在执行极慢、状态易假死、横向/纵向排版空间感知差等致命缺陷。高效的工业级应用应坚守“DOM 解析/文本萃取”路线。

## 3. 方案对比与推荐方向
| 方案 | 核心机制 | 核心优势 | 致命短板 |
| :--- | :--- | :--- | :--- |
| **传统爬虫 (轻量)** | DuckDuckGo 搜 URL + Axios 抓取 | 极度轻量，无需 API Key | 无法解析 JS 动态渲染网页，极易被 Cloudflare 拦截 |
| **商业 API (省事)** | 接入 Tavily / SerpApi | 极速且稳定，返回纯净文本 | 需要长期付费，底层技术黑盒，丧失控制力 |
| **MCP/Daemon (极客)** | 通过扩展桥接用户正在使用的日常浏览器 | 完全共享登录态，无视反爬验证 | 分发部署灾难，无法脱离桌面运行在云端服务器 |
| **Playwright (工业)** | 在后台启动隔离的无头浏览器进程 | 通杀动态网页，完美适配云端、Docker 及 CI/CD 等无头环境 | 依赖库极其庞大，缺少用户态 Cookie 时偶尔会遇阻 |

**选定路径**：**Playwright 无头浏览器方案**。
- **理由**：综合权衡下，Playwright 是一条不偏科的“王道”。它既解决了传统爬虫抓不到现代 JS 网页的痛点，又规避了 MCP 方案无法在云端服务器部署的死穴。对于一个立志成为通用助手的 Agent，独立掌控自己的无头浏览器是最标准的工业级架构。

## 4. 约束、风险与未知项
- 引入 Playwright 会使得整个 Agent 项目的体积骤增（需下载底层浏览器内核）。
- 在面对极其严苛的企业级反爬盾时，无状态的无头浏览器仍有被识别拦截的概率。
- 提取出的全量 DOM/文本往往极长，如何进行精准的 Chunking（分块压缩）以防止大模型 Token 爆仓，将是下一步的重点难点。

## 5. 否决方案
- **纯视觉截图模拟（Computer Use）**：因当前时延过高且容错极差，不作为文本信息提取的主力。
- **MCP / Local Daemon 桥接用户浏览器**：由于其灾难级的部署门槛和丧失跨平台/云端部署能力的硬伤，予以否决。
