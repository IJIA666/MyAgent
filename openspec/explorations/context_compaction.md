# 探索主题: 上下文压缩与大型工具输出离线机制

## 1. 问题定义
随着 ReAct 多轮会话的迭代以及大文本工具（如长文件查看、大目录分析）的调用，Agent 的工作上下文 Token 会呈现爆发式增长。这会导致大模型 API 响应延迟急剧增大、Token 计费成本直线上升，甚至直接突破模型本身的上下文窗口限制。本项目需要设计一套在极简架构下运作的上下文压缩与大文本工具输出拦截离线机制。

## 2. 关键发现与调研结果
- **代码库现状**：目前 `SessionContext` 只提供了 `messageHistory` 的追加与回滚，尚无任何自动压缩与大文本截断防护。`LlmDriver` 为无状态的 OpenAI 桥接，具备直接发起无状态简易聊天的潜质。
- **核实与洞察**：根据业界标准，为避免信息漂移（Context Drift），不应将最新轮次的即时对话进行压缩；此外，针对大型工具输出，采用离线落盘至本地文件（Offloading）并提供文件读取路径引导是极其低廉且高保真的一维防御策略。

## 3. 方案对比与推荐方向
本方案决定采取 **规则离线 + 留新压旧滑动窗口摘要** 的混合机制，完全避开复杂子代理实例的挂载。

### 触发机制设计
- **自适应百分比阈值触发**：在会话请求前，Token 监控根据当前激活模型的最大上下文窗口限制（Context Window Limit，由模型配置提供），按动态百分比水位线（例如 75% 占用率）自适应计算出 Token 阈值。一旦当前估算的总 Token 占比超过该水位线，系统自动触发静默压缩。
- **手动指令触发**：在终端 REPL 交互菜单中提供 `Compact` 选项，支持用户一键手动强制压缩。

### 压缩细节
- **留新压旧滑动窗口**：保留最新 $N$ 轮（如最新 3 轮对话）活跃上下文，仅将更早的历史消息提炼为一段 `<context_summary>`，并作为历史首个消息节点注入，彻底从内存队列中剔除旧节点。
- **大文本工具离线**：若单个工具输出超过阈值（如 8000 字符），自动将内容落盘为 `.myagent/temp/tool_out_xxx.txt`，在上下文中替换为带前缀摘要的占位引导信息。

## 4. 约束、风险与未知项
- 摘要的生成会产生额外的 1 次 LLM 同步网络调用，会增加触发本轮请求时的首包延迟。
- 需确保当 LLM 查阅到占位符引导信息时，能够主动调用文件读取工具去查看完整的离线临时文件。

## 5. 否决方案
- **子代理独立记忆系统**：被否决。为极简 ReAct 会话引入复杂的子代理，会造成大量的 API 并发调用、时序死锁风险和巨额开发开销。
- **粗暴直接截断历史**：被否决。直接丢弃旧历史会导致 Agent 完全遗忘前期的开发共识与指令要求。
