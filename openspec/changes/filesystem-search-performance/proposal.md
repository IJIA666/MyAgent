## 改造原因

智能体在对本地项目代码库执行全文比对与特征定位时，需要高度依赖 `grepSearch` 与 `globSearch` 工具。当前这两个工具采用的同步物理递归扫描方式在处理大型工作区（例如包含 Python 的 `.venv`、前端的 `.next` 缓存或 `dist` 构建目录等）时，不仅会同步卡死 Node.js 主线程，还面临高昂的内存膨胀（OOM）风险和文件描述符耗尽（EMFILE）风险。为了确保智能体在大中型项目文件感知上的高效性与鲁棒性，现在必须对底层的扫描和读取架构进行彻底的异步流式与并发安全重构。

## 变更内容

1. **异步流式扫描重构**：将原有的同步递归文件收集（`scanDir`）重构为基于 Node.js 原生 `fs.promises.opendir` 的异步流式生成器。
2. **前置目录层级剪枝**：实现动态排除规则在目录遍历顶层的拦截机制，遇到排除项时直接跳过，严禁递归下探。
3. **并发信号量调度**：自研极简零依赖的 Promise 信号量调度器，将 `fs.promises.readFile` 并发句柄限制在 20-50 的安全区间。
4. **排除规则配置化**：排除规则不再硬编码，统一由 AppConfig 的 `runtimeLimits` 配置注入。

## 业务能力

### 新增业务能力
- 无

### 修改业务能力
- `grep-search`: 优化检索性能与并发稳定性，引入目录级前置剪枝策略与极简限流信号量。
- `glob-search`: 优化文件过滤与定位效率，适配异步扫描目录遍历器。

## 影响范围

* **受影响的组件**：文件系统工具组件（`src/adapters/tools/tools/filesystem/search.ts`）。
* **受影响的契约与API**：`GrepSearchTool` 与 `GlobSearchTool` 内部逻辑。其外部暴露给 LLM 的入参定义保持一致，不引入 BREAKING 不兼容变更，但其运行效能和在高并发、大工作区下的安全性会获得显著提升。
