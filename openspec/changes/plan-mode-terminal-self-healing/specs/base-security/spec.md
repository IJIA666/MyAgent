## 修改需求

### 需求: 终端写倾向命令拦截与安全降级
在终端命令 `execute_command` 拦截过程中，系统必须（MUST）通过敏感命令及常见别名正则审查输入命令。除了明确安全的只读白名单指令（如 `git status`、`git diff`）外，凡是包含写倾向、管道混写或未识别的复杂脚本，系统应当（SHALL）将其安全级别降级为 `behavior: 'ask'` 并挂起执行，拉起交互弹窗提问，不得静默放行。在 `Plan` 模式下，对于任何未被识别为绝对安全只读的非白名单终端命令，系统必须（MUST）予以硬拦截并返回 `BLOCKED (Plan Mode Only)` 错误；且错误消息中必须（MUST）附带针对大模型的引导性自愈提示，告知其应改用何种只读原生工具（如 `list_dir` / `read_file` 等）或指示其将高危改动在计划中进行合理表述。

#### 场景: 只读命令静默放行
- **WHEN** 智能体试图在终端执行只读白名单内的命令 `git status`
- **THEN** 拦截器识别其为无风险只读指令，直接静默放行，无需用户审批。

#### 场景: 危险写倾向命令降级审批
- **WHEN** 智能体试图在终端执行具有写倾向的删除命令 `Remove-Item -Force d:\Projects\MyAgent\dist`
- **THEN** 拦截器触发敏感命令正则与非只读判定，自动挂起命令执行，将命令的完整内容通过 `Ask` 机制展示，等待用户裁决。

#### 场景: Plan 模式下终端命令被拦截并返回自愈提示
- **WHEN** 智能体在 `Plan` 模式下试图在终端执行非白名单的只读或写命令 `wmic logicaldisk`
- **THEN** 拦截器实施硬性拦截并报错 `BLOCKED (Plan Mode Only)` ；且在返回信息中显式拼接提示语，引导智能体使用 `list_dir` 或 `read_file` 等只读 `API` 代替，阻止盲目重试。
