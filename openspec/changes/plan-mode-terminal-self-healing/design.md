## 背景

- **命令过度拦截**： 当前终端安全拦截器 `terminal.ts` 对不在白名单内的终端指令实行刚性 `BLOCKED` 拦截。而在 `Plan` 模式下，此类一刀切且缺乏引导的机制彻底破坏了智能体的只读诊断能力。

- **死循环无退路**： 拦截抛出的报错缺少提示，大模型在没有备用手段的情况下只会胡乱调整重定向符号反复重试，造成大量的 `token` 浪费 and 死循环。

- **缓存击穿问题**： 原本尝试通过在不同模式下物理裁剪 `execute_command` 工具来解决，但由于大模型 `System Prompt` 缓存机制对工具定义的高敏感度，动态裁剪会导致大面积缓存击穿，急剧拉高交互耗时与成本。


## 目标与非目标

**目标:**

- **自愈错误提示**： 重构安全网关的 Plan 拦截报错，动态拼接包含“请改用 `list_dir` / `read_file` 等专用只读工具或将高危改动描述至计划”的自愈引导词。

- **保持工具静态**： 确保在所有工作模式下（包括 `Plan` 模式），大模型工具集定义均保持 100% 完整静态下发，不执行任何运行时物理裁剪，保障系统缓存命中率。

- **气泡策略收紧**： 在系统提示词和 `<system-reminder>` 气泡中，显式强调通用终端工具不可在只读阶段用作常规数据查询的规则，斩断通用工具吸附。

**非目标:**

- **物理裁剪工具**： 本变更坚决不采用动态裁剪或下架 `execute_command` 工具的方式进行输入端拦截，捍卫双轨制设计的底座缓存性能。

- **放开安全沙箱**： 绝不放开常规的越权目录访问限制。


## 架构决策

- **自愈报错注入**： 修改 `src/adapters/tools/impl/system/terminal.ts` 中的 `checkSafety` 逻辑。在判定工作模式为 `Plan` 且 `safetyLevel !== 'allow'` 时，返回的 `message` 字段拼接针对大模型的引导话术。

- **静态工具下发**： 维持 `agent-loop.ts` 或对应通道在工具过滤时的纯静态性，禁止在 `Plan` 模式下强行剥离写倾向工具（如 `execute_command` ），捍卫缓存命中率。

- **气泡偏好强化**： 优化 `input-listener.ts` 和注入器中的气泡，对大模型实施偏好限制，明确告知其应优先调用专用只读 `API` 替代终端工具。

- **[调试修正] 审计气泡留存**： 在 `agent-loop.ts` 中，将当轮注入的气泡内容动态挂载到物理历史消息对象的 `systemReminder` 自定义非标属性上。由于 API 交互不处理该属性，它对 LLM 交互纯净度无副作用，但在会话持久化落盘时会被完整写入 JSON 记录中，提升系统可观测性。


## 风险与权衡

- **终端负面吸附**： 维持终端工具完整下发后，大模型仍有可能被终端工具的通用性吸引而产生调用倾向。 -> 缓解策略：通过在拦截报错中返回极具建设性的“只读自愈引导词”，并借助气泡注入进行前置压制，让大模型在发生错误后能实现秒级纠错并自动转向原生工具。

- **缓存击穿防范**： 动态参数变化可能引起缓存局部波动。 -> 缓解策略：工具定义在整个应用周期内全局锁定静态不变，保证缓存命中率维持在最高水平。
