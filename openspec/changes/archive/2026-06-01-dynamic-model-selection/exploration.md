# 探索主题: 动态模型选择与配置解耦

## 1. 问题定义
当前项目 `MyAgent` 中的模型配置高度耦合：
- 配置项强依赖 `.env` 环境变量（`DEEPSEEK_API_KEY`、`DEEPSEEK_API_URL`、`DEEPSEEK_MODEL`），扩展其他厂商模型繁琐。
- 核心代码 `session.ts` 中硬编码了 DeepSeek 模型特有的 API 载荷（`reasoning_effort: "high"` 和 `extra_body: { thinking: { type: "enabled" } }`），导致切换到不支持推理的模型或其它厂商模型时请求崩溃。

目标：实现内置多款主流模型配置，允许用户在不修改代码、不重启应用的情况下动态切换模型。

## 2. 关键发现与调研结果
- **现有逻辑**：`config.ts` 从 `.env` 获取固定的深知（DeepSeek）变量；`session.ts` 在每次 `chat.completions.create` 时都携带固化的推理参数。
- **参考实现调研**：深入调查了标杆项目（如 `openclaw`），发现在 `ui/app-chat.ts` 中，它们采用了拦截 `/model` 这一本地 Slash Command 的方式来进行热切换。这证实了在会话流内使用命令来变更模型是目前先进 CLI Agent 的通用最佳实践。

## 3. 方案对比与推荐方向
| 方案 | 优点 | 缺点 | 结论 |
| :--- | :--- | :--- | :--- |
| **A. 启动时 CLI 交互选择** | 直观、进入会话前目标明确。 | 每次启动多一步打断，不便于中途切换。 | 否决。不够敏捷。 |
| **B. 会话内 Slash Command (/model)** | **热切换极度灵活**，符合主流 Agent 最佳实践；支持长对话中途按需升降智。 | 需要实现一套本地命令拦截和模型注册表机制。 | **采纳。** |
| **C. 基于 Env Profile 的预设组** | 改动极小，无须改变会话逻辑。 | 依然需要修改配置并重启，体验不够无缝。 | 否决。 |

**推荐路径**：
采纳 **方案 B**。
- **代码重构点 1**：在代码库中引入一个模型注册表（Registry），预置几款常用模型（如 DeepSeek-V3, DeepSeek-R1, GPT-4o, Claude-3.5）的 URL 与特化 Payload 属性。
- **代码重构点 2**：在 `index.ts`（交互层）拦截 `/model <model-id>` 命令。当用户输入此命令时，直接更换 `SessionManager` 内部激活的模型配置。
- **代码重构点 3**：清理 `session.ts` 中硬编码的特化 Payload，改为从当前激活的 Model Profile 中动态读取并展开。

## 4. 约束、风险与未知项
- **环境凭证管理**：不同厂商的 API Key 前缀可能不同（如 `OPENAI_API_KEY`、`ANTHROPIC_API_KEY`）。如果用户试图切换到一个 `.env` 中尚未配置 Key 的模型，系统应当给出友好的提示而非底层报错。
- **会话历史兼容**：中途切换模型时，历史消息列表（`messageHistory`）直接沿用，需确保不同的模型厂商对系统提示词（System Prompt）或工具调用的格式兼容性。

## 5. 否决方案
- **启动时强制交互式表单**：否决原因，增加了启动摩擦力，且无法满足单次长会话中不同任务对模型能力的不同需求（例如：写代码用 R1，日常对话用 V3）。
