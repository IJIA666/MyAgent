## 改造原因

智能助手在处理高频开发任务时，往往缺乏跨会话的长效经验沉淀。一旦当前会话关闭、进程重启或切换到全新的 Thread ，上一轮对话中沉淀下来的关键信息（如用户偏好、开发踩坑教训、架构决策）就会丢失，这导致大模型容易在后续对话中重犯相同的错误。

为了解决这一痛点，我们引入长期记忆自省与提炼机制。第一阶段通过轻量非阻塞提炼逻辑将短期会话历史转化为长期知识，以提升智能助手的跨会话上下文理解延续度，降低重复沟通成本。

## 变更内容

1. **会话结束异步自省**：在会话自然结束（ `SessionEnd` 钩子触发）时，系统异步非阻塞地调用大模型（ LLM ）接口，将本次会话的核心信息（如踩坑记录、编码规范、用户偏好等）提炼为简短的事实片段。
2. **长期记忆增量落盘**：将提炼好的事实片段以增量追加的形式写入到项目 `.agent/MEMORY.md` 中。
3. **推理前置动态注入**：在下一次启动大模型推理前（ `BeforeModel` 钩子触发），如果检测到 `.agent/MEMORY.md` 存在，则读取其内容并作为上下文的一部分动态追加注入 System Prompt 中，以实现长效记忆的即时召回。

## 业务能力

### 新增业务能力
- `long-term-memory-refinement`: 会话结束后异步提炼长效经验与事实，持久化存入 `.agent/MEMORY.md` ；在下一次启动对话时，动态读取该记忆文件并注入大模型的 System Prompt 中实现长效召回。

## 影响范围

*   **Hook 钩子系统**：影响 `BeforeModel` 钩子和 `SessionEnd` 钩子。
*   **大模型调用与 Token 消耗**：在 `SessionEnd` 阶段会额外产生一次用于记忆自省提炼的异步 LLM 调用；在 `BeforeModel` 注入 `.agent/MEMORY.md` 后，新会话每次生成的 System Prompt 的 Token 消耗会有所增加。
*   **文件系统**：会在项目 `.agent/` 目录下读写 `MEMORY.md` 文件。
