## 背景

在堆砌复杂功能前，解决“成败归因”问题是首要任务。我们需要一个机制来追踪大模型在 ReAct 循环中究竟看到了什么、思考了什么、触发了什么工具，以便针对性地进行工程调优。

## 目标与非目标

**目标:**
- 在 `SessionManager` 中获取完整的请求与响应报文。
- 将每一轮交互封装为标准的结构体，追加写入会话级别的 JSONL 文件。

**非目标:**
- 暂不构建提供可视化界面（UI）的 Trace Viewer，仅解决落盘问题。
- 暂不接入外部监控平台（如 LangSmith 或 Datadog）。

## 架构决策

- **文件格式选择: JSONLines (JSONL)**
  - *理由*：每行一个独立 JSON 对象的机制非常适合流式追加写入（Append Only），即便程序崩溃也能保证已写入轮次的数据完整性。
- **解耦设计: AgentTracer 类**
  - *理由*：将磁盘 IO 和路径组装逻辑封装在独立的 `AgentTracer` 中，避免污染 `SessionManager` 的核心逻辑流。

## 风险与权衡

- **风险: 磁盘空间消耗** → 长时间的会话可能产生大量的 Trace 日志。
  - *权衡*：目前定位于开发调试与早期评测阶段，暂时不引入自动清理与轮转机制，优先保证观测数据的无损留存。
