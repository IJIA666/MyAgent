## 修改需求

### 需求: 超时等系统报错防幻觉重试
系统必须（MUST）在 `System Prompt` 中显式提供异常归因与重试响应的决策指令。明确区分“网络超时/基础设施繁忙等执行层异常”、“工具契约参数 Schema 不匹配校验报错”与“其他未知重大报错”三类故障：
1. 面对网络超时/基础设施繁忙等执行层异常，大模型必须（MUST）原参重新发起请求或直接报错返回用户，绝对禁止变动工具既定入参名称或擅自注入幻觉参数重试；
2. 仅在接收到确切的参数校验不通过异常时，才允许模型在对齐 Schema 后进行字段修正重试；
3. 面对既不符合网络超时特征、也不符合 Schema 错配特征的其他未知重大系统/业务工具报错（如文件锁、权限不足、未定义业务错误等），大模型必须（MUST）立即停止重试或随意修改入参的行为。必须（MUST）在回复中如实向用户陈述看见的错误原文、坦承自己无法判断根因，并请求用户协同确认为止。

#### 场景: 大模型遭遇系统级网络超时原参重试或报告用户
- **WHEN** 大模型执行搜索调用并接收到 `Request timed out` 的底层基础设施报错
- **THEN** 模型通过错误区分指令判定其为网络瞬时异常，在下一轮中自动以原输入参数重新调用或直接告知用户网络不通，绝对不会尝试篡改参数名或自行想象出类似 `apiKey` 字段强行调用。

#### 场景: 大模型遭遇未知的业务/系统错误时硬拦截重试并请求用户干预
- **WHEN** 大模型调用修改性工具时，接收到未识别的异常（如文件被锁定、或权限不足报错）
- **THEN** 模型通过错误区分指令判定其非超时和 Schema 错误，在下一轮中立即终止重试行为，向用户输出错误原文并请求用户介入排查。
