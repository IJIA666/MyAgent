## 修改需求

### 需求: 强制执行原子化操作与反休眠
系统必须在底层防范非授权的命令拼接与命令替换注入。系统必须防御以下两种情况：
1. **复合拼接与替换符拦截**：安全网关必须拦截包含非法复合连接符或注入符的命令（非法字符包括 `&`, `|`, `<`, `>`, `;`, `^`, `%`, `\r`, `\n`，反引号 `` ` ``，以及命令替换符 `$(`，`\(`）。如果检测到这些拼接或替换符号在非引号包裹状态下出现，系统必须直接抛出异常拒绝执行。
2. **引号安全放行**：网关必须具备轻量级引号感知能力。对于被单引号 `'`、双引号 `"`、反引号 `` ` `` 合理包裹的复合拼接字符（例如 `grep "feat;fix"` 中的分号），系统应当予以安全放行，避免误杀合法的命令参数。

#### 场景: 模型企图使用 `&&` 连接或使用重定向
- **WHEN** 模型发送带有 `&&` 的命令，或试图重定向输出 `echo 1 > a.txt`
- **THEN** 终端执行引擎通过正则检测发现非法连接符或重定向符，直接抛出异常并拒绝执行命令。

#### 场景: 正常命令参数中包含被双引号包裹的分号
- **WHEN** 模型发送执行含有安全包裹分号的只读命令（如 `git log --grep="feat;fix"`）
- **THEN** 安全网关的引号感知器识别出分号处于双引号内部，予以放行，命令被正常送入系统执行。

#### 场景: 模型利用未包裹的分号企图逃逸注入
- **WHEN** 模型利用分号在原始命令（包括外壳）中拼接注入第二条指令（如 `ls ; cat /etc/passwd`）
- **THEN** 安全网关在内部剥除外壳并经过引号感知后，捕获到处于 unquoted 状态的非法分号，直接拦截并抛出拒绝执行的异常。

## 新增需求

### 需求: 终端 Git 写操作绝对阻断
系统为了严格恪守只读安全边界，必须在最底层绝对阻断任何改写仓库或涉及文件变更的非只读 Git 指令。
1. **阻断子命令列表**：包括但不限于 `add`, `commit`, `checkout`, `reset`, `push`, `pull`, `rebase`, `merge`, `stash`, `revert`。一旦检测到核心命令以 `git` 开头且紧随这些写操作子命令，网关必须直接阻断抛错。
2. **全模式硬拦截**：该卡关规则属于不可豁免的硬底盘阻断，哪怕系统处于 YOLO（极速放行）模式，或 Auto（自动）模式下人工确认批准，也均直接强制拒绝执行，杜绝安全红线突破。

#### 场景: 模型在 YOLO 或 Auto 模式下企图执行 git commit 变更操作
- **WHEN** 模型在 YOLO 模式下试图调用终端工具执行 `git commit -m "update"`
- **THEN** 安全网关自动识别该核心命令属于 Git 写变更操作，触发绝对阻断拦截，抛出安全红线异常并直接拒绝执行。
