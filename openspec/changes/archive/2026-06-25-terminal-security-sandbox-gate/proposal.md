## 改造原因

为了防范以下两类严重的终端安全和权限漏洞：
1. **复合拼接与命令替换注入逃逸**：当前 `terminal-guard.ts` 中基于 `COMPOSITE_REGEX = /[&|<>^%\r\n]/` 的过滤无法拦截分号 `;`、反引号 `` ` ``，同时缺乏对 `$()` 和 `${}` 命令替换符号的拦截，导致模型在执行终端命令时可通过多指令拼接绕过沙箱和拦截网关。
2. **Git 限制漏洞**：按照“严禁执行除查看外的任何 Git 操作”的安全红线规范，当前网关只在 `checkCommandSafetyLevel` 对只读白名单外的 git 动作判定为 `'ask'`。在 YOLO 模式下会被直接通过，在 Auto 模式下一旦用户误确认也会被执行，缺乏在底盘上的绝对硬阻断。

## 变更内容

1. **复合拦截正则重塑**：升级 `COMPOSITE_REGEX` 屏蔽分号 `;`、反引号 `` ` ``、以及命令替换语法 `$(`、`\(` 等符号。
2. **引号感知防注入**：实现轻量级引号感知剥离逻辑。在进行拦截扫描时，忽略被单引号、双引号、反引号包裹的安全字符（例如 `grep "a;b"` 中的分号），但强力拦截所有 unquoted 状态的拼接注入字符。
3. **防御性内部剥壳**：保持 `validateCommand(command)` 签名与契约一致性，但其内部实现升级为自动剥除嵌套外壳后，对核心解包后的命令进行引号感知的拼接注入扫描。
4. **Git 写/变更操作硬性拦截**：建立非只读 Git 命令绝对黑名单。一旦检测到核心命令以 `git` 开头，且匹配到 `add`, `commit`, `checkout`, `reset`, `push`, `pull`, `rebase`, `merge`, `stash`, `revert` 等写入或变更操作，在任何模式下均直接拒绝执行，不允许降级为 `ask`。
