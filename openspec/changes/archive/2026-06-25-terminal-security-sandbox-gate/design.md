## 背景

当前终端执行安全网关 `terminal-guard.ts` 对命令注入拼接符拦截不全（遗漏分号与反引号），且无法识别参数内的安全引号包裹（容易引起合法参数误杀），对非只读的 Git 写入变更操作也缺乏绝对硬性阻断。为了建立铜墙铁壁般的终端执行环境，必须对其进行底层架构加固。

## 目标与非目标

**目标:**
* **复合命令及命令替换防堵**：阻断利用分号 `;`、反引号 `` ` ``、`$()` 与 `\(` 命令替换的注入漏洞。
* **参数引号安全避让**：在核心命令剥壳后识别引号包裹状态，安全放行包裹在单/双/反引号内部的复合字符（如 `grep "a;b"`），只强力阻断 unquoted 的危险拼接符。
* **全模式绝对阻断 Git 写命令**：不论在何种运行模式下（包括 YOLO 与 Auto），绝对禁止执行除只读查看外的任何 Git 变更操作，且无权通过人工审批放行。
* **签名一致与防御性设计**：维持 `validateCommand` 的外部签名契约，但其实现内核升级为“内部防御性剥壳再过滤”机制，防止调用方使用不当。

**非目标:**
* **不引入外部复杂 AST 库**：不引入编译要求高的 Tree-sitter 等依赖，保持代码极其轻量与易部署。
* **不拦截正常只读 Git 查询**：允许 `git status`, `git diff`, `git log`, `git show`, `git branch` 等无副作用的查看命令。
* **不兼容行内 PowerShell 复杂子表达式**：出于安全首要原则，对于 `$(` 在 PowerShell 中的合法子表达式误杀不做绕过，强制要求持久化为脚本文件运行。

## 架构决策

### 决策 1：防御性内部自动剥壳
* **背景与现状**：目前 `unboxNestedCommand` 与 `validateCommand` 职责分离，导致 `validateCommand` 直接检查原始命令时，包裹在外壳（如 `powershell -Command`）双引号内的分号无法被安全处理。
* **决策**：`validateCommand(command)` 内部首行立即调用 `unboxNestedCommand(command)` 获取解壳核心命令 `unboxedCmd`。校验与拦截逻辑完全基于 `unboxedCmd` 进行。
* **理由**：维持了 API 外部契约的简易性，防范了遗漏剥壳导致的安全后门。

### 决策 2：引号感知的状态机扫描逻辑
* **背景与现状**：直接用正则表达式 `COMPOSITE_REGEX` 对核心命令一刀切扫描会误杀 `grep "a;b"` 里的合法参数分号。
* **决策**：实现一个轻量级的逐字符状态机分析算法。遍历核心命令 `unboxedCmd`，跟踪当前是否处于单引号 `'`、双引号 `"`、反引号 `` ` `` 包裹之内，并处理转义字符 `\`。
* **逻辑**：仅当处于**任何引号包裹之外 (unquoted)** 的状态下，如果遇到匹配 `/[;&|<>^%\r\n]|\$\(|\\\(/` 字符或反引号，则断定发生命令拼接注入，立即抛出异常。

### 决策 3：底盘阻断非只读 Git 变更操作
* **背景与现状**：目前 Git 写操作被降级为 `ask` 状态，人工确认后即可执行，违反了 Git 变更红线。
* **决策**：
  1. 定义 `DANGEROUS_GIT_WRITE_REGEX = /\b(add|commit|checkout|reset|push|pull|rebase|merge|stash|revert)\b/` 包含所有的 Git 写/变更操作。
  2. 在 `isHardlineDangerous` 绝对黑名单中加入如下判定：当剥壳后的 `unboxedCmd` 以 `git` 开头，且匹配到 `DANGEROUS_GIT_WRITE_REGEX` 时，直接返回 `true`。
  3. `validateCommand` 内部也在自动剥壳后，对命中上述 Git 写的命令执行抛错阻断。
* **理由**：提供双层绝对拦截，将限制贯彻在最底盘，YOLO 模式也绝对无法逃逸。

## 风险与权衡

* **PowerShell 子表达式变量访问误杀**：
  * *风险*：PowerShell 合理的变量子表达式 `$($var.name)` 会触发 `$(` 命令替换注入特征而引发误杀。
  * *权衡*：安全优先。为了阻断高危的 `$(whoami)` 注入漏洞，我们选择“宁错杀”决策。模型在运行复杂或含有子表达式的命令时，必须先将其落盘为 `.ps1` 文件，再调用该文件运行以触发人工审核卡关。
* **畸形不平衡引号**：
  * *风险*：若传入参数的引号未成对闭合或嵌套极度扭曲，可能导致状态机计数错乱。
  * *缓解*：在状态机遍历前，首先检测命令中单/双引号是否成对（偶数），不平衡的直接拒绝执行以防引号闭合逃逸。
