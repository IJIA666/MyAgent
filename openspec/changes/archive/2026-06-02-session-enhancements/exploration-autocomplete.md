# 探索主题: 斜杠命令交互式自动补全 (Command Auto-complete)

## 1. 问题定义
随着斜杠命令（如 `/model`, `/rollback`, 未来的 `/history`, `/resume`）增多，用户希望在键入 `/` 时自动弹出命令推荐列表，并支持通过上下方向键动态选择，以减少全拼输入的心智负担和打字量。

## 2. 关键发现与调研结果
- **现有逻辑**：在 `src/interface/cli.ts` 中，我们使用的是 Node.js 极为轻量、原生的 `readline.createInterface()` 来捕捉用户输入。
- **核心洞察**：原生的 `readline` 天生只支持基于 `<Tab>` 键的静态补全（即敲下 Tab 后帮你把剩下的字母补齐，或者罗列出可能的词），它**不具备**“在光标下方悬浮渲染一个交互式下拉菜单供上下键选择”的能力。

## 3. 方案对比与推荐方向
要实现“上下键动态选择菜单”，我们面临着技术路线的分歧：

| 方案 | 优点 | 缺点 | 适用场景 |
| :--- | :--- | :--- | :--- |
| **方案 A：原生 Tab 键补全** (Native Readline Completer) | 零依赖。只需利用 `readline` 内置的 `completer` 参数。用户键入 `/r` 后按 Tab 键，自动补齐 `/rollback`。 | **不支持上下键选择下拉菜单**，必须靠按 Tab 来触发，属于老派 Unix 命令行风格。 | 坚持极简原生依赖、不想大修 UI 层的情况 |
| **方案 B：引入重型交互框架** (如 Ink / Inquirer) | 界面现代美观，完美支持用户想要的自动推荐与上下方向键选择。 | **架构震荡极大**。无论是之前提到的全量框架 `ink`（React for CLI，如 Claude Code 所用），还是单纯接管输入的交互提示库（如 `Inquirer` / `Enquirer`），都会强行接管整个 TTY 终端流。这极易导致我们刚做好的“双击 ESC 打断”和“流式内容滚动输出”陷入抢占冲突甚至瘫痪，需要推翻并重写整个 `cli.ts` 的事件分发机制。 | 决心彻底重构终端交互层 |
| **方案 C：手写裸终端劫持** (Raw TTY Hacks) | 保持当前架构，依靠强行截获按键并在光标下方绘制字符菜单。 | 极度脆弱 (Brittle)。一旦遇到用户终端窗口过窄发生折行，菜单擦除计算就会错乱，出现严重的“视觉幽灵”残影。 | 不推荐 |

**当前探索建议与最终决策**：
鉴于用户的战略规划（未来重心可能向真正的图形前端转移，当前只是暂用终端），我**强烈反对**此时引入方案 B 这种重量级 UI 引擎。重写整个 CLI 的投入产出比（ROI）极低，属于严重的过度设计。
因此，我们**正式拍板采用方案 A（原生 Tab 键补全）**。用最少的代码成本，解决“敲全命令太累”的核心痛点，同时完美保持底层架构的纯粹与稳定，绝不为短期的终端炫技背上长期的技术债。

## 4. 约束、风险与未知项
- 如果选择方案 B，原有的针对系统级的 `keypress` 拦截（双击 ESC 控制中断与回滚）可能会与 Inquirer 等高级库自身的快捷键分发器发生严重抢占冲突。
