## 新增需求

### Requirement: 局部规则文件的探测与自动加载
系统必须在会话启动时，自动探测项目根目录下是否存在指定的局部规则文件（默认为 `.myagent.md` ）。如果文件存在，系统必须加载其全部文本内容并驻留在内存缓存中；如果文件不存在，系统应当静默忽略，局部规则上下文默认为空。

#### Scenario: 项目中存在合法的局部规则文件
- **WHEN** 会话启动且项目根目录下存在包含规则内容的 `.myagent.md` 文件
- **THEN** 系统成功读取该文件，并将其内容提取存入会话上下文的加载内存中，在单次会话周期内缓存该内容，不再重复发起磁盘 I/O 读取

#### Scenario: 局部规则文件不存在
- **WHEN** 会话启动但项目根目录下不存在 `.myagent.md` 文件
- **THEN** 系统正常完成初始化并正常运行，局部规则内容上下文为空

### Requirement: 规则在上下文历史中的前置动态注入
系统必须通过 `ContextAdapter` 接口，在每次 LLM 交互时将局部规则动态注入至消息历史中。注入消息的角色必须为 `system` ，其内容必须包裹在特定的 XML 标签中以起到格式隔离作用，并且注入位置必须在最后一条角色为 `user` 的消息之前，以确保不破坏 Tool-use 轮次的消息交错顺序。

#### Scenario: 向含有用户消息的历史记录中注入局部规则
- **WHEN** LLM 交互发生，且当前消息历史中包含至少一条 `user` 消息，且局部规则内容非空
- **THEN** 局部规则内容被包裹在 `<project_rules>` 标签中，以 `role: 'system'` 的消息格式插入到最后一条 `user` 消息之前，其余历史消息顺序保持不变

#### Scenario: 无用户消息时的边界注入
- **WHEN** LLM 交互发生，但消息历史中不包含任何 `user` 消息（如会话刚刚启动），且局部规则内容非空
- **THEN** 局部规则消息被以 `role: 'system'` 追加到消息历史列表的末尾

### Requirement: 规则的手动热重载与缓存清除
系统必须对外暴露规则重载方法。当外部调用该方法时，系统必须立即清空内存中锁定的规则缓存（包括全局规则与局部规则），并在下一次与大模型交互前重新读取磁盘文件，以将最新的规则内容注入后续交互。

#### Scenario: 执行手动重载指令
- **WHEN** 规则重载方法被调用，且磁盘上的规则文件已更新
- **THEN** 内存中的规则文件缓存被立即清空，在随后的 LLM 交互时重新触发磁盘读取，将更新后的规则内容注入上下文
