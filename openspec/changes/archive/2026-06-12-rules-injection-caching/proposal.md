## 改造原因

智能体在执行任务时需要感知两类自定义规则：全局规则（全局人设与安全红线）与局部规则（项目级特定规范，例如项目根目录下的 `.myagent.md` 文件）。当前系统的痛点表现为：
1. 缺乏局部规则文件的自动探测与加载逻辑。
2. 缺乏局部规则文件读取的锁定机制。如果会话中途局部规则文件被修改或多次读取，容易引发 API 请求中前缀哈希抖动，从而导致大模型前缀缓存（Prompt Caching）频繁失效，显著增加响应延时和 Token 成本。
3. 全局规则目前仅在会话启动时加载，如果开发过程中修改了规则文件，无法在保留当前对话历史的前提下实现热重载。

因此，需要建立一套外部规则加载、注入与内存级锁定的规范，在单次会话循环中保障大模型前缀缓存命中率的最大化，并提供手动的缓存清理重载入口。

## 变更内容

1. **局部规则的自动探测与加载**：在会话启动时，自动探测并读取工作区中的局部规则文件（如项目根目录下的 `.myagent.md`）。
2. **规则动态前置注入**：将加载到的局部规则内容以 `role: 'system'` 消息形式包裹在特定的 XML 标签中，并通过 `ContextAdapter` 机制动态插入到最新一条 `user` 消息之前。
3. **会话级内存缓存锁定**：对局部规则文件的磁盘读取实施内存缓存锁定，在单次会话生命周期内（除非显式重置）保持其前置哈希完全不变，提高 Prompt Caching 命中率。
4. **规则缓存重载机制**：在会话管理器中暴露清理/重载接口，允许在交互中显式清空内存缓存，以便下一轮 API 调用重新载入最新的全局与局部规则。
