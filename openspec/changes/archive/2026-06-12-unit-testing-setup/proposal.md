## 改造原因

智能体系统底层深度依赖本地文件沙箱安全边界校验、外部 MCP 服务进程的生命周期管理以及复杂的上下文决策逻辑。在此前的多次迭代与加固重构中，系统缺乏自动化的测试拦截网与依赖模拟（Mock）机制，只能依靠手工编写的临时测试脚本进行非标校验。这给系统的长期演进和团队协同开发带来了潜在的回归风险。

特别是在大脑决策层中，上下文适配器（`DefaultContextAdapter`）控制着局部规则和临时技能的动态注入位置。若注入顺序错乱或击穿消息角色相邻性规则，大模型交互将直接产生致命协议错误。

因此，现在急需引入并搭建现代化的单元测试基础设施。通过自动化测试门禁防范未来的路径逃逸、信号泄露、命名冲突等高风险漏洞，并全面保障核心上下文拼接逻辑的精准与不可变原则，从而为核心重构提供确定性的底座保障。

## 变更内容

本变更主要包含以下基础设施建设与测试加固工作：
1. **测试框架集成**：在项目中引入 `vitest` 测试运行器作为开发依赖，提供原生 TypeScript 和 ESM 环境的极速执行支持。
2. **配置文件注入**：在项目根目录下配置 `vitest.config.ts`，定义测试文件的查找路径与环境隔离机制。
3. **测试命令配置**：在 `package.json` 中配置通用的 `npm run test` 脚本。
4. **安全沙箱单元测试**：针对 `src/action/tools.ts` 中的 `secureResolvePath` 校验逻辑编写覆盖完整物理路径边界（包含恶意相对路径遍历、绝对路径越界及同前缀越位逃逸）的单元测试。
5. **MCP 客户端优雅销毁与同名冲突测试**：针对 `src/action/mcp-client.ts` 编写测试用例。利用 `@modelcontextprotocol/sdk` 内建的 `InMemoryTransport` 在进程内存中模拟 MCP JSON-RPC 消息流，在不唤起真实 stdio 子进程的前提下，测试并断言其对于同名工具挂载冲突的抛错阻断、优雅关闭延迟、以及信号监听的解绑回收逻辑。
6. **上下文适配器拼装测试**：针对 `src/brain/adapters/DefaultContextAdapter.ts` 编写单元测试用例，断言局部项目规则与临时技能的插入顺序、插入位置（必须插在最后一条 `user` 消息之前以防协议崩溃）以及无 `user` 消息时的末尾兜底行为。

## 业务能力

### 新增业务能力
- 无 (本变更为纯技术性测试重构与基础设施搭建，不引入用户可见的新业务逻辑能力)

### 修改业务能力
- 无 (核心组件的现有业务行为规格不发生任何变更)

## 影响范围

*   **开发依赖项**：新增 `vitest` 及其配套包（约增加几十兆的环境体积）。
*   **配置文件**：项目根目录新增 `vitest.config.ts`。
*   **工程脚本**：`package.json` 中将添加 `scripts.test` 命令。
*   **目录结构**：`test/` 目录将被正式启用，作为持续集成的测试文件存储区，且测试代码将上传至 Git 仓库管理。
