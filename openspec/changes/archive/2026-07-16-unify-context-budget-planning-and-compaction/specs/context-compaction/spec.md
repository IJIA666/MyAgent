## ADDED Requirements

### Requirement: 完整请求预算与单次策略规划
系统 MUST 在最终模型请求已经完成消息注入和工具裁剪后，对 messages、tools 及模型输出预留构成的完整请求进行预算估算。系统 MUST 在第一次摘要调用前一次性选择不压缩、中段压缩或全量压缩，同一次模型请求不得先后执行两种摘要策略。

#### Scenario: 在最终请求边界估算完整预算
- **WHEN** `BeforeModel` 插件、system-reminder 注入和模式相关工具裁剪均已完成
- **THEN** 系统必须估算最终 messages 和最终 tools 的输入 Token
- **THEN** 系统必须加入当前模型最大输出预留，并将完整预计用量与 `contextWindow * compactionWatermarkFactor` 比较
- **THEN** 后续步骤不得再修改将要发送的 messages 或 tools

#### Scenario: 剪枝后恢复安全水位
- **WHEN** 初始完整请求超过安全阈值，但可恢复工具结果剪枝后的请求不再超过阈值
- **THEN** 系统必须使用剪枝后的请求投影继续模型调用
- **THEN** 系统不得调用摘要模型或修改持久化历史

#### Scenario: 预测中段压缩可以满足目标
- **WHEN** 剪枝后仍超过安全阈值，且存在安全可压缩中段
- **WHEN** 固定请求开销、system 头部、预算内近期尾部和最大中段摘要之和预计不超过安全阈值
- **THEN** 规划器必须选择中段压缩
- **THEN** 规划器不得在同一次模型请求中再选择全量压缩

#### Scenario: 中段压缩预计收益不足
- **WHEN** 受保护尾部本身已经过大、没有安全中段、摘要源材料无法放入摘要请求，或中段候选预计仍超过安全阈值
- **THEN** 规划器必须在调用任何摘要模型之前直接选择全量压缩
- **THEN** 系统不得先执行一次中段摘要进行试错

### Requirement: 可恢复的工具结果剪枝
系统 MUST 仅对能够从结构化引用或更晚完整副本恢复的旧 tool 消息执行自动剪枝。剪枝 MUST 保留消息 role、`tool_call_id`、错误状态和恢复依据，不得假设任意工具都可以安全重跑。

#### Scenario: 缩减已落盘的旧工具结果
- **WHEN** 受保护近期尾部之外的 tool 消息带有 `isTruncated=true` 和有效 `originalPath`
- **THEN** 系统必须把长预览替换为包含工具调用 ID、原始输出路径和已截断事实的短引用
- **THEN** 系统必须保留原消息的 role 与 `tool_call_id`

#### Scenario: 缩减完全重复的旧工具结果
- **WHEN** 受保护近期尾部之外存在内容完全相同的多个 tool 消息
- **THEN** 系统必须保留时间上最新的完整副本
- **THEN** 更早副本可以替换为指向最新 `tool_call_id` 的重复结果标记

#### Scenario: 不可恢复的工具结果保持原样
- **WHEN** 旧 tool 消息没有落盘引用、没有相同的更晚完整副本，或包含工具错误
- **THEN** 系统不得自动删除、清空或改写其内容

#### Scenario: 请求投影剪枝不修改持久历史
- **WHEN** 剪枝后无需生成语义摘要
- **THEN** 剪枝必须只作用于本次模型请求投影
- **THEN** `SessionContext` 与持久化会话中的原始消息必须保持不变

### Requirement: 全量会话检查点压缩
系统 MUST 提供独立于中段历史摘要的全量检查点策略。该策略 MUST 摘要全部非 system 持久历史，并生成供正常 Agent 继续当前对话的状态检查点，不得改变 Agent 身份或生成 handoff 层级。

#### Scenario: 自动规划直接选择全量检查点
- **WHEN** 中段压缩预计无法使请求回到安全阈值
- **THEN** 系统必须将可恢复剪枝后的全部非 system 持久历史交给全量检查点摘要协议
- **THEN** 新历史必须由原连续 system 前缀和一条 `[Conversation Checkpoint]` 消息组成
- **THEN** 独立工具列表必须继续由请求组装器提供，不得写入持久历史

#### Scenario: 检查点保留继续任务所需状态
- **WHEN** 系统生成全量检查点摘要
- **THEN** 摘要必须覆盖当前目标与最新用户请求、用户约束与偏好、已完成工作和验证结果、关键决定、当前状态、阻塞、下一步及相关精确资源
- **THEN** 路径、命令、错误和标识符必须只在继续任务需要时保持精确
- **THEN** 凭据和秘密值必须替换为 `[REDACTED]`
- **THEN** 摘要不得声称 Agent 已转变为领导者、子单元或只负责战略交接

#### Scenario: 手动请求全量压缩
- **WHEN** 用户执行 `/compact full`
- **THEN** 系统必须直接选择全量检查点策略
- **THEN** 系统仍必须执行摘要输入容量检查、结果验证和失败原子性规则

#### Scenario: 全量摘要输入仍无法容纳
- **WHEN** 全量检查点摘要的源材料和输出预留超过当前模型物理上下文窗口
- **THEN** 系统必须保留原始持久历史并返回明确失败
- **THEN** 系统不得静默删除普通 user/assistant 消息，不得把不完整静态文本提交为成功检查点

### Requirement: 有限压缩恢复与上下文溢出分类
系统 MUST 限制自动压缩 restart 和 provider 上下文溢出的恢复次数，并 MUST 将上下文溢出与认证、网络、限流及其他请求错误区分处理。

#### Scenario: 连续预算 restart 被限制
- **WHEN** 一次真实模型调用尚未发生，预算规划已经产生一次压缩 restart
- **WHEN** 重组后的请求仍要求再次压缩
- **THEN** AgentLoop 必须停止再次摘要并返回明确错误
- **THEN** restart 不得无限回退 iteration

#### Scenario: provider 首次报告结构化上下文溢出
- **WHEN** LLM adapter 将 provider 错误规范化为 `LlmContextWindowExceededError`
- **WHEN** 当前请求尚未执行全量压缩且尚未使用溢出恢复
- **THEN** AgentLoop 必须允许规划器强制执行一次全量压缩并重组请求

#### Scenario: 全量恢复后仍然溢出
- **WHEN** 当前请求已经执行过全量压缩、已经使用过一次溢出恢复，或恢复后的请求再次返回上下文溢出
- **THEN** 系统必须停止恢复并返回明确错误
- **THEN** 系统不得再次摘要已有检查点

#### Scenario: 非上下文错误不触发压缩
- **WHEN** provider 返回认证、限流、网络、超时或无法确认类型的其他错误
- **THEN** 系统必须沿用普通模型错误处理
- **THEN** 系统不得因为该错误自动触发上下文压缩

## MODIFIED Requirements

### Requirement: 中段压缩失败原子性
系统 MUST 先完成安全边界计算、摘要生成和候选结果验证，再一次性替换会话历史。任何失败都不得用缺少真实历史事实的静态文本强行截断历史，且未通过完整请求预算验证的候选历史不得提交。

#### Scenario: 摘要调用失败或返回空文本
- **WHEN** 中段或全量摘要模型抛出异常、超时或返回空白结果
- **THEN** 压缩必须返回结构化失败结果
- **THEN** 内存消息历史和已持久化消息历史必须保持压缩前状态

#### Scenario: 不存在安全可压缩中段
- **WHEN** 头部保护区与尾部保护区重叠，无法形成中段，或预算内无法保留至少一个完整近期轮次
- **THEN** 规划器必须把中段策略判定为不可行并在摘要前直接选择全量策略
- **THEN** 系统不得调用中段摘要模型进行试错

#### Scenario: 候选历史膨胀或仍超过目标水位
- **WHEN** 摘要生成的候选历史预计用量不小于剪枝后的请求，或加入固定请求开销和输出预留后仍超过安全阈值
- **THEN** 系统必须拒绝提交候选历史并返回失败原因
- **THEN** 内存和持久化历史必须保持压缩前状态

#### Scenario: 持久化失败时恢复内存历史
- **WHEN** 候选历史已经写入内存，但会话持久化失败
- **THEN** 系统必须恢复压缩前的内存历史
- **THEN** 压缩结果必须标记为失败且不得发出成功 restart

### Requirement: 对抗 Lost-in-the-Middle 的首尾双保中段压缩 (Head & Tail Preserved Compaction)
当统一预算规划器选择中段压缩时，系统 MUST 保护消息历史开头连续的 system prompt 前缀，并仅对该前缀和近期尾部之间的对话历史进行 LLM 语义总结。工具列表 MUST 继续作为独立请求字段保留。近期尾部 MUST 由完整 user 轮次组成，并同时服从最大轮数与 token 硬预算；若无法在预算内保留至少一个完整近期轮次，系统 MUST 将中段策略判定为不可行。

#### Scenario: 规划器选择中段有损压缩
- **WHEN** 剪枝后的完整请求仍超过安全阈值，且中段候选预计能够恢复安全水位
- **THEN** 系统必须只保护消息历史开头连续的 system prompt 前缀
- **THEN** 首个 user 轮次及其 assistant/tool 结算消息应与其他较早历史一起进入中段
- **THEN** 独立模型工具列表必须保持不变
- **THEN** 系统必须只把中段交给历史型摘要模型，并将有效摘要以 `[Summary of Earlier Conversation]` 原位插入
- **THEN** 预算内的受保护尾部必须按原顺序完整拼接在摘要之后

#### Scenario: 按轮数和 token 硬预算选择近期尾部
- **WHEN** 系统从最后一个 user 轮次向前选择受保护尾部
- **THEN** 尾部最多保留 `compactionRetainCount` 个完整 user 轮次，默认最多 4 轮
- **THEN** 加入任意轮次会超过 `compactionRetainTokens` 时，系统必须停止扩展尾部，默认预算为 8000 tokens
- **THEN** 最新完整 user 轮次自身超过预算时不得突破预算被无条件保留，中段策略必须判定为不可行并交由规划器选择全量策略

#### Scenario: 保持工具调用协议完整
- **WHEN** 某个受保护轮次包含 assistant `tool_calls` 与后续 tool result
- **THEN** 系统不得把压缩边界放在该工具调用与结果之间
- **THEN** 中段压缩不得改写预算内近期 tool result
- **THEN** 受保护尾部之外的旧 tool result 仅可按“可恢复的工具结果剪枝”需求生成摘要输入视图

#### Scenario: 手动压缩复用统一规划策略
- **WHEN** 用户执行不带参数的 `/compact`
- **THEN** 系统必须使用与自动水位触发相同的完整预算、剪枝、策略预测和原子失败规则
- **THEN** 系统必须向用户报告实际选择的 middle、full、skipped 或 failed 结果
- **WHEN** 用户执行 `/compact full`
- **THEN** 系统必须按“全量会话检查点压缩”需求执行，不得先调用中段摘要

#### Scenario: 自动压缩在最终请求边界原子提交
- **WHEN** 最终请求预算规划在模型发送前触发压缩
- **THEN** 压缩服务必须先在候选历史上完成摘要与预算验证，不得提前修改宿主会话
- **THEN** 只有候选历史通过验证并成功持久化后，AgentLoop 才能收到一次 `restart` 控制信号
- **THEN** 摘要失败、候选验证失败或持久化失败时不得提交历史或返回成功 restart
