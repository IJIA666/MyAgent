## 改造原因

在当前的 `MyAgent` 系统中，除了基础的文件读写与局部编辑等工具外，缺少针对目录管理、路径删除、批量文件读取、Git 只读查看以及敏感操作审核等高频功能的原生支持。大模型为了实现这些能力，不得不频繁组装终端命令行并在 `executeCommand` 中执行。这引发了以下几个核心痛点：
1. **跨平台兼容失败率高**：Windows 环境下的 Powershell/CMD 与 Linux 环境下的 Bash 在基础命令及其参数（如目录创建 `mkdir` 、路径删除 `rm` / `del` 等）上存在巨大差异，大模型极易拼错或用错命令参数。
2. **命令注入与路径越权高危**：裸命令行的参数极难在系统底层实现百分之百的沙箱路径穿越校验，大模型在遭受恶意注入或幻觉失控时，容易误删工作区沙箱外的系统关键文件。
3. **终端输出解析极其低效**：终端的 stdout 裸输出往往杂乱无章，并且夹带大量的 ANSI 颜色控制字符，大模型必须具备极强的容错性去艰难解析，不仅开发过程极其不稳定，还会带来大量的 Token 资源浪费。

## 变更内容

本变更致力于扩展 `MyAgent` 的原生内置工具链（ Native Tools ），将高频、高危且对跨平台语法敏感的操作原生封装为系统 TS 工具，同时引入双轨替换策略与确权凭证网关：
1. **原生路径与目录管理**：新增原生的目录创建、目录与文件安全删除、文件移动与复制工具，彻底磨平平台命令差异，并在工具底层逻辑中强制进行工作区路径范围越权校验。
2. **高吞吐读取与可靠修补**：新增多文件并行批量读取工具，废除硬性字符截断，采用前置熔断机制以降低交互延迟；原生支持严格的 Unified Diff 补丁修补工具，并引入基于期望上下文签名定位的特征块替换工具。
3. **只读版 Git 查看能力**：原生封装 Git 状态、日志和增量 Diff 的查看，直接将结构化数据传回，不再走裸终端管道。
4. **前置安全审批服务**：复用底座现有的挂起式 `ApprovalService` 审批卡关机制。当大模型试图调用高危或破坏性工具（ 如路径删除 `deletePath` 等 ）时，工具在底层将自动申请审批，挂起执行 Promise 并交由 CLI 拦截，提示用户进行单次或始终放行的决策，确权后继续物理执行，完美保障删除操作的审计安全性。

## 业务能力

### 新增业务能力
- `native-tools-extension`: 扩展 MyAgent 的原生内置工具链，向系统提供安全的文件路径管理、高吞吐批量读取、严格 Diff / 签名特征块替换、只读 Git 状态查看，以及复用 ApprovalService 的安全确权拦截防护能力。

## 影响范围

1. **工具层实现**：新增一系列内置工具类定义于 `src/action/native-tools/` 中，并注册至虚拟服务器 `src/action/virtual-mcp.ts`。
2. **安全确权卡关**：高危工具（ 如 `deletePath` ）内部需对接底座的 `sessionContext.approvalService` 发起挂起式确权申请。
3. **LLM 调用边界**：通过对工具 `description` 的重新设计约束 LLM 在敏感场景下需优先通过纯文本请求人类确权的交互边界。
