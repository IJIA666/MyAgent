## 改造原因

在本地执行 `npm run dev` 启动 Agent 时，系统会因 `.env` 中默认配置的带有窗口尺寸后缀的 `DEEPSEEK_MODEL=deepseek-v4-flash[1m]`，在配置加载器解析为模型 ID 预检索时查找不到对应的本地 Profile，从而抛出 `致命错误：Error: 未知的模型 ID: deepseek-v4-flash[1m]` 阻断启动。

为了保证 Agent 能在普通终端上稳健启动，需要对其配置预加载进行兼容。同时，为了方便开发调试与提供更佳的用户体验，有必要在系统启动成功后的配置控制台 Banner、以及 REPL 键盘输入的交互式提示符中，直观、动态地将大模型所对应的上下文总大小限制展示给用户。

## 变更内容

1. **配置预加载逻辑修正**：在 `src/config/loader.ts` 从环境变量获取模型参数时，主动使用正则 `.replace(/\[\d+[km]\]/i, '')` 自动剔除可能携带的类似 `[1m]` 或 `[128k]` 的窗口限制后缀，还原成纯净的模型 ID 传入配置工厂中去检索本地内置模型特征字典（`BUILTIN_MODELS`）。
2. **启动日志 Banner 优化**：在 `src/index.ts` 打印的系统成功启动配置摘要信息中，追加输出当前所挂载大语言模型解析出的上下文总限制大小（`contextWindow` 的 tokens 数值）。
3. **REPL 交互式提示符优化**：在 `src/brain/session.ts` 的 `getModelName()` 方法中，基于 `llmConfig.contextWindow` 的大小动态换算并拼接 `[1m]` 或 `[128k]` 类型的窗口标识。这使得输入提示符和重绘的历史提示符动态展示为类似 `用户 [deepseek-v4-flash[1m]] >` 的状态。

  - 改变了控制台交互提示符中模型部分的展示内容，使其在后面增加了对应上下文限额的友好标签。不包含任何破坏性的业务逻辑与 API 变更。
