## 新增需求

### 需求: MemoryService 长期记忆后台重建与高保真同步

系统在启动初始化时，如果向量数据库（`vectorDb`）中存储的向量数为 0 且物理长期记忆文件存在，必须 (MUST) 触发后台异步重建。且在主会话写入新记忆时，系统必须 (MUST) 通过 `MemoryService` 触发增量文本切片和分批向量化同步 Upsert 存入向量数据库中。

#### 场景: 启动期异步检测到向量库为空时自动重建
- **WHEN** 实例化会话管理器，探测到当前 `vectorDb.count()` 返回 0 且本地物理 `MEMORY.md` 文件存在时
- **THEN** 系统必须在后台异步读取记忆文件，提取所有以 `- **` 开头的记忆要点，分批（每批上限 10 条以防 DashScope 接口超限）向 EmbeddingPort 请求向量并同步存入向量数据库中，且此过程不得阻塞主会话的交互启动。

#### 场景: 长期记忆物理保存时触发增量同步
- **WHEN** 主会话的 `LongTermMemoryPlugin` 插件检测到需要保存记忆要点并触发物理写时
- **THEN** 系统必须通过 `MemoryService` 互斥队列追加写入记忆文件，并自动对写入内容进行要点文本切片，将其增量向量化存入向量数据库中。

---

### 需求: 后台自省提炼子智能体的隔离性与动态自适应

记忆提炼子智能体在运行长期记忆自省与精简提炼时，必须 (MUST) 在隔离的子 `SessionContext` 与子 `AgentLoop` 中静默自旋，且其底层的 API 请求必须 (MUST) 动态映射主会话实时的大模型连接配置，以支持动态模型切换。

#### 场景: 动态切换模型后自省子智能体自适应运行
- **WHEN** 交互过程中主会话的大模型配置 `llmConfig`（包含模型 ID、接口地址或 API Key）发生动态变更，并在此后触发了记忆提炼任务时
- **THEN** 运行在后台的自省子智能体必须使用该变更后的最新 `llmConfig` 构建 API 交互，确保提炼自省任务能正确执行，绝不发生鉴权过期或使用旧模型的错误。
