## MODIFIED Requirements

### Requirement: 动态对话尾部消息气泡注入

系统必须（MUST）在模型请求装配阶段向最后一条 user 消息动态追加 `<system-reminder>`，注入当前安全模式、工作目录和日期。诊断类回合还必须注入与当前目标相关的对象级证据摘要、未覆盖目标、剩余成本预算、连续低增益原因、允许的下一步以及聚焦回答约束。提醒不得只提供一个会掩盖局部有效证据的全局等级，也不得把无关历史和冗长证据原文重复塞入上下文。

#### Scenario: 正常轮次动态追加

- **WHEN** 模型请求装配器准备发起调用
- **THEN** 系统把最新模式、cwd 和日期追加到临时请求消息，持久化历史不发生改动

#### Scenario: 授权或模式变化立即可见

- **WHEN** 当前会话的安全模式或可消费授权发生变化
- **THEN** 下一次请求必须注入最新状态，不得使用过期快照

#### Scenario: 诊断提醒展示相关证据而非全局覆盖

- **WHEN** 账本同时存在目标 A 的 complete measured 和目标 B 的 error
- **THEN** reminder 必须分别展示两者及覆盖范围，不得只注入 `DiagnosticEvidenceLevel: error`

#### Scenario: 连续低增益时注入明确停机动作

- **WHEN** 诊断守卫判定连续工具调用没有新增目标、指标或完整性
- **THEN** reminder 必须要求模型停止扩散，基于现有证据总结或请求缩小范围，并标明被阻止的原因

#### Scenario: 提醒要求具体回答

- **WHEN** 当前回合进入最终回答阶段
- **THEN** reminder 必须要求模型删除无证据的量化、完成度和处置结论，避免常识复述和泛泛建议，并对未知项给出具体验证条件
