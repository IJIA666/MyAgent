## 修改需求

### 需求: 推理启动时动态注入长期记忆
系统在每次大模型对话推理启动前，如果检测到向量数据库和项目 `.agent/` 目录下存在持久化的长期记忆，必须根据用户当前的 Query 向量进行检索查询，召回最相似的 Top-K 条记忆片段，将其动态追加并整合到大模型当前 System Prompt 的末尾以提供精准的上下文关联。

#### 场景: 大模型推理前进行向量相似度检索并注入记忆
- **WHEN** 大模型即将开始新一轮推理生成（触发 `BeforeModel` 钩子）且存在持久化的记忆数据库
- **THEN** 系统获取用户当前轮次输入的文本内容（截取前最多 2000 字符），生成其 Embedding 向量，并调用向量数据库的检索接口，匹配出相似度分值符合阈值（如相似度分值 >= 0.5）的 Top-K 条（如最多 5 条）记忆片段，将其格式化拼接，追加到当前大模型请求的首个 system 消息的 content 末尾（若不存在则在首部新建 system 消息），完成语义检索记忆召回。

### 需求: 专属写记忆工具的安全路径锁定
供 Forked 子智能体调用的 `writeMemoryFile` 工具， 必须在底层强制限定写入文件的目标路径为 `.agent/MEMORY.md`， 不接受任何外部路径参数传入， 严禁越权修改工作区其它文件。同时系统必须在写入物理文件后，自动对追加的内容发起异步切片并将其存入向量数据库，以保持向量索引与物理文件同步。

#### 场景: 提炼子智能体调用工具安全落盘并同步向量数据库
- **WHEN** 提炼子智能体在 ReAct 循环中发出 `writeMemoryFile` 调用
- **THEN** 工具读取传入的内容，强制且唯一地追加写入至 `.agent/MEMORY.md` 文件中，并且系统自动在后台异步对该新增的记忆内容按行/要点列表进行拆分切片，生成其 Embedding 向量并同步 upsert 追加写入向量数据库中，保持数据状态同步。

#### 场景: 规避 PostRunHook 高昂规范化质检开销
- **WHEN** 提炼子智能体调用 `writeMemoryFile` 追加写入记忆
- **THEN** 该工具必须显式标记其 `securityCategory` 为 `'safe'`（ 或 `'read'` ）， 从而不触发 `AgentLoop` 中针对代码写操作 `'write'` 的 `PostRunHook` 全量编译与 `eslint` 质检拦截， 规避额外的 CPU 损耗与环境缺失风险。
