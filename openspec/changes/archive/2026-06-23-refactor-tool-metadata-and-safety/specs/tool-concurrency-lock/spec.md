## 新增需求

### 需求: 工具并行执行与读写锁冲突规避
系统在执行大模型下发的多个并行函数调用时，必须 (MUST) 支持基于 Promise 的并行异步执行以提升交互吞吐与性能。为了防止并行操作下对同一个文件的并发修改造成数据损坏或竞态冲突，系统在调度引擎层必须 (MUST) 实现基于操作目标物理文件路径粒度的读写锁（Read-Write Lock）控制机制。

#### 场景: 互不相干的多文件 I/O 工具并行加速
- **WHEN** 智能体单次返回了多个针对互不相关物理路径或纯只读的工具调用时
- **THEN** 引擎必须开启并行 Promise 执行调度，提升工具的并发执行效率。

#### 场景: 同一目标路径下的并发竞争串行化
- **WHEN** 多个并行工具调用均指向同一个文件路径（如同时读取与重写同一个文件）时
- **THEN** 引擎必须依靠文件路径级读写锁对该路径的请求进行强制加锁，保证相同文件的操作在锁队列中串行按序执行，杜绝竞态导致的文件损坏。

#### 场景: 并发工具调用的异常隔离与容错（Promise.allSettled）
- **WHEN** 并行调度的多个工具调用中，有其中一个或多个工具抛错失败，但其他工具执行成功时
- **THEN** 引擎必须使用 `Promise.allSettled` 回收结果，仅将失败的错误信息回填给对应的工具结果，确保决不因单点失败熔断或阻断其他正常的并行工具调用。
