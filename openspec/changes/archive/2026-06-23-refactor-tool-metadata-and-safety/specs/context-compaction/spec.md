## 修改需求

### 需求: 核心文件绝对重载 (File Pinning)
在发生上下文硬截断时，系统必须通过原生状态机追踪，硬性提取最近处于活动状态的核心文件内容注入到新上下文，防止大模型遗忘正在修改的文件内容。

#### 场景: 遵循 Token 预算机制的文件硬拼接
- **WHEN** 系统执行指针级硬截断拼接新提示词时
- **THEN** 系统自动捞取状态机中记录的最近操作文件（最多 5 个），受制于总预算 25,000 Token、单体预算 5,000 Token 的硬拦截约束，读取源码包裹在 `<transient_file>` 标签中强行拼接于头部

#### 场景: 基于工具元数据的文件路径追踪收集
- **WHEN** 触发上下文状态机分析工具历史以收集最近读写过的代码文件路径时
- **THEN** 收集服务必须 (MUST) 读取被调工具声明的 `filePathParamKey` 契约元数据（如 `view_file` 声明参数为 `AbsolutePath`，`write_to_file` 声明参数为 `TargetFile`），自适应抓取其参数值作为操作的目标文件物理路径，从而完全消除对 `readFile`、`writeFile` 的名字硬编码强耦合。
