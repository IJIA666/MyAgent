## 改造原因

之前的终端执行方案仅仅在 `child_process.execSync` 外包了一层皮，无法处理异步长时间运行的任务，存在进程假死、内存由于日志暴涨而 OOM、以及在 Windows PowerShell 环境下经常出现中文输出乱码等痛点。此外，之前的方案缺乏安全性考量，模型可能会使用 `&`、`;` 拼接复合命令进行黑盒越权操作。为了构建一个具备真正自理能力的 Agent 框架，我们需要一个专精于 Windows 生态、强制原子化、兼具深度安全拦截与流式防爆的高阶终端引擎。

## 变更内容

1. **底层引擎与流控 (并发闭环)**：废弃 `execSync`，改为基于事件流的 `child_process.spawn`。引入 `timeoutMs` 与 `noOutputTimeoutMs` 双重防假死机制。
2. **智能阻塞降级 (Auto-Backgrounding)**：吸收 Claude 精髓，当同步命令卡住超过一定时间（如 15 秒）后，系统不会粗暴强杀，而是将其自动转移为后台驻留任务 (Background Task)，释放 Agent 继续执行其他操作。
3. **安全隔离与沙箱锁定 (Sandboxing)**：
   - 彻底废弃 `shell: true`，在传入命令前通过硬正则 `/[&|<>^%\r\n]/` 暴力拦截所有复合连接符与重定向，实现绝对原子化（附带免疫了 `sleep && xxx` 挂起攻击）。
   - 强制将命令执行的 `cwd` (工作目录) 校验并锁死在当前工作区根目录下，严禁越权修改宿主系统目录。
4. **权限持久化与工作模式**：
   - 引入工作模式 (如 Safe, Auto, YOLO)。
   - 实现“始终放行 (Always Allow)”机制，将用户信任的命令持久化到配置文件中。
5. **日志防爆 (Disk Spilling)**：对 stdout/stderr 实现截断流处理，超大日志溢写到本地磁盘临时文件。
6. **Windows 原生特化**：
   - 强杀僵尸进程：调用原生 `taskkill /PID <pid> /T /F` 清理 npm 子进程树。
   - 字符集防乱码：对 PowerShell 强制注入 `try { [Console]::OutputEncoding=[System.Text.Encoding]::UTF8 } catch {}`。

## 业务能力

### 新增业务能力
- `terminal-tool`: 提供符合安全沙箱、防止阻塞和进程假死、原生支持 Windows 并发流的高阶终端工具能力。
- `security-modes`: 提供终端工作模式切换与命令“始终放行”的白名单持久化能力。

## 影响范围

- 将彻底替换本项目当前仅用于读写的简易 Terminal 工具相关代码逻辑。
- Agent 在调用终端工具时不再因超长构建日志而陷入假死，也不会再遇到 `&&` 不支持或乱码的语法阻碍。
- 新增的文件处理和流缓存可能会对本地 `%TEMP%` 目录产生临时文件，需要在生命周期内进行清理。
