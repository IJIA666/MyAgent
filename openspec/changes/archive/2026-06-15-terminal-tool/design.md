## 背景

目前的 Agent 终端执行工具仅依赖 `child_process.execSync`，在处理长时间运行的任务、海量日志输出和复杂 Windows 原生环境（如 PowerShell 的 UTF-8 中文乱码和僵尸进程残留）时表现极其脆弱。此外，它并未对模型传入的命令执行强制校验，容易导致模型在无意间构造黑盒越权操作。通过调研 7 款优秀的开源 Agent 项目，我们总结出了一套完善的下一代 Windows 专精的沙箱终端架构蓝图。

## 目标与非目标

**目标:**
- 实现基于 `child_process.spawn` 的异步流式执行引擎。
- 支持双重超时检测（总超时与无输出超时），并引入 **智能阻塞降级 (Auto-Backgrounding)**，长时任务自动转后台防死锁。
- 实现超大日志的流式截断并自动溢写至本地磁盘（Disk Spilling）。
- 强制原子化拦截（底层采用正则表达式主动阻断带有 `&`, `|`, `;` 等复合连接符的拼接命令）。
- 彻底解决 Windows 下的环境水土不服：包含中文字符乱码（采用隐式 UTF8 环境声明）、npm 孤儿进程树（集成 `taskkill` 清理）。
- 引入命令转后台的启动缓冲期（200ms），智能捕获命令初始化的瞬间崩溃报错。
- **权限体验优化**：实现终端拦截的“工作模式”划分，以及用户确认“始终放行”后的命令白名单持久化记录。
- **沙箱隔离 (Sandboxing)**：工作区目录锁定，禁止 `cwd` 越权操作。

**非目标:**
- **跨平台支持**：明确不兼容 Linux、macOS，底层进程操控严格特化针对 Windows 平台及 PowerShell。
- **交互式伪终端 (PTY)**：暂不实现基于交互缓冲区的命令行对话能力，依靠提示词约束模型使用静默运行参数。

## 架构决策

1. **引擎选型：弃用 `execSync`，拥抱 `spawn`**
   - *Why?* `execSync` 无法实现事件回调与流式截断。使用 `spawn` 可精准监听 `data` 事件，实现超长输出防爆。
2. **安全隔离：强制防注入与沙箱锁定**
   - *Why?* 禁用 `shell: true`。在接收命令参数时，底层使用硬编码的正则 `/[&|<>^%\r\n]/` 拦截复合连接符，换取对操作步骤绝对的透明监控（参考自 OpenClaw），这也顺带免疫了 `sleep 10 && check` 这类隐藏攻击。同时，强制校验 `cwd` 必须在当前工作区路径内，防止非授权系统目录读写。
3. **僵尸进程连根拔除：Windows 原生 `taskkill`**
   - *Why?* Node.js 原生的 `child.kill()` 对 Windows 中由 npm 等脚本衍生的深层进程树完全无效。超时强杀时显式调用 `taskkill /PID <pid> /T /F`，保障环境干爽。
4. **日志卸载：Chunk 截取与 Disk Spilling**
   - *Why?* 我们将在内存中仅保留最近和最开头的日志文本，同时开辟一个异步的 FileStream 将全量输出源源不断地写入 `%TEMP%`，事后仅给大模型提供该缓存文件路径。
5. **智能阻塞降级 (Auto-Backgrounding)**
   - *Why?* 借鉴 Claude Code，遇到 `npm install` 这类长时同步任务，如果不切断等待会卡死整个 Agent 的并发池。我们设定超时预算（如 15 秒），达到预算后不强杀进程，而是自动将同步流转交到后台任务表，返回给大模型 `<background-task-id>`。
5. **安全模式与白名单持久化 (Permission Persistence)**
   - *Why?* 强制人机交互安全校验极速降低开发体验。参考 Claude Code，我们将引入 `Work Modes` (工作模式，如 Safe, YOLO)。如果用户在拦截时授权了“始终放行(Always Allow)”，架构会将其持久化写入 `.agent/allowed_commands.json`，后续匹配到的指令直接跳过拦截，实现“一次授权，终身无感”。

## 风险与权衡

- **进程强杀失败风险** -> 若 `taskkill` 异常或无权限执行，底层必须包裹 `catch` 异常并在降级路径中尝试 Node 基础的 `child.kill()` 作为兜底。
- **强制原子化带来的单步效率下降** -> 代理需要多花几次来回交互去分步执行原本可以通过 `&&` 一口气串联的指令。但这换来了用户极佳的可控性和被授权打断能力，这在安全设计中是极高优先级的妥协。
