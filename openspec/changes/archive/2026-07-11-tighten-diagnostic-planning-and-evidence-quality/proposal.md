## 改造原因

最新真实日志显示，上一轮终端与审计边界修复后，剩余问题已经不在 runtime 放行链路，而在诊断规划与回答质量本身：

- 工具失败后，模型仍会回退去尝试更复杂的复合 shell 命令，而不是优先降级到内置只读工具或收窄问题。
- 在缺少真实大小证据时，模型会把目录枚举结果表述成“深度扫描完成”或“基于实际扫描结果”，存在证据等级与结论等级不匹配的问题。
- 扫描过程缺少明确停机条件，容易重复枚举大量目录，造成 token 消耗膨胀和低价值循环。
- 最终建议中会混入高风险、泛化过度的清理项，例如把安装缓存目录直接描述为“可整目录删除且不影响程序”。

这些问题会直接影响产品可信度：用户看到的是“工具基本可用了”，但智能体仍可能因为规划和表述失真，给出低效甚至危险的建议。因此需要补一组新的行为约束，收紧诊断任务中的失败恢复、证据分级、停机条件和高风险建议边界。

## 变更内容

- 为诊断类任务新增规划护栏：当系统查询失败、被拦截或证据不足时，模型必须优先降级到内置只读工具、澄清问题或直接暴露不确定性，不能继续升级为更复杂的 shell 复合命令。
- 为扫描流程新增停机规则：当已拿到足够候选路径或继续枚举不会提升证据等级时，模型必须停止扩展扫描并进入汇总，不得无上限地重复 `listFiles`。
- 为回答新增证据分级约束：目录存在性、目录枚举、真实大小、执行期错误需要分级表达；没有真实大小证据时，不得宣称“深度扫描完成”“大头已确认”或给出高置信度释放空间估算。
- 为清理建议新增安全分层：高风险目录、缓存、安装包与修复介质必须降级为“谨慎项”或禁止项，不能再输出“一刀切可删且无副作用”的绝对化建议。

## 业务能力

### 新增业务能力
- `diagnostic-planning-guardrails`: 约束诊断任务中工具失败后的降级路径、扫描停机条件与循环上限。
- `diagnostic-evidence-quality`: 约束诊断回答中的证据分级、可宣称范围和不确定性表达。
- `cleanup-recommendation-safety`: 约束磁盘清理与类似建议中的高风险目录、绝对化表述和风险分层。

### 修改业务能力
- `simple-agent-core`: 诊断类 tool-call 闭环中的规划收束与最终回答策略需要收紧，不再允许“低证据高结论”的默认行为。
- `system-reminder-injection`: 需要支持向诊断类任务注入更明确的运行时提醒，强制模型遵守证据分级与失败降级规则。

## 影响范围

- 影响诊断类任务的 system reminder / prompt 注入内容，以及 `AgentLoop` 或相邻规划链路对失败恢复与停机条件的控制。
- 影响最终回答生成前的质量校验逻辑，尤其是对“已完成扫描”“实际结果”“可安全删除”等高风险表述的约束。
- 影响相关测试：需要补充工具失败后的降级路径测试、扫描停止条件测试、证据分级测试和危险建议黑名单测试。
- 不改变现有 terminal runtime、审计落盘、Plan 放行策略本身；这些边界已在上一轮 change 中处理，本次只收紧诊断任务的规划与回答质量。
