## MODIFIED Requirements

### Requirement: 动态对话尾部消息气泡注入 (Dynamic Tail User Message Injection)

系统应当（SHALL）在发起 LLM 接口调用前的载荷装配阶段，从当前的 `SessionContext` 内存状态中获取瞬时的安全模式（`workMode`）、当前工作目录（`cwd`）和当前日期（`date`）。
系统必须（MUST）将这些环境参数打包为系统提醒信息，并使用 `<system-reminder>` XML 标签进行包裹。该系统提醒气泡必须（MUST）被动态拼接追加到发送给 LLM 接口的最后一条 `user` 角色的消息内容的尾部。
当当前回合被识别为诊断、排障或磁盘清理建议任务时，系统还必须（MUST）在同一个 `<system-reminder>` 中注入与该回合相关的动态约束，包括失败后的降级规则、当前证据等级边界、扫描停机信号以及高风险清理对象的保守提示。

#### Scenario: 正常轮次消息游走追加

- **WHEN** 载荷组装器准备发起大模型 API 请求时
- **THEN** 系统定位到待发送消息数组的最后一项，在其文字内容的末尾追加包装了当前 `workMode` 与 `cwd` 的 `<system-reminder>` 气泡，且数据库中的 `messageHistory` 物理历史不发生任何改动

#### Scenario: 降级后状态无延迟同步

- **WHEN** 执行敏感文件操作触发了安全模式降级（如切换至 Safe 模式）后，进入下一轮 LLM 交互
- **THEN** 系统在请求载荷装配时自动读取最新的 `Safe` 工作模式状态并拼装在末尾 User 消息尾部，大模型对最新的安全限制产生零延迟感知

#### Scenario: 诊断类回合注入动态约束

- **WHEN** 当前回合被识别为诊断、排障或磁盘清理建议任务，且本轮已有系统查询失败、扫描预算消耗或证据等级限制
- **THEN** 系统必须把这些动态约束一并注入尾部 `<system-reminder>`，使模型在下一次决策时明确知道不能升级复杂命令、不能夸大证据，也不能输出高风险的绝对化清理建议
