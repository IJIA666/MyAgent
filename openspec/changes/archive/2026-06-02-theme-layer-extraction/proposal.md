## 改造原因

当前的终端界面控制中，大量的 `COLOR_*` ANSI 转义序列直接硬编码在 `src/interface/cli.ts` 和业务指令路由 `command.ts` 中。这不仅造成了代码的高度冗余，更致命的是让渲染层的细节（颜色、高亮排版）深度污染了业务控制流。借鉴于业界成熟 Agent 架构（如 Claude-Code 的 `outputStyles` 隔离理念），为了未来能够平滑支撑外部图形化 UI 乃至多端渲染，必须从根本上将这些终端样式抽离，建立严格的接口防腐层。

## 变更内容

- 移除 `src/interface/cli.ts` 与 `src/interface/command.ts` 等业务逻辑层中写死的所有 ANSI 颜色常量与控制符。
- 新增统一的界面样式基建（如 `src/interface/theme.ts`），集中定义交互界面的视觉属性规范与包装函数。
- 梳理现有终端交互中的状态输出（例如：思考态、系统提示态、命令成功态、错误态），并全面切换到 Theme 层提供的渲染工具。

## 业务能力

### 新增业务能力
- `theme-layer`: 统一控制台输出样式基准，提供标准化、语义化（如 error/success/dim）的终端视觉包装接口。

### 修改业务能力
无

## 影响范围

- **受影响模块**：重构范围限制在 `src/interface/` 模块下，重点波及 `cli.ts`（Readline 状态机控制）和 `command.ts`（指令输出）。
- **外部依赖**：不引入额外的第三方终端渲染库，沿用原生 ANSI 转义，仅做模块架构层面的物理隔离。
