## 改造原因

当前 MyAgent 在执行 `readFile` 工具时采用直接追加全量内容的策略 (Append-Only)。对于数千行的代码文件，一旦被多次读取，将会产生大量的冗余正文，不仅造成高昂的 Token 消耗，而且极大地浪费了前沿大模型前缀缓存 (Prompt Caching) 的降本红利。借鉴业界标杆 Claude Code 的最佳实践，我们需要引入基于文件修改时间 (mtime) 的缓存拦截机制，以零历史破坏、零上下文管理成本的方式，根除同一文件多次读取导致的上文膨胀问题。

## 变更内容

- 在底层工具执行逻辑（`readFileTool`）中，引入并维护一个记录物理文件路径、读取范围以及上次获取时的最新修改时间 (mtimeMs) 的内存字典状态 (`readFileState`)。
- 当大模型针对同一文件及相同范围发起二次及以上的读取请求时，通过比对磁盘最新 `mtimeMs`。
- 若文件未发生改变，拦截读取操作，并将原本返回的明文文本替换为轻量级历史指针占位符 (Stub)，引导大模型自行回顾历史上下文中早期的 `tool_result`，避免重传全文带来的 Token 重复计费。

### 新增业务能力
- `read-file-stub-deduplication`: 文件读取结果的内存拦截与去重缓存机制

### 修改业务能力

## 影响范围

- **受影响代码**: 仅影响基础工具注册模块中的文件读取工具定义 (`src/action/tools.ts` 或实际所在的工具模块文件)。
- **兼容性**: 100% 兼容现有的 Function Calling 标准协议及历史消息序列，对原有的全局上下文装配与 Compact 压缩截断机制零干扰。
