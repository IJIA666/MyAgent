## 改造原因

当前 Skill 学习计数可以跨多个成功任务累计，但达到阈值时，后台复盘只收到最后一个触发任务的轨迹。这样会丢失同一会话中此前已经贡献计数的任务，也无法利用后续任务对早期经验的补充、纠正和跨任务共性。Hermes 的做法是在触发时复制主会话当下可见的完整上下文，并让隔离后台 Agent 基于该快照复盘；重复看到此前上下文是预期行为，不需要维护“已复盘消息”游标。

## 变更内容

- 达到 Skill 复盘阈值时，冻结主会话在本次 `RunEnd` 的完整当前对话消息历史，而不是只截取触发任务；父会话 system 消息不进入快照。
- 后台 Review Agent 使用隔离上下文自身的 system，并以原生消息序列回放父会话的 user/assistant/tool 快照，再追加复盘指令；不再把轨迹序列化进单条 JSON 消息，也不再使用固定 80 条/单条 6000 字符的二次裁剪。
- 保留用户任务入口提供的逻辑边界，用它判断运行是否有资格推进学习计数；该边界不再定义后台复盘输入的起点。
- 保留现有等待交互恢复、计数持久化、FIFO 串行、入队不可变快照、权限隔离、三工具上限和非阻塞失败语义。
- 不新增增量游标或“已复盘”标记；后续复盘可以再次看到较早的当前会话上下文。

## 业务能力

### 新增业务能力

无。

### 修改业务能力

- `skill-learning-session-boundaries`: 将后台 Skill 复盘输入从“仅触发任务轨迹”改为“触发时主会话的完整当前上下文快照”，同时保留用户任务边界的触发资格职责。

## 影响范围

- 核心契约：`BackgroundSkillReviewRequest` 的消息输入语义，以及 `AgentRunSummary.learningTrajectoryStartIndex` 的职责说明。
- 主要实现：`SkillLearningPlugin` 的 RunEnd 快照构造，`BackgroundSkillReviewService` 的排队复制、隔离上下文初始化与复盘指令构造。
- 等待恢复：继续使用 `SkillLearningContinuation` 合并计数、已加载 Skill 和工具证据；最终复盘消息从恢复后的主会话当前历史统一取得，避免重复拼接等待前轨迹。
- 测试：插件、后台 Review、SessionManager、等待恢复和真实学习闭环测试需要从“排除早期任务”迁移为“保留完整当前上下文并重复回放旧上下文”的新契约。
- 不改变配置项、Skill 工具协议、写入批准、读取凭证、Skill 写锁、主会话历史持久化或用户通知协议。
