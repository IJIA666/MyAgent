## 新增需求

### 需求: 控制台安全模式实时查询与切换 (Real-time CLI Workmode Switch)
系统应当（SHALL）在控制台指令层支持快捷命令 `/workmode`，用于实时查询与设定安全执行工作模式。当用户输入合法参数时，系统必须（MUST）同步刷新当前的 `SessionContext` 的私有工作模式，并同步修改底层终端工具校验链的全局 `setWorkMode` 运行态。

#### 场景: 无参数状态交互式二级选择向导
- **WHEN** 用户在 CLI 交互中仅执行 `/workmode`，或通过图形快捷菜单联动派发 `/workmode` 时
- **THEN** 命令行控制台应首先打印出当前激活的安全模式，并立即拉起带有（Safe / Auto / YOLO / Plan）选项的可视化二级单选列表，让用户选择后动态热切换。若用户选择取消则不更改。

#### 场景: 传入合法参数切换工作模式
- **WHEN** 用户输入并执行 `/workmode Plan`（或传入 `Safe` / `Auto` / `YOLO`）时
- **THEN** 系统控制台应打印切换成功通知，此时 `SessionContext.getWorkMode()` 应与所传模式实时同步一致，且底层文件工具的全局校验安全模式也应实时切换为目标值。

#### 场景: 传入非法参数拦截报错
- **WHEN** 用户输入并执行 `/workmode invalid_name`（或其它非定义模式名）时
- **THEN** 系统控制台应拦截该非法切换并打印报错信息，列出系统所支持的四类合法模式范围。

---

### 需求: 交互式 Clack 图形菜单集成同步 (Interactive Clack Menu Sync)
系统应当（SHALL）在控制台双击 `/` 唤起的 Clack 可视化图形选择操作菜单中，登记并挂载“工作安全模式切换”相关的菜单入口。

#### 场景: 图形化菜单项选择与派发
- **WHEN** 用户通过图形菜单选择了“切换工作安全模式”子项时
- **THEN** 控制台分发路由器应自动派发执行并提交 `/workmode` 命令，自动向用户反馈当前模式并进入切换流程。

---

### 需求: 帮助提示菜单命令修正与补充 (Help Menu Update & Corrections)
系统必须（MUST）在 `/help` 指令控制台输出的行清单中增加 `/workmode` 命令的格式规范声明；同时，系统必须（MUST）纠正原提示中对 `/model` 传参的误导描述，使其能准确反映实际的可选参数特性。

#### 场景: 帮助菜单格式完整输出
- **WHEN** 用户在控制台中键入并执行 `/help` 命令时
- **THEN** 控制台打印的可用指令列表中应含有 `/workmode [mode]` 行，且原有的 `/model <id>` 描述被修正为 `/model [id]`（并加注说明空参会引导图形交互向导），以此实现参数一致性。
