## 背景

智能体虽然已支持基于 `Plan` 工作模式的尾部气泡注入与敏感工具物理裁剪，但用户目前无法在 CLI 交互过程中对这些安全模式状态进行热切换或即时查询。我们需要在命令解析层追加 `/workmode` 相关的斜杠指令与交互映射，以在不重启进程的前提下自由升降级系统的安全屏障。

## 目标与非目标

**目标:**
- 实现并注册 `WorkModeCommand` 指令，支持通过 CLI 输入查看和动态切换工作安全模式。
- 同步在 `/` 唤起的 Clack 可视化图形选择菜单中，挂载 `/workmode` 快捷切换项。
- 修正 `/help` 硬编码列表，补充新指令，并将 `/model <id>` 描述更正为可选参数的 `/model [id]`。

**非目标:**
- 坚决不对 CLI 指令反射底座进行重构，依然沿用目前项目中经典的 `ICommand` 和 `CommandRegistry` 静态注册链路，规避对已有测试集造成干扰。

## 架构决策

- **级联修补方案**：
  - 理由：由于当前 CLI 层（无论是 `/help` 输出、Clack 弹窗菜单还是 `CommandRegistry` 注册表）均采用了强类型的静态硬编码方式来保证极致的低开销，选用级联修补的方案，能让新增的模式指令与项目整体的编写风格保持 100% 连贯，降低维护和学习心智。
- **双向状态同步设计**：
  - 理由：智能体架构中存在双重状态读取机制。大模型侧的消息装配和工具裁剪依赖会话私有的 `SessionContext.getWorkMode()`，而本地文件工具和终端命令工具（如 YOLO 执行白名单过滤）在部分无 context 入参的静态调用中会读取 `terminal-config.ts` 中的全局 `getWorkMode()`。命令在修改模式时，必须**同时调用这两个修改器进行同步热写入**，确保状态绝对一致。
- **无参数调用时的交互式二级 Clack 向导设计**：
  - 理由：为了与项目内 `/model` 命令的行为保持体验一致，避免用户在通过图形菜单双击 `/` 选择后还需要重新使用键盘手动敲击参数，我们将 `/workmode` 设为双态：当命令行显式传参时，采用直接静默切换；当无参调用时，会自动在终端拉起 Clack 可视化二级单选列表（`p.select`），直接用方向键即可回车选中或确认取消，保证极佳的交互统一性。

## 风险与权衡

- **[状态切换 busy 忙锁冲突]** -> `SessionContext.setWorkMode()` 限制在智能体运行中（`isProcessing = true`）时写入会抛出并发 busy 异常。
  - *缓解策略*：控制台的斜杠指令只能在智能体结束推理、交还控制权并等待 Stdin 输入的空闲期（`isProcessing = false`）触发，因而在时间线上自然隔离，完全不会触发冲突。
- **[工作模式变动引起缓存瞬时失效]** -> 模式变动改变了消息气泡注入的 `SecurityMode` 参数，如果开启了物理裁剪，还可能会改变 `tools` 定义字段，造成大模型在下一轮的缓存失效。
  - *缓解策略*：在 `.env.example` 中补充对 `ENABLE_PLAN_TOOL_STRIPPING` 开关与缓存击穿博弈代价的注释说明，将性能与安全的权衡权力移交用户。
