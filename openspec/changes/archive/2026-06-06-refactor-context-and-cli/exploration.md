# 探索主题: 终端交互式 Slash Command 与临时技能入栈

## 1. 问题定义
用户希望废弃硬编码的 `pin/disable` 机制，转而采用临时“单次请求级”的技能挂载方式。同时，为了提升终端用户的体验，希望像主流桌面端应用一样，在终端输入 `/` 时立刻展示可用的相关指令菜单（交互式下拉菜单），而不是靠枯燥的纯记忆去手敲长命令。

## 2. 关键发现与调研结果
- **代码库现状**：目前 MyAgent 在 `src/interface/cli.ts` 中使用的是 Node.js 最原生的 `readline` 模块来接收输入。`readline` 天然是基于“行（Line）”进行整块处理的。虽然它提供了 `completer` 支持 Tab 补全，但无法在用户敲击 `/` 的瞬间自动弹出高亮的悬浮下拉菜单。
- **核实与洞察**：通过联网核实 `@clack/prompts`（项目中已安装的 UI 库）与 `readline` 的共存机制，发现两者的 TTY 模式存在竞争冲突。`@clack/prompts` 接管标准输入时必须先暂停或关闭原有的 `readline`。如果在用户盲敲（keypress）途中强行打断 `readline` 启动 Clack，极易导致终端光标错乱或字符残留。

## 3. 方案对比与推荐方向
| 评估维度 | 方案 A: 孤立回车触发 (Enter-to-Trigger) | 方案 B: 击键拦截触发 (Keystroke Intercept) | 结论 |
| :--- | :--- | :--- | :--- |
| **触发方式** | 输入 `/` 并按**回车** | 键盘刚敲击 `/`，尚未回车 | A 更稳妥 |
| **实现难度** | 极低（复用现有解析链路） | 极高（需接管原始 stdin 事件并处理光标） | A 占优 |
| **UX 体验** | 稍逊（多按一次回车） | 现代感强（即时弹出） | B 占优 |
| **稳定性** | 100% 稳定（没有 TTY 冲突） | 容易出现乱码、无法退回纯文本模式 | A 占优 |

**推荐路径**：采用 **“增强型方案 A（孤立回车触发 + 快捷参数）”**。
即保留 `readline` 处理纯文本的稳定性。如果用户只敲一个 `/` 并回车，我们关闭 `readline`，弹出一个炫酷的 `@clack/prompts` 全屏下拉菜单让用户用上下键选择。同时，我们也支持高阶用户直接敲入 `/skill git 帮我提交` 实现秒切，兼顾新手引导与极客效率。

## 4. 约束、风险与未知项
- **多行文本难题**：终端里最难处理的是多行代码输入。如果全面改用现代 UI 库替代 `readline`，大段粘贴代码时容易出现严重的格式崩溃，这也是我们坚持保留底层 `readline` 的原因。
- **动态入栈生命周期**：在实现“临时技能入栈”时，必须确保大模型抛出异常或中途被中止（Abort）时，临时技能的状态标志能被安全清理，否则会导致下一次对话被意外污染。

## 5. 否决方案
- **全面替换 Readline 为全量交互式表单引擎 (如 Inquirer/Enquirer 全家桶)**：这种做法虽然能实现即时弹窗，但会让普通的纯文本聊天变得极其重度，且严重破坏跨平台终端（尤其是 Windows PowerShell）在粘贴大段文本时的性能和排版，被否决。
