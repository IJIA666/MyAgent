## 背景

当前 MyAgent 通过在 System Prompt 中硬编码拼接 `pinnedSkills` 和 `disabledSkills` 来实现上下文挂载。这种方式破坏了大模型提示词基线缓存，并容易引发“注意力稀释”。另外，终端交互仅依赖 `readline` 默认行为，使用斜杠命令的心智负担重，缺乏现代桌面化应用的交互直觉。

## 目标与非目标

**目标:**
- 实现上下文动静分离，保障全局规则的基线缓存 100% 命中。
- 通过“历史流动态入栈”技术实现针对特定任务的高强度单点聚焦（Context Pinning）。
- 利用 `@clack/prompts` 提供原生的互动下拉菜单，提升 `/` 命令体验。

**非目标:**
- 绝不完全抛弃 `readline`，不使用全盘表单引擎替代长文本聊天流（避免粘贴多行文本崩溃）。
- 不针对特定大模型厂商的 API（如 Anthropic 的 `<cache_control>` 数组格式）进行特化硬编码适配，坚决维持通用 LLM 协议层交互。

## 架构决策

- **决策 1: 放弃死锁前缀，采用尾端入栈机制 (History Stream Push-Pop)**
  - *Why*: 在 `context.ts` 中不修改头部能保住缓存，而在用户提问（User Message）前将特定的 `SKILL.md` 作为独立的 System Message 压入末尾，不仅能极高强度地引导模型完成当前任务，且执行完毕后能立即被代码弹栈（出栈），彻底防止环境污染。
- **决策 2: 孤立回车触发全屏交互菜单**
  - *Why*: 在原生的 `readline` 处理输入时中途拦截击键会导致极难排查的 TTY 乱码。我们妥协为“用户输入独立 `/` 并回车时才唤起 `@clack` 下拉交互”，这既满足了可视化的菜单选择，又保证了底层输入引擎的极度稳定。

## 风险与权衡

- **[风险点: 管中窥豹 / Tunnel Vision]** -> 缓解策略：全局静态头部层（`messageHistory[0]`）必须永久保留一份精简的技能“目录大纲”，确保大模型虽然不去读无关技能的细节，但始终拥有所有能力的感知视野。
- **[风险点: 终端状态冲突]** -> 缓解策略：在唤起 `@clack/prompts` 菜单期间确保先执行 `rl.close()` 释放标准流，等表单交互流程彻底结束后再调用 `initRl()` 重新接管终端。
