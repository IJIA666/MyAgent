## 改造原因

智能体的动作执行与工具沙箱子系统是整个系统运行的安全屏障。当前版本的实现中，路径沙箱保护机制存在严重的路径越界安全漏洞，外部 Model Context Protocol (MCP) 子进程管理没有实现幂等关闭且存在内存泄漏的风险，多服务挂载时也未考虑工具命名冲突可能引起的路由混乱。为了提升系统的整体安全性与运行稳定性，亟需对该子系统进行核心底座架构的加固与质量重构。

## 变更内容

本次变更将对动作执行与工具沙箱子系统的底层实现细节进行系统化调整，主要包含以下几项改动：
1. **沙箱路径校验加固**：重构 `secureResolvePath` 中的路径前缀匹配逻辑，引入系统路径分隔符（`path.sep`）与完全相等匹配，彻底杜绝同前缀的目录穿透绕过漏洞。
2. **MCP 进程回收与清理重构**：为 `McpToolManager` 建立完善的生命周期管理，依次调用 `transport.close()` 和 `client.close()` 以保障子进程的优雅回收；实现全局进程信号监听的回调解绑，消除重复实例化造成的内存泄漏风险。
3. **工具冲突防御校验**：在聚合加载外部 MCP 服务的工具元数据时，增加工具重名判定，当检测到不同 Server 存在相同命名的工具时采取阻断抛错，防止大模型调用发生路由混乱。

## 业务能力

### 新增业务能力
*无*

### 修改业务能力
- `simple-agent-core`: 沙箱绝对路径安全校验规范性防穿透加固。
- `mcp-switch`: 增加外部 MCP 子进程的回收释放、解绑信号与工具命名防重名冲突校验规范。

## 影响范围

- **受影响代码模块**：
  - `src/action/tools.ts`（文件读写沙箱校验逻辑）
  - `src/action/mcp-client.ts`（MCP 客户端生命周期与子进程管理）
  - `src/action/toolRegistry.ts`（本地与外部工具统一聚合注册器）
- **外部依赖与系统行为**：
  - 外部 stdio MCP 服务的启停与销毁行为，信号监听的注册与注销生命周期。
