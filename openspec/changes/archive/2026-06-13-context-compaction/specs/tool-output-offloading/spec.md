## 新增需求

### 需求: 大文本工具输出拦截与落盘

当单个工具输出的内容长度超过限额时，系统必须在 Harness 调度层进行物理拦截，自动将内容写入本地的临时存储文件中，防止上下文瞬间爆满。

#### 场景: 工具输出超限拦截落盘
- **WHEN** 任意工具执行返回的字符串长度大于或等于 8000 字符时
- **THEN** 系统必须将该全量输出持久化保存到项目本地的 `.myagent/temp/tool_out_<uuid>.txt` 文件中，禁止直接将其写入会话的 messages 历史中

### 需求: 占位文本引导

对于被拦截的大文本工具输出，系统必须在 messages 历史的 tool 消息体中替换为带路径指引与引导的占位提示词，使用结构化标签包裹。

#### 场景: 生成占位文本
- **WHEN** 超限工具输出成功落盘到磁盘后
- **THEN** 系统必须向上下文写入一条包含该文件物理路径、首尾预览摘要（各 1000 字符）、以及专门调阅工具引导信息的占位提示，告诉模型“如需阅读完整内容，请使用 read_temp_file_by_lines 并指定行号”

### 需求: 智能分页调阅工具

系统必须向大模型提供一个专门的分页读取工具 `read_temp_file_by_lines`，支持大模型在看到占位引导后按需获取内容，避免将文件全量拉回上下文。

#### 场景: 分页读取特定行区间
- **WHEN** 大模型识别到占位信息并主动调用 `read_temp_file_by_lines` 且参数 `targetPath` 在沙箱区、`lineStart` 与 `lineEnd` 均合法时
- **THEN** 系统必须对文件路径进行沙箱验证，并只读取并返回该文件中对应行区间的纯文本，拒绝返回全量数据
