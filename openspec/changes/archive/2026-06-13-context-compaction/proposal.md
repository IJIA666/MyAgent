## 改造原因

随着 ReAct 多轮会话的迭代以及大文本工具（如长文件查看、大目录分析）的调用，Agent 的工作上下文 Token 会呈现爆发式增长。这会导致大模型 API 响应延迟急剧增大、Token 计费成本直线上升，甚至直接突破模型本身的上下文窗口限制。

为了保证系统的经济性与高响应度，并提升在极长会话下的稳定性，急需设计一套在 Harness+Skill 架构下运作的上下文压缩与大文本工具输出拦截离线机制，同时保障前缀缓存（Prompt Caching）命中率以及防止重要代码记忆丢失。

## 变更内容

本变更是针对会话生命周期与大文本处理的一次系统级优化，包括以下改动：
1. **触发机制**：新增基于激活模型最大窗口百分比（如 75%）自适应触发的静默压缩，以及终端 REPL 交互菜单中的手动一键压缩。
2. **时序压缩逻辑**：放弃修改历史首个 System 消息的传统方案，改由后台调用轻量大模型（LLM）将较早历史自动提炼为开发共识与技术轨迹摘要，作为 `role: "user"` 的 `<conversation-checkpoint>` 消息块插入新会话头部，并实现物理 Session 轮转以保障后续轮次的前缀缓存 100% 稳定命中。
3. **自动记忆重建**：压缩触发后，自动扫描被剔除历史中最近读取过的核心代码文件，将其内容作为轻量级附件（受 Tokens 额度限制）重新挂载至新会话。
4. **大文件拦截**：拦截超出 8000 字符的工具输出并离线落盘至本地 `.myagent/temp/` 临时文件夹，在上下文中替换为带前缀摘要与路径指引的占位引导。
5. **智能分页调阅**：新增 `read_temp_file_by_lines` 专用物理工具，支持大模型在查看占位引导后，按需分页调阅临时文件特定行，防止全量拉回导致的死循环。
6. **配置化模型覆写**：在 `ModelProfile` 与 `LlmConfig` 中引入 `contextWindow` 物理窗口配置以及 `temperature`、`timeout`、`maxRetries`、`headers` 等大模型调用与网络控制选项；重构 `getModelConfig` 工厂以读取通用环境变量（如 `DEEPSEEK_MODEL`、`DEEPSEEK_CONTEXT_WINDOW`、`DEEPSEEK_TEMPERATURE`、`DEEPSEEK_TIMEOUT` 等）覆写整个大模型配置，实现对模型名中特定后缀（如 `[1m]`、`[128k]`）的自动剥除以防止第三方 API 校验失败，支持对配置值中 `1m`/`128k` 缩写文本的解析，并实现覆写模型名称但未指定窗口时自动退化为保守值（32k）的主动防御，实现 Claude Code 式的第三方 API 代理。

## 业务能力

### 新增业务能力
- `context-compaction`: 监控会话 Token 并通过时序 Checkpoint 追加与物理会话轮转实现无偏航的上下文压缩。
- `tool-output-offloading`: 拦截大文本工具输出并落盘为临时文件，通过智能占位与分页工具防止上下文爆满和死循环。

## 影响范围

*   **核心会话与驱动层**：`SessionManager`（调度循环、锁控制、物理轮换）与 `SessionContext`（Token 估算、消息管理与持久化）。
*   **上下文适配器**：`DefaultContextAdapter`（组装逻辑需兼容压缩后的 Checkpoint 与临时文件附件）。
*   **工具体系**：`tools.ts`（文件读写和检索工具），以及新增的 `read_temp_file_by_lines` 工具定义。
