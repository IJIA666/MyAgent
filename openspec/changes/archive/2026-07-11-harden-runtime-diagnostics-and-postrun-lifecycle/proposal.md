## 改造原因

最新 `.myagent` 会话日志暴露出一条跨越诊断工具、工具执行、运行后质量检查、规则热重载与日志追踪的连续失效链：Plan 模式下通用只读工具无法提供足够的目录级测量证据，模型因此退回 `execute_command`；原子只读命令虽然通过安全策略执行，却仍因工具静态 `securityCategory='write'` 被记为写操作，误触发全量 PostRunHook；模型生成结束后，用户继续等待约 46 秒，并看到 `PostRunHook`、`RuleManager` 等内部实现名称；与此同时，技能 watcher 只要收到任意文件系统事件就宣称“技能文件变动”，但没有内容差异证据，也没有完整的 watcher 释放生命周期。最终回答仍可能用局部或截断测量结果支撑超出覆盖范围的诊断结论。

当前问题不能仅靠隐藏日志、修改文案或增加一个文件元数据字段解决。系统需要在同一个 change 中贯通“实际副作用判定—质量检查触发—受限测量—证据作用域—热重载正确性—结构化可观测性”整条链路，使安全上的保守分类不再污染运行语义，使诊断结论能够严格对应真实测量对象，也使用户只感知产品状态而不感知内部类名和原始执行细节。

## 变更内容

1. 在工具静态安全类别之外建立本次调用的实际 effect 结果，明确区分“工具理论上可能写入”与“本次调用实际发生写入”；审批、默认拒绝与保守并发控制继续使用静态风险信息，PostRunHook、变更追踪与质量检查只消费已执行调用的实际 effect。
2. 收敛 PostRunHook 为面向用户的质量门禁：只有真实代码写入才触发检查；前台只展示抽象、稳定的校验状态与结论，内部名称、命令和详细输出进入结构化日志与 trace；失败仍可反馈模型修复，但必须防止无变更重跑和无限自修复循环。
3. 修正规则与技能热重载：文件系统事件只作为候选信号，必须经过目标过滤与内容差异确认后才能更新缓存和系统提示词；保存并释放 watcher，避免会话和子智能体生命周期结束后遗留监听器；消除重复扫描和误导性 INFO 日志。
4. 完善通用只读诊断能力，使目录测量能够在一次受限调用中比较直接子目录的聚合占用，并对权限拒绝、符号链接或联接点、跨卷边界、截断、跳过项和时间预算给出结构化结果，而不是遇到单项错误就终止整个扫描。
5. 将诊断证据从回合级单一枚举值调整为与目标路径、指标、来源、覆盖范围及完整性绑定的证据记录。局部、截断或跳过错误的测量只能支持对应对象的下界或部分结论，不能把整个诊断任务提升为完整 `measured`。
6. 收紧诊断失败后的降级行为和工具可发现性：提示词必须使用实际注册的工具名称；文件树信息优先走内建只读工具，系统级信息只允许原子只读命令补位；失败后不得升级成复合 shell，也不得在证据不足时输出高置信度空间估算。
7. 为质量检查、实际 effect 判定、目录测量和技能热重载补齐结构化日志与 trace 事件，记录触发原因、关联调用、耗时、覆盖范围、截断与结果，同时遵守 metadata-only、replay 和脱敏边界。

## 业务能力

### 新增业务能力

- `runtime-effect-accounting`: 记录单次工具调用经策略判定并实际执行后的副作用、变更资源与完成状态，为质量检查和运行时行为提供真实依据。
- `postrun-quality-gate`: 定义真实代码变更后的质量门禁触发、前台呈现、失败反馈、重试上限和可观测性契约。

### 修改业务能力

- `tool-security-category`: 明确静态安全类别只表示潜在风险和保守安全策略，不得直接等同于本次调用的实际副作用。
- `native-tools-extension`: 扩展通用只读文件工具的受限目录比较测量、错误容忍、链接边界、时间预算和结构化完整性信息。
- `diagnostic-evidence-quality`: 将证据升级为按对象、指标、来源和覆盖范围记录，约束截断值、下界值与局部测量的结论范围。
- `diagnostic-planning-guardrails`: 让诊断预算按扫描成本与新增证据治理，并保证失败后使用真实存在的内建工具收敛，而不是继续升级 shell。
- `rules-injection-caching`: 将规则与技能文件事件改为差异确认后的缓存更新，并补齐 watcher 的实例级关闭与子智能体释放语义。
- `logging-observability-and-naming`: 增加质量门禁、实际 effect、目录测量和热重载的结构化状态日志，禁止默认前台泄漏内部实现名称。
- `trace-logging`: 在现有 capture mode 与脱敏约束下记录运行后质量检查及相关诊断阶段的可关联 metadata span。
- `agent-event-lifecycle`: 规范质量门禁发生在 `complete` 前的事件状态与 UI 呈现，保持 `complete` 仍是唯一终结点。

## 影响范围

- 工具元数据与执行结果契约：`NativeTool`、`ToolRegistry`、`ToolExecutor`、`ToolCallOrchestrator` 及工具调用结果传递。
- 命令工具与 Plan 安全判定：原子只读命令的实际 effect、审批效果、锁与快照触发语义。
- Agent 主循环与质量检查适配器：写操作累积、PostRunHook 调度、失败反馈、重试和前台事件。
- 文件系统只读工具与诊断护栏：`readFile`、`listFiles`、目录聚合测量、证据记录、预算与停机条件。
- 规则/技能缓存：`RuleManager`、`MemoryService` 子智能体、会话关闭和系统提示词更新。
- CLI/TUI：质量检查状态渲染、详细信息折叠或调试通道，以及 `complete` 前后的输入生命周期。
- `.myagent` 日志与 trace：新增可关联事件字段、耗时和结果摘要，不改变默认 metadata-only 的隐私边界。
- 单元、契约和集成测试：覆盖只读命令不触发质量检查、真实写入触发、目录部分测量、证据不外推、watcher 释放及日志/trace 关联。
