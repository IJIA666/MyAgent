## 改造原因

当前文件写入工具（基于行号或全量写入）给大模型带来了极高的认知负担，且行号极易发生漂移，常常导致“算错行号、代码插错位置毁坏文件”的痛点。
经过对 Claude Code、Opencode、Hermes 三大顶级开源/官方 Agent 项目的深入探索，发现业界在单点局部修改上达成了绝对一致的共识：抛弃行号，全面采用基于纯特征文本段（`old_string`）和新文本段（`new_string`）的字符串精确匹配替换。本次改造旨在落地这套业界成熟规范，彻底解决大模型改代码错乱的问题。

## 变更内容

- 剥离原写入工具的职责：明确原有的全量写入工具仅用于“创建新文件或全文件完全重写”场景。
- 引入新的增量编辑机制：设计并实现基于 `old_string` 和 `new_string` 的局部特征文本修改能力，并内置诸如“多处匹配主动拦截”、“找不到匹配时给予引导提示”等防呆逻辑。

## 业务能力

### 新增业务能力
- `file-edit`: 基于纯特征文本匹配的文件局部增量修改能力及防呆拦截系统。

### 修改业务能力
- 无。

## 影响范围

- **工具层**：将直接修改或新增 `src/action/native-tools/file-system.ts` 以及相关的工具注册文件。
- **系统提示词**：影响工具的系统描述（Schema Description），需要引导模型优先使用 `file-edit`，而将全量覆盖作为备用。
