# 提案: 重构并解耦 Native Tools (refactor-action-tools)

## 1. 背景与痛点 (Motivation)
当前，所有与操作系统和文件系统交互的原生动作层工具均被硬编码堆砌在 `src/action/tools.ts` 这一个长达 500 行的“上帝文件”中。这不仅包含了大量的具体业务逻辑（如沙箱安全检查、文件去重快照读取等），还强行混入了工具的 Schema 定义代码。这种“一锅端”的设计导致代码极难测试，同时也阻碍了未来扩展新工具（如 PTY 终端交互工具、AST 语法树导航工具等）。

## 2. 核心目标 (Goals)
- **单一职责原则 (SRP)**：将不同功能域的底层操作拆分到各自的专用模块中。
- **扩展性增强**：建立 `src/action/native-tools/` 目录规范，确保未来新增工具只需添加独立文件并注册即可，不干预旧代码。

## 3. 非目标 (Non-Goals)
- 本阶段不对工具库增加任何全新的功能或业务行为。
- 本阶段不涉及 `SessionManager` 或大模型核心对话执行流的重构（属于 Phase 2）。
