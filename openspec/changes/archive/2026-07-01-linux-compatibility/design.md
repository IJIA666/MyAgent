## 背景

目前 `MyAgent` 代码底座在设计时已具备跨平台逻辑的分支，但在开发过程中所有的单元测试与验证皆在 Windows 本地完成。为了支持将 Agent 部署在生产级受限的 Linux 容器内（防逃逸执行），并能够无缝对接主流的 POSIX MCP 服务生态，必须消灭由于平台反馈盲区导致的路径分隔符硬编码等经典跨平台陷阱，并建立起长效自动化 Linux 校验机制。

## 目标与非目标

**目标:**
1. **测试用例 100% 绿灯**：WSL 或 Linux 容器本地环境运行全部 Vitest 测试（包括单元测试与集成测试），消除全部平台兼容报错。
2. **路径分隔符解耦**：彻底消除 native tools 代码及测试代码中硬编码的反斜杠 `\\` 或硬抹平的 `replace` 逻辑，全部采用平台自适应的标准 `path` API。
3. **CI/CD 流水线守护**：新增根目录下的 `.github/workflows/ci.yml` 自动化配置文件，实现在 GitHub Actions 云端 ubuntu-latest 容器上自动编译并测试通过。

**非目标:**
1. **不废弃 Windows 兼容**：不改变目前 Windows 本地开发的便利性，保留 Windows 平台专属的乱码防护及进程树强杀等逻辑。
2. **不开发 OS 级依赖安装包**：不为 Linux 无头浏览器所缺失的图形支持库开发独立的 OS 包管理器安装脚本（仅在 GitHub 自动化流程或容器镜像层面声明与装载）。

## 架构决策

我们采纳 **双平台并行适配（Windows 本地开发 + Linux 容器运行与 CI 守护）** 的架构方案。

### 决策理由
- **高开发包容性**：不改变现有开发者所熟悉的 Windows 工作流，避免强迫开发者切换物理系统带来的开发摩擦。
- **极低改动成本**：底座跨平台逻辑分支大部分已就绪，主要改动在于抹平路径硬编码这一细节，开发成本低，但收益（容器化运行能力）巨大。
- **长效测试防护**：利用云端 GitHub Actions 流水线自动化对 ubuntu 平台进行单元测试运行，既避免了 Windows 本地开发的平台认知开销，又以零本地成本消除了平台回归缺陷。

## 风险与权衡

- **风险 1：路径分隔符硬编码导致 Linux 静默失败**
  - **描述**：由于在 Windows 宿主机开发，开发者易无意识编写硬编码的反斜杠 `\\`。在 Windows 的系统宽容度下，这些操作往往能正常运行，但在 Linux 下路径查找会静默出错，是 Linux CI 运行中最高频的回归缺陷。
  - **缓解策略**：在 Apply 编码阶段，对所有本地工具实现（`src/adapters/`）及测试套件（`test/`）进行文件内容的正则扫描，将任何硬编码 `\\` 或平台脆弱的 replace 清理重构为 `path.join`/`path.resolve`/`path.sep`/`path.normalize`。
- **风险 2：无头浏览器运行缺失图形库依赖 (Playwright)**
  - **描述**：Linux CI 容器在 Headless 模式运行包含浏览器爬网的测试时，由于系统缺少 `libgbm.so`、`libasound.so` 等底层动态库，会导致 Playwright 实例直接启动崩溃。
  - **缓解策略**：在 `.github/workflows/ci.yml` 脚本中，使用 `npx playwright install-deps` 命令在流水线中自动化一键安装无头 Chromium 所需的全部动态链接依赖库，无需开发者人工干扰。
