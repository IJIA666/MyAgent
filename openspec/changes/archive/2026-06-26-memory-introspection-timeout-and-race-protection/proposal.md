## 改造原因

在项目长期记忆模块的后台自省机制中，子智能体在会话结束时负责异步运行并提取记忆。但在当前的底层通信与控制设计中，存在以下两个严重的稳定性隐患：

- **后台自省无超时控制与强杀机制**：自省子智能体在独立的微任务循环中执行多轮交互，但其异步迭代生成过程缺少超时保护与外部取消控制。一旦遭遇大模型 API 服务响应卡死，该后台自省流程将无限期挂起并持续占用 TCP 连接，随着时间推移会累积引发严重的系统句柄与套接字泄露。

- **驱动实例单例竞态与取消漏拦截**：派生的后台自省流程与前台主交互流程共享同一个 `LlmPort`（即 `OpenAiLlmAdapter` 单例）。由于适配器内部当前使用全局的 `this.abortController` 单例，每次流式请求都会强行覆写该实例。一旦主流程与自省流程并发请求，全局控制权会被竞态抢占，导致跨会话的误杀和错误的取消。同时，该全局设计未针对非流式的 `chat` 调用实现取消拦截，导致在途的 `chat` 请求无法被物理掐断。

为了彻底解决以上问题，需要升级底层的 LLM 适配器接口与超时取消机制，通过支持局部 `AbortSignal` 级联控制与单次调用超时，消除竞态并防范句柄泄露。

## 变更内容

我们将进行以下核心重构以修复这些缺陷：

- **升级 `LlmPort` 接口定义**：在驱动端口 `LlmPort` 的 `chat` 与 `streamChat` 方法签名中，新增可选的 options 参数以支持上层传入局部的 `AbortSignal` 控制器，从而建立链路级的级联式取消通道。

- **重构 `OpenAiLlmAdapter` 适配器**：废除全局单例控制器，改用 Set 集合维护当前处于活跃状态的在途请求局部控制器。每次调用生成方法时，在内部动态创建局部的 `AbortController` 并存入集合。如果上层传入了外部 signal，则利用 `AbortSignal.any([localAC.signal, options.signal])` 将其与内部局部控制器进行组合，从而在底层网络请求中实现物理断开。

- **多实例无竞态广播**：调用 `OpenAiLlmAdapter` 的全局 `abort` 时，将广播并触发 Set 中所有活跃的局部控制器取消信号，既能兼容现有的全局中断逻辑，又排除了并发调用时的覆写竞态。

- **自省单次调用超时控制**：在自省迭代的底层调用发起时，注入单次请求超时参数 `AbortSignal.timeout(perCallMs)`，从而在兼顾多轮 ReAct 健壮性的前提下，实现网络故障时的强杀与句柄释放。

## 业务能力

### 新增业务能力

- 无

### 修改业务能力

- `llm-adapter`: 修改既有 LLM 适配器契约，支持局部 `AbortSignal` 的传递、流式/非流式请求的级联取消，以及在途请求的物理断开。

## 影响范围

- **驱动端口层**：`LlmPort.ts` 的 `chat` 和 `streamChat` 方法签名。

- **驱动适配器层**：`OpenAiLlmAdapter.ts` 适配器的生命周期、取消管理与网络通信逻辑。

- **核心循环层**：`AgentLoop.ts` 及其内部对 LLM生成方法的调用链。

- **业务逻辑层**：`MemoryService.ts` 中自省子智能体的多轮 ReAct 迭代生成逻辑。
