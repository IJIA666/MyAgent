# 探索主题: 终端模型交互体验升级 (Model UX Enhancements)

## 1. 问题定义
当前动态切换模型功能虽然打通了底层链路，但暴露出了严重的用户体验短板：
1. **状态盲区**：用户在提示符处无法直观看到当前处于哪个模型，容易引发上下文错乱。
2. **缺乏持久化**：命令 `/model` 仅修改内存状态，重启后依然会重置回默认配置，无法将配置保存到本地。
3. **参数僵化**：像 `reasoning_effort`（思考等级）和 `thinking_type` 这类高级推理参数被硬编码在 `config.ts` 的模型字典中，用户无法在命令行灵活调整。
4. **交互简陋**：`/model` 强制要求用户手敲完整的模型名称，不支持交互式选择。

## 2. 关键发现与调研结果
- **现有逻辑**：
  - 提示符在 `index.ts` 中被静态绑定为 `用户 > `，没有动态监听机制。
  - `.env` 文件的加载是单向只读的，尚未提供写回文件的工具函数。
  - 模型特定参数（Payload）通过 `buildExtraPayload` 匿名函数硬编码返回，缺乏运行时上下文。
- **竞品/参考项目架构分析**（位于 `D:\projects\Agent`）：
  - **Claude Code**：这是目前的行业标杆。通过深入剖析它的源码（`claude-code-analysis/src`），我发现它直接在底层深度集成并定制了 **`ink`**（Terminal 的 React 渲染引擎）。这让它能像写网页前端一样，在终端里渲染组件树、处理焦点态和极度复杂的动态回显。
  - **Hermes Agent**：同样使用了 `ink` (React for CLI) 与 `ink-text-input`，实现了完全组件化的动态重绘终端界面。
  - **OpenClaw**：使用了 `@clack/prompts`。这个库提供了极其美观的终端向导界面（如下拉选择、单选框、美化的进度条等），可以做到视觉上非常高大上。
  - **Tinypace-ai-desktop**：这是一个带原生 GUI 的桌面端应用，并非纯 CLI 命令行工具，它的交互直接运行在系统窗口或浏览器中。
  - **结论**：我们的原生 `readline` 确实过于简陋。要想达到 Claude Code 级别的动态刷新，需要引入 React for CLI (ink) 并彻底重写主引擎；而采用 `@clack/prompts` 则是目前最具性价比的“轻量级高端化”升级方案。

## 3. 方案对比与推荐方向

### 方案 A：参数化扩展 (CLI 原生强化风格)
通过为指令增加可选 Flag 实现，结合 ANSI 转移字符手动覆写。
- 优点：无需引入新依赖，底层纯粹。
- 缺点：视觉效果依然简陋，且需用户记忆参数。

### 方案 B：引入专业 TUI 库 (Wizard 风格 - `@clack/prompts`) —— 最佳折中方案
仅在发生系统配置（如 `/model` 切换）时，临时调起 `@clack/prompts` 的精美交互向导，平时仍保持原生的流式输出。
- 优点：交互惊艳，且**非侵入性极强**。它只修改交互入口模块 (`index.ts`)，丝毫不污染底层的 Agent 引擎。这与未来接入“QQ/飞书/GUI客户端”的**解耦战略**完美契合。

### 方案 C：全面 React 化 (Claude Code / `ink` 风格)
将整个终端彻底重写为 React 组件树。
- 优点：业界极致体验，能够实现像网页一样复杂的局部动态刷新。
- 缺点（致命风险）：**重构难度极大且违背长远规划**。引入 `ink` 会导致整个系统的消息队列、流式生成和事件循环与 Terminal 强行绑定（UI 与业务逻辑深度纠缠）。未来如果想把底层剥离给飞书机器人或图形界面，这套庞大的终端 UI 代码反而会成为极其痛苦的技术包袱。

**推荐路径**：采用**方案 B（引入 @clack/prompts 作为轻量外观）**。这是最聪明的折中，既提升了当前的测试体验，又捍卫了“先做好底层逻辑、保持引擎纯粹”的战略方针。

### 补充探讨：配置的落地方案

针对您最关心的**持久化**和**动态取消思考模式**问题，虽然我们引入了 UI，但底层支撑逻辑必须补齐：

1. **解决持久化写入 (.env 修改)**
   - **技术路径**：目前我们只依赖 `dotenv` 读取。未来在 `src/utils/env.ts` 中实现一个简易的正则替换函数。当在菜单中选择“保存为默认模型”时，读取 `.env` 文本，正则匹配 `^DEEPSEEK_MODEL=.*` 并替换后写回。
   - **好处**：这种方式能绝对保留 `.env` 中原有的注释结构，不会破坏人工排版。

2. **解决参数僵化 (动态配置思考等级)**
   - **技术路径**：将 `ModelProfile` 接口中的 `buildExtraPayload()` 从“无参硬编码”改造为接受上下文配置：`buildExtraPayload(options)`。
   - **向导联动**：当 `@clack/prompts` 侦测到你选择了 `deepseek-v4-pro`，自动跳出子菜单问你：“选择思考模式：[关闭] / [Low] / [Max]”。选择后，将结果通过 `options` 传给会话管理器，不再死板绑定。

## 4. 约束、风险与未知项
- 向 `.env` 写回文件时需要小心不要破坏原有的注释结构。
- `readline` 提示符的更新时机：必须在流式输出结束之后，否则会出现提示符被冲刷掉的闪烁问题。
