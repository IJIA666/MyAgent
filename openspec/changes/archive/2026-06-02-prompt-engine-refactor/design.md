## 背景

当前 `src/brain/session.ts` 内部堆积了大量用于定义大模型行为边界的长文本（System Prompt）。这不仅违反了“代码与配置分离”的最佳实践，还会严重阻碍我们未来向“动态注入 MCP 工具说明”以及“读取本地运行环境上下文”方向演进。为了避免陷入过度设计（直接引入重度 3 层上下文引擎），本次改动旨在以最小代价完成文本的物理隔离。

## 目标与非目标

**目标:**
- 将目前 `session.ts` 里的预设文本彻底外置为专属模块 `src/brain/prompts.ts`。
- 构建基础骨架：对外暴露纯函数 `buildSystemPrompt()`。
- 完成对 `SessionManager` 初始化的平滑切流。

**非目标:**
- 暂不引入 Mustache/Handlebars 等复杂的模板引擎进行变量注入。
- 暂不设计基于长度阈值的记忆滑动窗口、上下文压缩缓存体系。

## 架构决策

- **选择 TS 模块而非 Markdown 文件存放文本**
  - *理由*：通过 `export const BASE_SYSTEM_PROMPT = ...` 直接利用 TypeScript 的语言原生能力，不仅零运行期 IO 损耗，且保留了未来支持 JS 模板字面量轻度插值的可能，契合“克制版降级”方针。
- **Builder 函数化设计**
  - *理由*：由于当前没有复杂的上下文状态要在多次调用间暂存，暴露 `buildSystemPrompt()` 函数比设计一个臃肿的 `PromptBuilder` Class 更加精简。未来入参需要扩展时（如传入工作区目录路径），直接在函数签名上增补即可。

## 风险与权衡

- **风险: 标点/换行符遗失** → 从 `session.ts` 中剪切原有模板字面量时，如果缩进、换行或反引号处理不当，可能导致喂给模型的人设发生微小的排版变异，从而影响其响应稳定性。
  - *缓解措施*：必须采用无修改（原封不动）的 Copy-Paste 迁移策略，确保文本二进制一致性。
