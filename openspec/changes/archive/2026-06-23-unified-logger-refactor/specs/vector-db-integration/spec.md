## MODIFIED Requirements

### 需求: 向量数据库初始化与生命周期管理

系统必须具备向量数据库的初始化与连接生命周期管理能力。在系统初始化或需要加载向量存储时，必须通过依赖注入机制显式指定数据库物理目录，而不得在适配器内直接读取全局环境变量。在测试或独立实例化时允许路径为空，并安全降级使用 `process.cwd()` 作为物理工作区计算基准。如果数据库或特定的集合（表）不存在，应当自动创建并以强类型 Schema 锁死数据格式；在系统退出或关闭会话时，应当优雅物理断开连接以释放句柄与资源。

#### 场景: 数据库启动与自动初始化
- **WHEN** 向量服务启动或会话初次连接向量数据库
- **THEN** 系统根据调用方在实例化时显式传入的物理工作区路径（或在未传参时安全降级至以进程当前工作目录 `process.cwd()` 为兜底基准）建立物理连接。若表不存在，则自动以包含 id ( UUID )、text (记忆文本)、vector ( 1536 维特征向量)、metadata (额外元数据) 的 Schema 结构自动建表并锁死结构。

#### 场景: 数据库连接的优雅注销与清理
- **WHEN** 系统接收到退出信号、执行 close 会话或进程即将注销时
- **THEN** 系统必须自动触发向量数据库适配器的 close() 优雅销毁方法，彻底物理关闭底层文件连接，并清空内存，防止文件锁残留与内存泄漏。
