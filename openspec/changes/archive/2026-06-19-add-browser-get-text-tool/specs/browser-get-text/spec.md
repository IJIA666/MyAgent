## 新增需求

### 需求: 提取当前页面指定选择器的可见纯文本

系统必须提供一个只读的原生浏览器操作工具 `browser_get_text`。当工具被调用时，它应当提取当前激活的浏览器页面中匹配目标选择器的所有可见文本。在此过程中，必须过滤非文本相关噪声（如脚本、样式及隐藏元素），且为了系统整体的平稳运行，最终返回给智能体的结果必须具备最大长度限制。

#### 场景: 成功抓取指定选择器匹配的多个元素文本并过滤噪声
- **WHEN** 智能体在已导航的页面上调用 `browser_get_text` 传入 CSS 选择器参数（例如 `".chat-message"`）。
- **THEN** 系统必须利用 Playwright 查询当前租户页面中所有匹配 `".chat-message"` 的可见元素，自动剥离其中所含的 `<script>`、`<style>`、`<noscript>`、`<svg>` 等不包含实际可读内容的标签，排除被 CSS 规则隐藏的文本，并将所得的多段元素文本使用双换行符（`\n\n`）进行拼接并返回。

#### 场景: 默认读取 body 全页可见文本及截断防护
- **WHEN** 智能体在已导航的页面上调用 `browser_get_text` 但不传入任何 CSS 选择器（参数为空），或者目标文本内容极其庞大。
- **THEN** 系统必须默认将查询范围限定在整个页面的 `body` 元素上，提取全页的可见纯文本（同样滤除噪声和隐藏元素），并强制对最终拼接好的合并文本执行硬性长度限制（只保留前 80,000 个字符，超出部分予以截断），以保障下游 Token 解析与内存的平稳。

#### 场景: 匹配节点不存在时报错拦截
- **WHEN** 智能体传入一个当前页面上完全不存在的 CSS 选择器（例如 `".non-existent-selector"`）。
- **THEN** 系统必须抛出明确的错误异常提示（如 `"未在页面上找到匹配选择器 \".non-existent-selector\" 的元素"`），以便智能体接收错误反馈并修正后续决策。
