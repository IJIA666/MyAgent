## 改造原因

在当前的智能体底座中，唯一的网页感知工具是 `generateAriaSnapshot`。该工具使用严格的可交互元素选择器过滤网页内容，使得普通排版文本、文章段落、纯展示性质的 SPA 页面内容在感知阶段被全部清除。导致智能体在导航到展示型页面时处于“全盲”状态，无法阅读网页文本进行内容提取与分析。
为了解决这一痛点，需要在浏览器原生工具集中引入一个只读的文本感知工具，使智能体能够获取当前视口或指定选择器匹配区域内的可见文本内容，恢复内容感知和语义阅读能力。

## 变更内容

1. **引入新原生工具**：在 `browser-action.ts` 中新增只读的 `BrowserGetTextTool`，并提供注册名称 `browser_get_text`。
2. **文本清洗与降噪**：工具应支持获取指定选择器区域内的可见文本，并自动过滤 `<script>`、`<style>`、`<noscript>`、`<svg>` 等不包含实际可读内容的标签，排除被 CSS 规则隐藏的无效文本。
3. **严格模式冲突防护**：当选择器在页面匹配多个节点时，循环提取各节点文本并使用双换行拼接，以规避严格模式下的 locator 多节点匹配异常。
4. **截断防御与 Token 保护**：限制最终返回的字符串最大长度不超过 80,000 字符，防范由于极长文本输入导致的 Token 超载或内存溢出。
5. **在底座中注册该工具**：在虚拟 MCP 中注册并暴漏给智能体，使其能够在决策链中选择并调用。

## 业务能力

### 新增业务能力

- `browser-get-text`: 提供对当前网页页面文本的内容抓取与降噪阅读能力，支持 CSS 选择器范围过滤及输入长度截断防御。

### 修改业务能力

无
