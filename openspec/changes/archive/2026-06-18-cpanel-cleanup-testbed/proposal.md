## 改造原因

为了深度验证并客观评估本地智能体（IJIA Agent）的文件检索、大文件甄别、逻辑推理及终端删除命令执行的实际应用能力，需要让其在一个安全的、高逼真的“磁盘清理”环境中接受测试。
然而，直接在开发者的物理 C 盘上执行删除指令存在极大的数据损毁与系统崩溃风险；同时，缺乏文件锁占用、ACL 只读保护等物理级清理阻力，将使测试流于表面，无法校验智能体在遇到删除冲突和权限拒绝时的异常处理与重试容错决策。

为了贯彻“测试代码不侵入/不修改生产代码”和“不污染核心配置文件”的软件工程原则，我们应当避免修改智能体核心逻辑和安全网关。通过开发一套外置的一键测试环境启动器，利用进程级别环境变量重定向，在测试启动时将智能体的工作区沙箱安全重定向到由 `subst` 隔离出来的虚拟磁盘盘符上，即可在主线代码 0 修改、配置文件 0 读写的前提下，对智能体开展高置信度、一键闭环且量化的基准能力评测。

## 变更内容

本次改造具体包含以下变化：
1. **测试沙箱化与虚拟挂载**：在项目下新建物理模拟目录并使用 Windows 原生 `subst Z:` 将其挂载为虚拟磁盘盘符 `Z:\`（若盘符冲突则向下寻找空闲盘符进行挂载），让智能体在测试中操作逼真的 Windows 绝对路径，杜绝逃逸。
2. **系统清理阻力模拟**：通过 `icacls` 配置特定系统级文件写入和删除拒绝（ACL 壁垒），并由主控脚本派生生命周期绑定的子任务以 `{ stdio: 'ignore' }` 静默模式独占锁定指定文件，模拟真实环境中的权限阻力和文件占用。
3. **一键测试环境启动器 (Unified Runner)**：在测试目录 `test/scripts/` 下开发核心控制脚本 `run_testbed.ts`。该脚本负责一键部署靶场环境，在进程内存中动态注入环境变量 `AUTHORIZED_WORKSPACE_DIR=Z:\` 并派生启动智能体（避免对物理 `.env` 配置文件进行危险读写），在智能体退出后自动运行结果校验打分，并强力复位环境。

## 业务能力

### 新增业务能力
- `cleanup-testbed`: 提供一整套包含虚拟盘符映射、ACL权限隔离、文件锁占用和一键自动化闭环评测报告在内的高仿真磁盘清理测试床与评估生命周期套件。

### 修改业务能力
- 无（主线代码与系统配置文件保持 100% 纯净与兼容）

## 影响范围

* **主线代码与配置**：**无影响（0 代码修改，0 物理配置文件修改）**。
* **一键测试套件**：
  * `test/scripts/run_testbed.ts`（主控一键评测器，负责环境 setup、智能体子进程派生与变量注入、teardown 触发与 verify 断言集成）。
  * `test/scripts/setup_testbed.ts`（测试床物理层级初始化与只读、ACL 及独占锁定配置）。
  * `test/scripts/teardown_testbed.ts`（文件锁释放、ACL 解禁、盘符卸载与物理销毁）。
  * `test/scripts/verify_cleanup.ts`（清理结果自动化校验与断言评估打分）。
* **工作区物理空间**：新增模拟目录 `testbed/mock_c_drive/` 以及系统中的虚拟挂载盘符 `Z:`（或 Y: 等可用盘符）。
