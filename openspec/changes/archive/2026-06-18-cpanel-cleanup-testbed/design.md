## 背景

IJIA Agent 拥有终端执行命令与文件系统的读写操作能力。在针对“磁盘垃圾清理”这一应用场景进行能力评测时，测试系统需要解决两大核心问题：
1. **安全性隔离**：不能让智能体直接在物理 C 盘上误删核心系统文件。
2. **场景高保真度**：测试环境必须模拟出 Windows 真实的绝对路径认知（如 `Z:\Windows\Temp`）以及物理级别的删除阻力（只读文件、ACL 权限拦截、进程排他锁占用），以考验智能体在遇到异常时的容错、跳过及提权判断决策。

为了保证测试框架不污染、不侵入生产主干代码，且不读写破坏开发者的物理配置文件（如 `.env`），我们需要实现“智能体源码 0 改动，配置文件 0 读写”的一键自动化闭环评测技术方案。

## 目标与非目标

**目标:**
* 在开发工作区中手动创建 Windows 物理层级拓扑树 `testbed/mock_c_drive/`，并一键调用 `subst Z:` 挂载为虚拟 Z 盘（若盘符冲突则动态向下漂移）。
* 在项目原有的测试脚本目录下提供一键测试环境启动器 `test/scripts/run_testbed.ts`，以集成形式串联环境搭建、智能体子进程启动、变量注入、对话交互、结果打分与环境解构销毁的完整测试生命周期。
* 模拟真实的 UAC/ACL 权限壁垒，利用 Windows 的 `icacls` 对模拟核心文件剥夺当前用户写入与删除权限。
* 模拟排他文件锁占用，通过 Node.js 主控进程生命周期锁定派生的子进程（PowerShell）执行锁定，保证主进程崩溃时操作系统内核能自动回收文件锁，避免僵尸进程锁死文件。
* 通过在派生智能体子进程时动态注入进程级别环境变量 `AUTHORIZED_WORKSPACE_DIR`，实现智能体工作区重定向，彻底规避直接读写物理配置文件的风险。
* 提供自动化量化校验报告（`test/scripts/verify_cleanup.ts`），针对清理召回率、核心安全无误删率以及异常容错能力进行综合百分制打分。

**非目标:**
* **绝对不修改**智能体的物理文件读写核心逻辑与安全网关拦截规则（`terminal-guard.ts` 保持 100% 纯净）。
* **绝对不改写**开发区磁盘上的 `.env` 文件。

## 架构决策

### 决策 1: 使用 `subst Z:` 挂载建立虚拟隔离盘
* **理由**：智能体具有针对特定 Windows 固定垃圾路径的检索直觉（例如 `C:\Windows\Temp`），如果直接使用相对路径，会破坏智能体的泛化绝对路径检索能力。将测试床挂载为虚拟盘符，既满足了绝对路径检索逼真度，又保证了删除操作被隔离在虚拟区内。
* **动态漂移**：当 `Z:` 盘被物理占用时，脚本自动探测其他空闲盘符（如 `Y:`、`X:`）进行挂载。

### 决策 2: 一键评测启动器 (`Unified Runner`) 与进程级沙箱重定向
* **理由**：若在测试时去修改物理配置文件 `.env`，一旦脚本在中途崩溃，会导致原有的 API Key 等开发配置永久丢失。
* **具体设计**：
  1. 在项目原有的测试脚本目录下创建主控脚本 `test/scripts/run_testbed.ts`；
  2. 启动时自动执行 `test/scripts/setup_testbed.ts` 挂载好虚拟盘符（假设为 `Z:\`）；
  3. 挂载成功后，使用 Node.js 的 `child_process.spawn` 派生智能体主进程，并**动态在子进程的 env 中注入配置：`AUTHORIZED_WORKSPACE_DIR=Z:\`**。此时，将终端的输入输出与智能体子进程双向透传绑定，供测试者进行聊天交互；
  4. 智能体退出的瞬间，主控脚本捕获子进程退出事件，自动调用 `test/scripts/verify_cleanup.ts` 进行断言评估并打印打分报告；
  5. 评估结束后，主控脚本自动调用 `test/scripts/teardown_testbed.ts` 解锁、解挂并强力销毁测试物理目录。
* **优势**：全生命周期在一键命令 `npx tsx test/scripts/run_testbed.ts` 中完全闭环，配置文件零读写，实现了优雅、极低心智负担的自动化沙箱评测。

### 决策 3: 主进程生命周期锚定与 stdio 阻断防僵尸锁定
* **理由**：为防止后台独占锁进程在测试遭遇未捕获异常崩溃时成为“孤立僵尸进程”永远锁死垃圾日志，我们在 `test/scripts/setup_testbed.ts` 中通过 Node.js 派生（`spawn`）一个锁定文件的子任务（通过 Powershell 以 `FileShare::None` 独占锁定）。
* **挂起防范**：为避免子进程运行时控制台或报错输出塞满系统默认的管道缓冲区导致 PowerShell 进程处于“写挂起”假死状态，我们在 `spawn` 时必须显式声明配置 `{ stdio: 'ignore' }`。
* **效果**：Windows 操作系统的 Job Objects 会对此类子进程树强制进行父子进程生命周期绑定。一旦主控 Node 测试进程崩溃或非正常清退，操作系统内核将自动捕获并强制终结锁文件的子进程，即时释放文件句柄锁。

### 决策 4: 高速、0 内存稀疏大文件分配
* **理由**：测试用例包含 180MB 甚至 1.2GB 的模拟系统日志与游戏包文件。如果在 Node.js 中创建如此大体积 of 随机 Buffer 写入磁盘，会引发 V8 虚拟机内存溢出并严重拖慢 IO 效率。
* **方案**：在初始化测试用例大文件时，直接调用 Windows 原生的高效文件空间分配命令：
  ```cmd
  fsutil file createnew "<testbed_path>\CBS.log" 188743680
  ```
  该命令在 OS 内核层秒级完成空间预占，耗时在毫秒级且完全无内存开销。

### 决策 5: UAC ACL 权限模拟与 reset 重置
* **理由**：为了逼真模拟系统受限及 TrustedInstaller 等 UAC 权限拒绝场景，我们在初始化时调用：
  ```cmd
  icacls "Z:\Windows\System32\kernel32.dll" /deny %USERNAME%:(W,D)
  ```
  这会明确在 ACL 控制层面剥夺当前用户的写入和删除权限，智能体运行普通的删除命令时会遇到真实的 EPERM (Access is denied) 权限阻力。在 `test/scripts/teardown_testbed.ts` 阶段，通过执行 `icacls "Z:\Windows\System32" /reset /T` 递归重置权限，从而解除 ACL 屏蔽，保证 teardown 阶段能够彻底物理销毁整个测试床目录。

## 风险与权融

* **[风险点 1] 虚拟盘符占用冲突**
  * **描述**：如果宿主 PC 上已经挂载了物理 `Z:` 盘或网络共享卷，`subst Z:` 挂载会失败。
  * **缓解策略**：在 `test/scripts/setup_testbed.ts` 部署前首先查询可用盘符。若 `Z:` 被占用，则依次向下检索未分配的盘符（如 `Y:`, `X:`），并在挂载成功后，通过 `run_testbed.ts` 直接将该盘符动态注入到派生智能体子进程的环境变量 `AUTHORIZED_WORKSPACE_DIR` 中。
* **[风险点 2] 权限限制残留导致项目工作区无法清理**
  * **描述**：若测试异常中止，且 `test/scripts/teardown_testbed.ts` 权限重置逻辑未被触发，则 `kernel32.dll` 等文件的 ACL 拒绝属性会残留，导致开发者手工也无法在工作区中删除 `testbed/` 目录。
  * **缓解策略**：在 `test/scripts/setup_testbed.ts` 每次运行的最初阶段，强行执行一次权限重置脚本以还原历史残留状态；并在 `test/scripts/teardown_testbed.ts` 中增加异常捕获和最坏情况下的 ACL 解禁命令，确保开发区物理清洁度。
