## 背景

随着 MyAgent 承接更长、更难的编程工程任务，由于缺乏高效的短期记忆与快照管理，容易在面临大报错/海量搜索文本时触发 Token 水位线报警或让模型在原地绕弯。在此背景下，我们需要构建一套兼顾“物理一致性快照”与“高精准上下文去噪”的短期记忆控制子系统。

## 目标与非目标

**目标:**
1. **防爆与去噪**：拦截中型工具输出（编译错误、大文件 diff），实现双向行级/字节保底折叠，防止 Lost-in-the-Middle 导致的注意力漂移。
2. **日志 100% 原始保真**：虽然投递给大模型的是裁剪后的折叠文本，但物理落盘的 `transcript.jsonl` 会话日志必须能 100% 还原和回溯原始未截断工具输出，保留全部行号。
3. **安全与内存保护**：工具可去中心化自定义配额，大输出超限时同步写盘至外带文件以防止 Node.js 内存溢出（OOM）。
4. **一键快照物理回退**：对有写副作用的敏感操作进行备份并在回档时还原物理文件，确保内存消息与工作区物理状态 100% 一致。

**非目标:**
1. **对物理写无关（读操作）的文件备份**：文件读操作（如 `read_file`）绝对不进行任何冷备份，以防磁盘 I/O 爆炸。
2. **非幂等外部副作用的回滚**：本快照系统绝不对大模型 API 计费、网络外部 API 请求等非幂等操作进行任何物理撤销或回滚尝试。
3. **子变更一阶段支持回滚**：子变更一（Compaction & Pruning）将完全独立，坚决不引入任何物理冷备份及回滚逻辑，以保证低延迟特性先期发布。

## 架构决策

为了将“无损去噪”与“内存防爆”统一，我们做出了以下宏观架构决策：

1. **同步外带写盘 + 复合引用历史（方案 D + 方案 C）**：
   * **拦截机制**：每次工具返回时由 `ToolDispatcher` 同步触发去中心化配额卡关（从 `ToolMetadata` 动态获取 `max_lines` 与 `max_bytes`）。
   * **存储机制**：超限的原始大输出同步写盘至外带目录（`.myagent/tool-outputs/`），同时在内存 `messageHistory` 和会话物理日志中写入复合引用结构 `CompoundToolResultContent`（包含行级折叠预览与原始文件物理路径 `originalPath`）。
   * **无损投递**：上下文转换层在将消息送大模型前，过滤并仅提取折叠后的 text 预览送审，实现对模型侧的无损去噪；而会话物理日志则完美保真原始数据路径。
   * **首尾双保中段压缩（Middle Compaction）**：动态统计会话 Token 水位，超限时保护第一轮 Prompt/ToolResult 和最近交互轮，仅在后台将中段的 `messageHistory` 提炼为单条 Summary 消息，对抗 Lost-in-the-Middle。

2. **安全类别协同的冷备份快照物理还原（方案 B）**：
   * **沙箱备份**：建立隐藏沙箱目录 `.myagent/backups/`。
   * **精准拦截**：仅当工具的 `securityCategory` 属于 `edit` / `write`（具有脏改副作用）时，才触发冷备份写操作。
   * **物理回滚**：回滚时提取快照 Tree 状态。如果在快照点某个文件不存在，调用 `unlink` 物理删除该后增文件；若存在且不一致，调用 `copyFile` 将冷备份物理覆盖还原，维持物理一致性。

## 风险与权衡

* **[风险点：冷备份空间暴涨]** -> **[缓解策略]**：建立 Cleanup 机制，在 Session 关闭或主程序销毁时，一键彻底删除 `.myagent/backups/` 和 `.myagent/tool-outputs/` 下的当前 Session 物理缓存。
* **[风险点：双向折叠破坏重要编译上下文]** -> **[缓解策略]**：双向折叠采用行对折算法（前半段 + 后半段），保留最重要的最底层堆栈 Trace 和开头报错声明，且指示引导中附带完整外带大输出链接，方便模型自己使用 `read_file` 查阅详情。
