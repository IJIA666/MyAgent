## 改造原因

当前智能体（Agent）在调用工具失败或遭遇未预期的系统级业务/进程异常时，其行为往往属于概率本能预测（如反复盲目重试、错误地修改入参名、甚至捏造参数重新调用的“碰运气”行为）。虽然在此前的 `mcp-stability-enhancement` 变更中，我们在 `prompts.ts` 中引入了第 9 条红线规则，成功拦截了“网络超时”和“Schema 错配”两类特定异常下的瞎碰。但对于超出此范围的未知报错（如临时文件锁冲突、底层权限不足、工具内部业务崩塌等），智能体依然会触发原地瞎猜的重试，造成大量无谓的 Token 消耗以及修改性操作中的安全越权隐患。因此，我们迫切需要在单会话和短上下文中建立“未知报错归因约束机制”，强制智能体在此类未知报错面前停止一切自愈重试，将真实报错抛回用户并中断求助。

## 变更内容

在系统提示词 `BASE_SYSTEM_PROMPT` 的第 9 条红线规则中新增第三分支。当接收到的工具报错既不符合网络超时特征，也不符合 Schema 校验特征时，强行切断大模型一切修改参数并尝试重新调用的重试行为。规范其动作响应为：向用户如实陈述错误原文、坦承无法判断其根本原因，并请求用户协同介入确认后再决定下一步动作。

## 业务能力

### 新增业务能力
- 无

### 修改业务能力
- `base-stability`: 在异常与超时防幻觉重试机制中，扩充第三分支——针对未识别的非网络、非 Schema 工具执行错误进行硬阻断，并规范陈述原文与请求人类协助的响应规格，以约束盲目重试行为。
