# 探索主题: 极简 TypeScript 授权文件操作 Agent

## 1. 问题定义
用户希望构建一个基于 TypeScript (Node.js) 的极简本地命令行 Agent。该 Agent 必须实现以下三大核心能力：
1. **多轮连续对话**：在内存中维护会话状态，实现自然的上下文理解。
2. **安全受控的文件操作**：定义一组受限文件操作工具（读、写、列出），通过大模型工具调用（Tools 机制）触发，执行前必须经过严格的路径边界检查，确保仅能在用户授权的 workspace（如 `d:\projects\MyAgent`）中操作，绝不越权。
3. **动态模型切换**：支持通过外部配置文件或环境变量，无缝切换底层使用的 DeepSeek 系列模型（如 `deepseek-chat` 等）。

## 2. 关键发现与调研结果
- **SDK 适配**：由于 DeepSeek 官方 API 与 OpenAI 协议完美兼容，Node.js 侧我们可以直接使用官方的 `openai` 依赖包，以极高的稳定性和极低的学习成本与大模型交互。
- **简易执行环境**：无需进行繁琐的 `tsc` 手动编译。我们可以在开发环境引入 `tsx`（TypeScript Execute），直接在 Node.js 中以单条命令免编译、极速运行 `.ts` 脚本。
- **工具调用状态机**：利用标准 OpenAI 兼容的 `tools` 参数定义文件工具（声明 `type: "function"`），并在客户端接收到 `tool_calls` 响应时，路由到本地对应的文件操作系统函数，执行后将结果反馈给模型，直至模型输出 natural text。
- **边界防卫机制**：在本地文件工具中引入绝对路径校验，使用 `path.resolve` 和 `path.startsWith` 验证 Agent 试图读写的路径是否处于授权路径（Workspace Path）内，从根本上防止 Agent 意外删改系统盘或其他未授权文件。

## 3. 方案对比与推荐方向
| 方案 | 优点 | 缺点 | 结论 |
| :--- | :--- | :--- | :--- |
| **方案 A：原生 OpenAI SDK + 内存会话队列 + readline** | 代码清透、零黑盒，最有利于深刻学习和掌握 Agent 的消息循环机制与 Tools 工具调用细节。依赖极少。 | 需要手动组织 Message 列表的管理。 | **推荐首选 ✓** |
| **方案 B：使用 LangChain.js / AutoGen 等重型框架** | 提供了现成的 Agent 包装类和各种记忆存储器。 | 抽象层过于厚重，难以直接观察并理解底层 API 请求的流向，违背了“最简单 agent”的学习初衷。 | **否决 ✗** |

**推荐路径**：采用**方案 A**。利用 TypeScript 结合原生 `openai` SDK 来处理 DeepSeek 交互，并使用 Node.js 原生的 `readline` 模块创建交互式命令行 REPL。

## 4. 约束、风险与未知项
- **路径遍历漏洞（Path Traversal）**：Agent 可能会尝试传入 `../../etc/passwd` 等路径来绕过限制。我们在本地实现的工具必须使用 `path.resolve()` 规范化路径，再与授权工作区根目录进行前缀比对，一旦发现越界拦截并向 Agent 返回错误信息。
- **动态模型切换的兼容性**：虽然大模型支持动态切换，但不同规模或版本的模型在 Tools 工具调用的遵循能力上存在差异。我们会设计一个灵活的配置文件 `config.json` 或 `.env` 文件，模型名称与 API Key 均在此集中配置。

## 5. 否决方案
- **否决大型框架集成**：坚持零依赖或超轻量依赖，不使用 LangChain 等黑盒库。
- **否决不受限文件操作**：坚决禁止将原生 `fs` 命令直接无过滤地暴露给大模型。
